# 추천 성분 CatBoost V3 — 모델 설명서 및 평가 보고서

2026-11-14. 모델 이름은 `recommend-cat-v3`다. 추천 시스템 V2의 성분 후보 생성기를 교체하는 모델이며,
추천 흐름의 이름과 API 응답의 `v2` 키는 그대로 사용한다.

## 번들과 실행

이 폴더의 세 파일을 Git으로 함께 배포한다.

| 파일 | 역할 |
|---|---|
| `model.cbm` | native CatBoost 가중치, 4,894,696 bytes |
| `manifest.json` | 모델 이름·입력 순서·범주·성분 ID·해시·분석 점수 계약 |
| `README.md` | 실행 안내, 데이터·학습 설정, 평가와 한계 |

학습 데이터·원문 상담·이미지·개인별 분석 메타데이터는 추론에 필요하지 않으며 Git에 포함하지 않는다.
모델을 내보내거나 재학습하지 않고 이 폴더의 파일을 그대로 사용한다.

```powershell
# 저장소 루트, 최초 1회 또는 의존성 변경 시
uv sync --project backend/api --group recommendation

# 기존 Docker DB·카탈로그를 사용하는 개발 비교 API
uv run --project backend/api --group recommendation python scripts/data/recommendation/run_v2_comparison.py --docker-local
```

백엔드 기본 모델과 `.env.example`은 V3다. 기존 `.env`나 셸에 V2가 지정되어 있으면
`RECOMMENDATION_MODEL=recommend-cat-v3`로 바꾸고 API를 재시작한다. 루트 비교 실행기는
`.env` → `.env.development` → `.env.local` → `.env.development.local` 순으로 읽으며 셸 환경변수가 최우선이다.
FastAPI를 직접 실행할 때는 프로세스 환경변수 또는 `backend/api/.env`에 설정한다.
기존 DB·카탈로그·인증 설정은 그대로 필요하다. 이번 모델 교체에는 DB 마이그레이션이나 모바일 에셋 준비가 없다.
Docker 이미지에는 이 폴더가 자동 복사되지 않는다. 별도 서버에서는 `RECOMMENDATION_MODELS_DIR` 아래에
`recommend-cat-v3/bundle/`을 배치하고 CatBoost 의존성을 설치한다.

응답에서 `v2.model.version == "recommend-cat-v3"`, `v2.model.features` 10개를 확인한다.
서비스는 manifest와 실제 모델의 입력 수·범주형 인덱스·파일 해시를 검증한다. 누락 시 다른 모델로 대체하지 않는다.
상세 실행은 저장소 루트의 `docs/recommendation-v3-handoff.md`를 따른다.

## 무엇이 달라졌는가

기존 양호/주의 3개 상태와 사용자 입력을 보존하고, 모공·주름·색소 분석의 원점수 3개를 추가했다.
예를 들어 모공 점수 0.51과 0.95는 모두 주의지만, V3는 두 수치를 구분할 수 있다.
반복 상담 역빈도 가중치 조정은 적용하지 않았다. 성분 정답을 대안 집합으로 합치는 변경도 적용하지 않았다.
주/보조 고민 선택, ML 핵심 5성분, COSING 확장, 제품 후보 생성, 리뷰 보정 및 최종 5제품 로직은 유지한다.

## 입력 계약

| 순서 | 입력 | 종류·의미 |
|---:|---|---|
| 1 | `age_group` | 범주형, 10대~60대 |
| 2 | `gender` | 범주형, 남성/여성 |
| 3 | `skin_type` | 범주형, 건성/중성/지성/복합성 |
| 4 | `primary_concern` | 범주형, 해당 호출의 대상 고민 |
| 5 | `pore` | 범주형, 모공 양호/주의 |
| 6 | `wrinkle` | 범주형, 주름 양호/주의 |
| 7 | `tone` | 범주형, 색소 양호/주의 |
| 8 | `pore_score` | 수치형, 모공 원점수 0~1 |
| 9 | `wrinkle_score` | 수치형, 주름 원점수 0~1 |
| 10 | `pigmentation_score` | 수치형, 색소 원점수 0~1 |

정확한 범주와 80개 DB 성분 ID의 순서는 `manifest.json`이 기준이다. 마지막 3개는 범주형으로 처리하거나
반올림하지 않는다. 상태 3개는 대응 점수가 0.5 이상이면 주의로 만든다.
점수 계약은 `skin-analysis-v4`의 `binary_caution_probability`,
`mean-cheeks-pore-tone-eyes-wrinkle-v1`이다. 점수는 0~5등급을 단순히 정규화한 심각도가 아니라
이진 주의 분류의 보정되지 않은 출력이다. 여드름 점수는 현재 입력에 없다.

출력은 manifest의 80개 성분별 확률 점수다. 상위 5성분을 후보로 사용하며 각 성분은 DB ID로 제품과 연결한다.
확률은 성분 정답과의 대응 점수이며 제품 효능·피부 개선 가능성으로 해석하지 않는다.

## 데이터와 학습

AI허브/NIA 라벨의 자연어 답변에서 추천 성분을 추출하고 성분 사전·지식 엑셀·원문 검수로 정규화한
80열 멀티핫 정답을 사용한다. 피부 분석 이미지 자체는 성분 모델의 입력이 아니다.
연령대·성별·피부타입·대상 고민과 분석 상태/점수를 사용한다.
검수 과정에서 추정·제외·보류 행을 분리하고 남은 성분 라벨을 보정했다.
원문에서 지정한 대상 고민을 학습에 유지했다. 서비스의 자동 선택 고민과 같다는 보장은 없다.

총 5,273행: 학습 3,689 / 검증 792 / 테스트 792. 기존 분할을 유지했다.
source·상담 원본 그룹·이미지 그룹이 구간 사이에 겹치지 않는지 검사했다.
분석 점수는 원문 source로 연결하고 상태·사용자 정보·모델 버전·범위의 일치를 확인했다.

## 평가 결과

동일 분할·정답·설정에서 검수 후 7입력 기준 모델과 비교했다. 아래 F1은 임계값 0.5가 아니라
상위 5개만 양성으로 만든 예측 기준이다. R-Precision은 각 행의 정답 개수 R만큼 추천해 계산한다.
P@5·Recall@5는 행별 값의 평균이고, macro-F1은 전체 80개 열을 평균하며 분모가 0인 열은 0으로 처리한다.

| 구간·모델 | R-Precision | P@5 | Recall@5 | Top-5 micro-F1 | Top-5 macro-F1 (80종) |
|---|---:|---:|---:|---:|---:|
| 검증 · 기준 | 79.99% | 66.67% | 82.54% | 73.43% | 23.05% |
| 검증 · V3 | 82.40% | 69.07% | 85.24% | 76.07% | 25.33% |
| 테스트 · 기준 | 79.92% | 66.36% | 82.50% | 73.28% | 24.01% |
| 테스트 · V3 | 80.93% | 67.83% | 84.36% | 74.90% | 25.29% |

테스트에서 P@5 +1.46%p, Recall@5 +1.86%p, micro-F1 +1.62%p, macro-F1 +1.28%p다.
정답에 등장한 38성분만의 macro-F1은 50.55% → 53.24%다.
같이 비교한 가중치 조정 모델은 P@5 64.60%, 두 방법 적용 모델은 66.92%로 V3보다 낮았다.
검증·테스트에서 다섯 지표가 모두 개선된 점수 추가 모델을 V3로 채택했다.

## 검증과 한계

- native 저장·재로딩 후 테스트 792행의 예측이 실험 결과와 허용 오차 1e-12 이내로 일치했다.
- 서비스 입력을 구성할 수 있는 테스트 719행의 입력 순서를 확인했다.
- 모공·주름·색소를 주 고민으로 하는 세 사례에서 고정 카탈로그로 최종 5제품 반환을 확인했다.
- 저장소 테스트 `backend/api/tests/test_recommendation_packaged_bundle.py`는 이 번들만으로
  실제 추론과 주/보조 고민별 제품 추천이 동작하는지 검사한다. 학습 원문이 필요하지 않다.
- 단일 seed이며 이미 관찰한 개발 테스트셋이다. 독립적인 최종 성능 추정이나 통계적 유의성을 입증하지 않는다.
- 희귀 성분의 성능 편차, 학습 대상 고민과 자동 선택 고민의 차이, 지표 사이 점수 비교의 보정은 남은 과제다.
- 학습 ROI와 모바일 전처리의 동등성은 검증되지 않았다(`mobileEquivalenceValidated: false`).
- 최종 제품 효능·사용 만족도·실사용 개인화 개선은 이 평가로 확인하지 않았다.
