# 유튜브 조사 상품 적재와 매칭

## 범위

- 입력: 조사 엑셀의 `전체 제품` 시트. 입력 파일과 생성된 검수 CSV는 저장소에 넣지 않음.
- `raw_yt_product`: 조사 브랜드·상품명·옵션 조합 1건당 1행. 옵션이 `원본에 별도 옵션 없음` 또는 `원문에 명시 정보 없음`이면 옵션 이름을 비움. 단일 색상이라는 뜻으로 해석하지 않음.
- `raw_yt_product_mention`: 영상별 언급 1행. 원본 행 ID와 조사 레코드 ID로 역추적 가능.
- `yt_oy_product_match`: 올리브영 상품·옵션 후보와 검수 결정. 이름 유사도만으로 `confirmed`를 만들지 않음.
- `yt_catalog_product_link`: 검수된 유튜브 원본 상품 ID와 앱 서빙 상품 ID의 연결. 한 원본을 두 상품으로 나누거나 여러 원본을 한 상품으로 합친 경우도 표현함.
- 유튜브 조사값을 먼저 원본 테이블에 적재하고, 확인된 중복 여부에 따라 앱 서빙 대상과 미취급 상품을 구분함. 원본 행은 삭제하지 않음.

## 실행 순서

1. 로컬 DB의 Alembic을 현재 develop head까지 적용. 유튜브 원본 테이블은 0015에서 추가됨.
2. `load_products.py --validate-only`로 파일 구조·건수 확인. 현재 파일의 예상값: 영상 언급 1,617건, 제품·옵션 조합 1,490건.
3. 같은 스크립트를 쓰기 옵션 없이 실행해 DB 제약과 이전에 잘못 적재된 옵션 미확인 행의 정리 건수까지 검증한 뒤 트랜잭션 롤백.
4. 로컬 DB에 `--apply`로 적재하고 두 테이블의 건수·원본 행 ID 유일성 확인.
5. `match_products.py`의 기본 미리보기로 `brand_review.csv`, `unknown_brand_products.csv`, `product_candidates.csv`, `unmatched_products.csv` 생성. `확인 필요` 브랜드는 별도 목록에서 조사하고 유사 브랜드 추천으로 자동 대체하지 않음. 브랜드 별칭은 검수자와 검수일이 있는 CSV만 사용.
6. 검토 후 후보를 저장하려면 `match_products.py --apply` 실행. 후보 상태는 모두 `candidate`; 상품·옵션 확인 뒤에만 `confirmed`로 전환.
7. `enrich_confirmed.py`로 확정 연결의 기존 올리브영 색상·제형을 미리보기. 상품 옵션을 특정했거나 올리브영 활성 옵션이 정확히 하나일 때만 색상 사용. 기존 유튜브 조사값은 보존.
8. 데이터 담당자의 로컬 `vishue_db`에서 적재·검수를 마친 뒤 팀원용 DB 덤프를 만들어 전달. 팀원은 덤프를 자신의 로컬 DB에 복원. AI-Hub처럼 개별 이용권한이 필요한 데이터는 기존 덤프 정책에 따라 제외. 현재 스크립트는 `127.0.0.1` 또는 `localhost`의 PostgreSQL만 허용.
9. 이미지·색상·제형 누락분을 보강할 때는 아래 `enrich_product_assets.py` 절차를 사용.

## Glowpick 가격·카테고리 보강

### 유튜브 상품 통합 보강

- 수동 완료 대상으로는 앞서 제공된 가격·용량 정보 9건, 피카소 799 엣지 아이라이너(27,000원·1ea), 크리니크 치크 팝 누드 팝(36,000원·3.5g)이 포함됨. 피카소 아이라이너는 브러쉬 도구로 분류해 `tool` 태그를 사용함.
- 보강 묶음은 기존에 적재된 8개 수동 확인 제품을 유지하면서 Dermatory·Picasso·Clinique 및 에뛰드 브러쉬 3종을 신규 대상으로 준비함. `load_youtube_v32_incremental.py`는 이미 같은 내용으로 있는 ID를 건너뛰므로 중복 삽입하지 않음.
- `youtube-etude-contour-brush-split.csv`는 원본 ID를 `-01` 턱, `-02` 코, `-03` 눈 브러쉬로 나누는 명세임. 상품 적재 후 `link_youtube_split_products.py`를 실행해 원본 영상 언급을 세 서빙 상품에 모두 `split` 링크함.
- `apply_reviewed_identity_rules_v316.py`는 기존 CSV에 승인 ID+URL 판정을 적용하는 후처리 전용 도구임. 외부 검색이나 DB 쓰기를 수행하지 않음.

- v3.15는 짧은 검색어부터 글로우픽을 조회하며, 연속 HTTP 500 두 번이면 화해·파우더룸으로 넘어감. Windows에서 CSV가 열려 있어 교체가 거부되면 `*.recovery-*.csv`에 진행 결과를 저장하고 그 경로에 이어 씀.
- v3.14는 글로우픽 검색어 하나가 HTTP 500으로 실패해도 다음 검색어를 시도함. 같은 검색어의 500 재시도는 한 번만 하고, 브라우저 검색과 화해·파우더룸 조회를 계속함. 모든 검색어가 실패하고 다른 출처에도 후보가 없으면 `errors`로 남김.
- v3.13에서는 이전 수집의 `complete`도 현재 상품 동일성 규칙으로 다시 확인하고, 부적절한 행만 재수집함. 검수된 `2호 퍼지` 행은 후보 페이지에 호수가 없으면 자동 완료하지 않음. 글로우픽 검색 API가 HTTP 500을 반복 반환한 맥 브로우 펜슬은 맥 공식 상품 페이지에서 확인한 가격·용량·이미지를 검수된 후보로 기록함.
- 이전 50건과 이번 전체 수집의 `not_found`는 **같은 `--report` CSV로 이어받을 때** 다음 실행에서 재검색하지 않음. 다른 CSV를 쓰거나 `--refresh`를 실행하면 이 기록은 적용되지 않음. `--retry-errors`는 기술 오류를 다시 시도하지만 `not_found`는 다시 검색하지 않음.

- `enrich_catalog_sources.py` v3.11은 아직 올리브영 상품이나 서빙 상품에 연결되지 않고 비상품 제외 목록에도 없는 유튜브 영상 언급 상품을 대상으로 함. 일반 화장품은 글로우픽 → 화해 → 파우더룸 순서, 메이크업 소도구와 속눈썹 제품은 올리브영 → 글로우픽 → 화해 → 파우더룸 순서로 조회함. 앞 단계에서 제품을 찾지 못한 경우뿐 아니라 동일 제품의 가격·이미지·용량 정보가 남아 있는 경우에도 파우더룸을 마지막 보강 출처로 조회함. 속눈썹·소도구는 용량을 필수 정보로 보지 않음.
- 브랜드 별칭 CSV를 이용해 한글·영문 표기의 정규화 브랜드 검색어를 추가함. 브랜드 표기가 달라도 후보를 바로 버리지 않으며, 제품명·브랜드·제품 유형 근거가 엇갈리면 `needs_review`로 분리함. 다른 브랜드·렌즈·명시적으로 거부한 URL은 후보에서 제외함.
- 상품명 비교에는 기존부터 띄어쓰기·유니코드·브랜드 별칭·검수된 오타·옵션 표기 정규화가 적용되어 있음. v3.9은 이를 새로 도입하는 버전이 아니라 자동 완료 판정에서도 같은 정규화 결과를 활용하고, 확인된 제품명 표기 변형과 가격이 상품명 끝에 붙은 사례를 보완함. 별도 옵션 칸·검수된 옵션 목록·구분 기호(`_`, `#`)·강한 숫자 호수 규칙으로 호수/옵션 접미사를 분리함. 구분자 없이 붙은 일반 단어는 자동으로 옵션 취급하지 않음. 에디션·컬렉션 표기는 패키지 차이로 보고 검수 사유로 추가하지 않음. 양쪽에 명시 옵션이 있고 값이 다르거나 상품 형태가 명백히 다르면 후보를 버리지 않고 `needs_review`로 남김.
- 글로우픽은 정규화 브랜드+제품명, 원문 제품명, 확인 가능한 기본 제품명 검색어를 사용하고 검색 결과의 제품 및 리뷰 태그 상품을 후보로 모음. 리뷰 태그 후보도 상세 페이지의 상품 동일성 근거가 충분하면 완료할 수 있음. 카테고리가 원본에 없으면 글로우픽 상세 페이지의 상품정보 카테고리 경로를 읽어 앱 카테고리 태그로 변환함. 화해는 검색 제품 후보를 브랜드·제품명 근거로 비교하고 상세 URL을 기록함. 화해 상세 페이지가 빈 응답을 주는 경우에도 검색 결과의 가격·용량·이미지를 사용할 수 있음.
- `review_reason` 컬럼명은 영어로 유지하고, 검수 사유 값은 한국어로 기록함. `makeup_zone`과 선택된 제품 상세 페이지의 카테고리 경로도 앱 분류 매핑에 사용함. 글로우픽은 상세 카테고리 경로를 읽고, 화해는 상세 페이지 JSON의 상품 카테고리를 읽으며 랭킹·수상 정보 유무에 의존하지 않음.
- 검수 완료한 상품 링크는 `reviewed_product_urls.csv`, 선택 후보와 검수된 필드 증거는 `reviewed_candidate_overrides.csv`, 가격 정정 승인은 `reviewed_price_overrides.csv`에 원본 상품 ID와 근거 URL을 기록함. 이 값은 다음 수집에서도 재사용함.
- `reviewed_hwahae_urls.csv`는 사람이 확인한 유튜브 원본 ID, 화해 상품 ID, 검색어를 기록함. 검색 결과에서 **그 ID가 실제로 확인될 때만** 후보로 채택하며 다른 상품으로 대체하지 않음. 원본 상품명에 리뷰 문장이 섞여 있거나 영어·한국어가 혼합된 예외에 사용함.
- v3.12는 SPF 뒤의 호수 표기를 보존하고, 출시 예정 메모·확인된 브랜드 접두어·호수 표기 차이를 정리하여 제품명 비교에 사용함. 별도 옵션 칸이 있으면 상품명과 호수를 합친 검색어를 먼저 시도함. 호수 번호만 같을 때는 원본 제목의 색상명까지 후보와 맞아야 완료함. 호수가 서로 다르면 같은 제품군으로 보여도 `needs_review`로 유지하여 다른 호수의 상품 이미지를 자동 채택하지 않음. 캔메이크 `Abloom`과 일반 파우더는 별개 제품이므로 이름이 비슷해도 자동 결합하지 않음.
- 원본 브랜드가 `확인 필요` 등 placeholder인 경우 브랜드명 대조와 브랜드 미확인 검수 사유를 생략함. 호수·SPF 표기 등을 분리한 핵심 제품명이 정확히 일치하고 식별 가능한 이름이며 제품 형태가 충돌하지 않을 때 자동 완료함. 같은 이름에 다른 브랜드 후보가 있으면 `needs_review`로 남김. 확인된 원본 브랜드명이 검색 후보 브랜드명 안에 포함되면 같은 브랜드로 판단함(예: `드롭비`/`드롭비 컬러즈`, `AOU`/`AOU (에이오유)`). 그 외 표기 차이만으로 후보를 버리지는 않으며, 실제 브랜드가 다르면 `needs_review`로 남김.
- 원본 상품명 끝에 별도 옵션명 또는 `01쿨애쉬`처럼 강한 호수·색상 표기가 붙고 기본 상품명이 후보와 일치하면 같은 상품으로 판정함. `reviewed_product_options.csv`에는 사람이 확인한 비숫자형 호수도 원본 ID별로 기록함. 원본 브랜드의 검수된 별칭이 상품명 앞에 붙은 경우도 제거해 비교함.
- 소도구와 속눈썹은 가격·이미지만 보강하고 용량은 비워둠. 결과 CSV의 태그는 `["youtube", "tool"]`; 그 외 상품은 원본 카테고리를 앱용 태그로 바꾸어 기록함. 원본 분류가 불명확하면 `unknown`으로 남겨 검토함.
- CSV의 `lookup_status`는 다섯 값으로 구분함: `complete`(식별·필수 정보 완료), `needs_review`(후보는 있지만 사람의 판단 필요), `incomplete_data`(후보는 식별했지만 필수 정보 누락), `not_found`(검색은 정상 완료했으나 후보 없음), `errors`(기술 오류로 검색이 끝나지 않아 결과를 확정할 수 없음). 후보가 없는 행은 더 이상 `needs_review`로 섞지 않음. `apply`는 `complete` 행만 원본 상품에 반영함.
- 사람이 확인한 글로우픽 제품 URL은 `reviewed_product_urls.csv`에 유튜브 원본 ID와 글로우픽 상품번호로 기록함. 해당 행은 자동 검색 후보 대신 승인된 상세 페이지를 직접 조회하고 CSV의 `match_basis`에 `reviewed_override`를 표시함. 상세 페이지에서 가격·이미지를 얻지 못하면 빈 값으로 남겨 검토함.
- 기본 `collect`는 10개 작업자로 수집하며 10건마다 CSV를 저장함. 후보 없이 정상 종료된 `not_found`는 같은 파일 재실행 때 다시 검색하지 않음. 기술 오류는 `errors`로 분리하며, 한 번의 실행 안에서 HTTP 5xx·연결 시간초과 등을 5초·15초·30초 후 재시도하고 전체 수집 뒤 필수 정보가 남은 일시 오류 행을 한 번 더 재시도함. 이후 별도 실행에서도 오류 행 재시도가 필요하면 `--retry-errors`를 지정함. 새 규칙으로 처음 수집할 때는 새 보고서 파일을 사용하며, `--refresh`는 보고서 결과 전체를 비우고 다시 수집함.
- 상품명과 브랜드 근거가 충분한 후보만 자동 완료하며, 유사도가 낮거나 원본 브랜드가 명확하지 않은 후보는 검수 대상으로 남김. 검색 결과는 일치도 순으로 비교하고, 리뷰 태그 상품이라도 상세 페이지의 브랜드·제품명이 정확히 일치하면 완료할 수 있음. 서로 다른 제품군 후보의 가격·이미지·용량을 합치지 않음. 먼저 찾은 후보가 한 필드의 값을 제공하지 않더라도 다른 출처의 동일 상품 후보가 그 값을 제공하면 채우며, 각 필드의 출처 URL을 따로 기록함. 원본의 신뢰 가능한 값은 덮어쓰지 않음. 이전 버전의 CSV에는 새 판정 기준이 소급 적용되지 않으므로 새 보고서 파일로 재수집함.
- 카테고리가 비어 있고 화해 제품을 선택한 경우 상세 페이지의 제품 분류(`productGoodsPairData.product.categories`)를 읽음. 단종 상품에도 이 분류가 남아 있을 수 있으므로 랭킹/수상 문구에 의존하지 않음.
- 파우더룸 검색은 `api.powderroom.co.kr/core/v1/common/user/search/product` API, 상품 정보는 `/core/v1/common/user/product` API에서 읽음. 검색 HTML은 자바스크립트 실행 전에는 상품 링크를 담지 않아 API 결과 ID를 사용함. 상품 상세에서 브랜드·상품명·가격·이미지·분류와 명시된 경우 용량을 수집하며, 값은 추정하지 않음. 제품 형태, 브랜드, 옵션 또는 용량이 충돌하면 자동 완료하지 않고 검수로 남김. 파우더룸 결과도 없으면 `not_found`, 요청 오류가 끝까지 해소되지 않으면 `errors`로 분리함.
- `--phase preflight`는 CSV의 원본 브랜드·제품명, URL과 갱신 대상을 확인함. `--phase apply`는 수집된 가격·이미지·용량 중 빈 값 또는 추정 가격만 로컬 `raw_yt_product`에 반영함. 태그는 CSV에 남겨 향후 서빙 카탈로그 작성에 사용함. 서빙 `products` 적재는 별도 단계임.

- `enrich_glowpick.py`는 로컬 `raw_yt_product`에서 `price_krw IS NULL`인 행을 대상으로 Glowpick 검색 후보를 CSV로 수집함. 기본 단계는 미리보기이며 DB에는 쓰지 않음.
- 검색은 상품명 단독과 확인 가능한 브랜드명+상품명 모두를 사용하고 결과를 합침. 제품 검색 결과뿐 아니라 전체 검색의 리뷰 결과에 태그된 상품도 후보로 수집함. CSV의 `candidate_source`에서 `product_search`, `review_tag` 또는 두 경로 모두인지를 확인할 수 있음. `확인 필요` 같은 placeholder 브랜드는 검색어로 사용하지 않음.
- 검색 후보는 상품명 유사도와 브랜드 일치 여부를 함께 보여주며, 점수만으로 자동 확정하지 않음. 검수자가 상품이 맞는 후보 한 행에만 `approved`를 `yes`로 표시함.
- `no_results`는 두 검색어의 제품 및 리뷰 검색 결과에 후보가 없었다는 뜻일 뿐, 해당 상품이 Glowpick에 없다는 확정 판정이 아님. 기존 결과를 새 검색 기준으로 다시 만들 때 `--refresh` 사용. 이전 버전 CSV도 새 `candidate_source` 열을 자동으로 보완해 이어서 갱신 가능함.
- `--phase verify`는 승인한 Glowpick 상품 상세 페이지에서 구조화 가격과 카테고리 경로를 다시 확인해 CSV에 기록함. 상세 페이지 검증에 실패한 행은 적재할 수 없음.
- `--phase apply`는 검수·상세 확인이 끝난 승인 행만 로컬 DB에 반영함. 가격과 카테고리는 비어 있는 값만 채우고 기존 값은 보존함.
- Glowpick 카테고리는 `raw_yt_product.category`가 비어 있는 경우에만 상세 페이지의 분류 경로 그대로 저장함. 앱 서빙 카테고리로의 변환은 별도 단계임.
- iPhone Safari User-Agent를 사용해 모바일 브라우저로 요청하되, Glowpick 웹 API를 호출함. `--workers` 기본값은 10이며, 전체 작업자가 요청 간격을 공유함.
- HTTP 403 또는 429 발생 시 전체 작업자가 1분·3분·10분 순서로 대기한 뒤 같은 요청을 재시도함. 세 번의 대기 뒤에도 차단되면 체크포인트를 저장하고 중단함.
- 수집·상세 확인은 10건 단위로 진행 로그와 CSV를 저장함. Ctrl+C 또는 차단 중단 뒤 같은 CSV로 이어갈 수 있음. Excel에서 CSV를 열어 파일 교체가 잠기면 최신 진행본을 `*.recovery-*.csv`로 저장하고 경로를 출력함.

## 이미지·색상·제형 보강

- `enrich_product_assets.py`는 `raw_yt_product`의 빈 `image_url`, `hex_code`, `texture`를 보강하는 로컬 전용 스크립트임.
- 확정된 올리브영 상품·옵션 연결은 원본 올리브영의 대표 썸네일, 정확히 연결된 옵션 색상칩, 제형값을 우선 사용함. 유튜브 옵션이 없을 때는 올리브영에 활성 옵션이 하나뿐인 경우에만 그 색상을 사용할 수 있음.
- 그 외 상품은 기록된 `product_url` 또는 `image_source_url`의 Open Graph / JSON-LD 메타데이터에서 확인 가능한 이미지, 명시적 HEX, 명시적 제형만 제안함. 상품 썸네일에서 색상을 추정하지 않음.
- 상품 페이지 주소가 없는 행은 Google 검색 링크를 검수 CSV에 생성함. 검색 결과의 첫 이미지를 자동 채택하지 않음. 확인한 상품 페이지 주소를 CSV의 `source_page_url`에 입력하고 다시 실행해 근거를 확인함.
- 미리보기 후 CSV의 `approved` 열을 `yes`로 표시한 행만 `--apply`로 DB에 반영함. 기존 값은 덮어쓰지 않음. 승인한 제안이 미리보기와 달라지면 적용되지 않음.
- 실행 중에는 웹페이지 수집과 상품별 분석 진행 상황을 각각 10개 단위로 터미널에 출력함.
- 외부 페이지의 구조화 정보가 없는 경우 색상·제형을 자동으로 채울 수 없으며, 해당 값은 검토 대상으로 남음.

## 이미지·색상 주의

- 현재 조사 파일의 1,490개 조합 중 직접 이미지 URL은 5개, 상품 페이지 URL은 642개, HEX는 0개임.
- 상품 페이지 URL은 이미지 URL이 아님. 일반 썸네일에서 색상을 임의 추정하지 않음.
- 매칭 실패 상품의 대표 이미지와 옵션별 색상칩은 `unmatched_products.csv`를 근거로 공식 상품 페이지·옵션 이미지를 별도로 확인해 확보해야 함. 출처 URL을 함께 기록하고 실제 옵션과 맞는지 검수할 것.
- `확인 필요` 브랜드와 이름 유사 후보는 미확정으로 유지. 매칭 실패가 곧 올리브영 미취급이라는 뜻은 아님.

## 올리브영 미취급 상품의 앱 반영

- `build_complete_catalog.py`는 `lookup_status=complete`인 보강 결과를 기존 카탈로그에 덧붙인 검토용 JSON을 생성함. 소도구 검수 CSV가 complete 소도구 24건을 모두 다루고 적재 승인했는지 확인함. 실제 도구로 판정한 상품은 `category=tool`, `tags=["youtube", "tool"]`로 기록하고, 화장품으로 판정한 행은 검수한 앱 카테고리를 사용함. DB에는 쓰지 않음.
- `tool`은 앱 상품 카테고리로 검색·표시할 수 있지만 AR 메이크업 영역이나 호수·제형 정보가 있다는 뜻은 아님. 소도구는 `makeupZone=null`, `texture=null`, 빈 용량으로 적재함.

- `verified_non_oy_products.csv`에는 공식 페이지에서 가격과 상품 사진까지 확인한 행을 기록함. 검증된 이미지·가격이 있는 기존 상품은 이 값을 유지함.
- `non_oy_source_price.csv`에는 올리브영 미입점 브랜드로 확인되고 상품을 식별할 수 있으며 원본 가격이 양수인 행의 ID와 앱 카테고리를 기록함. 이 경로는 원본 가격을 사용하고 이미지 URL을 비움. `추정 정가`는 `price_estimated` 태그를 추가함. 가격이 없는 행, 소도구, 하나의 행에 두 상품이 섞인 경우, 중복 표기와 상품을 식별하기 어려운 행은 넣지 않음.
- `build_verified_catalog.py --output <검토용 JSON 경로>`는 원본 유튜브 ID와 DB 값을 대조하고, 이미 올리브영 상품에 확정 연결된 행을 거부함. 기존 시드에 선택된 상품만 더한 검토용 JSON을 만들며 DB에는 쓰지 않음.
- `non_product_exclusions.csv`에는 상품명이 구매 기록이나 영상 설명 문장으로만 남아 상품을 특정할 수 없는 원본 ID를 수동 검토 후 기록함. `build_verified_catalog.py`는 raw-selection에서 이 ID를 제외하고, 원본 DB의 브랜드·상품명이 제외 목록과 바뀌었으면 중단함. `raw_yt_product` 원본은 삭제하거나 수정하지 않음.
- `filter_non_products.py`는 로컬 `raw_yt_product`를 조회해 이미 올리브영 매칭·카탈로그 연결·서빙 적재된 제품을 제외한 뒤, 명백한 비상품과 검토 후보를 나눔. 자동 제외 기준은 상품명에 `직접`, `..`, `ㅠㅠ`, `왜 단종`, `제 최애`, `대체 가능합니다`, `생각`, `것 같`, `느낌`, `같아요`, `제품`, `렌즈`가 포함되거나 브랜드명에 `렌즈`가 포함된 경우임. `..`는 연속 마침표 두 개를 뜻함. 브랜드·상품명에 렌즈가 있으면 콘택트렌즈 항목으로 자동 제외함.
- 기본 `--phase preview`는 Downloads에 자동 제외 후보 `youtube-non-product-auto-exclusions.csv`와 수동 검수 목록 `youtube-non-product-review.csv`를 생성하며 DB와 제외 목록 모두 수정하지 않음. 자동 제외 후보 CSV를 먼저 확인한 뒤 `--phase apply`를 실행하면 자동 제외를 `non_product_exclusions.csv`에 추가함. 수동 검수 CSV에서 `decision`을 `exclude` 또는 `keep`으로 선택하고 `--review-decisions <검수 CSV>`를 함께 지정하면 직접 `exclude`로 판정한 행도 추가함. 검수 CSV를 지정하지 않은 `apply`는 자동 제외만 반영함. 이 작업도 DB 원본을 삭제하거나 변경하지 않음.
- 앱 `category`는 `lip`/`cheek`/`eye`/`base` 등으로 변환하고 `tags`에는 `youtube`와 원본의 세부 카테고리를 보관함. `name`, `nameKo`, `description`, `volume`, `priceKRW`는 원본 값을 사용함. `position`과 `search_text`는 시드 적재기가 생성하고, `searchKeyword`는 브랜드와 상품명으로 생성함.
- 색상·제형이 비어 있으면 `makeupZone`을 `null`로 둠. 앱의 AR 상품은 검증된 색상과 제형을 모두 요구함. 유튜브 상품의 빈 이미지 URL은 실시간 쇼핑 이미지 검색으로 채우지 않음.
- 검토용 JSON과 기존 `backend/api/seed/catalog.json`의 차이를 확인한 뒤 시드 파일에 반영하고 `app.jobs.seed_catalog`로 로컬 DB에 적재함. 전체 시드 적재는 기존 서빙 카탈로그를 교체하므로 변경 건수와 기존 시드 보존을 먼저 확인할 것.
- 검증된 유튜브 전용 상품은 보통 원본 `yt_product_id`를 서빙 상품 ID로 사용함. 원본 ID와 서빙 ID가 다르거나 분리·통합되는 예외는 별도 연결 테이블을 사용함. 색상값이 검증되지 않은 경우 호수 링크와 AR 적용은 생략함.
- 검수 카탈로그의 원본 ID와 서빙 ID가 다르거나 분리·통합된 상품은 `link_approved_catalog.py`가 `yt_catalog_product_link`에 연결을 기록함. 기본 실행은 미리보기이며 `--apply`를 지정한 경우에만 로컬 DB에 반영함.
- `yt_catalog_product_link`는 카탈로그 전체 재적재에서도 유지됨. 한 원본에서 분리된 쿠션 두 상품은 같은 영상 언급에 각각 연결되어 영상 목록에서도 두 서빙 상품으로 표시됨.
