# 유튜브 조사 상품 적재와 매칭

## 범위

- 입력: 조사 엑셀의 `전체 제품` 시트. 입력 파일과 생성된 검수 CSV는 저장소에 넣지 않음.
- `raw_yt_product`: 조사 브랜드·상품명·옵션 조합 1건당 1행. 옵션이 `원본에 별도 옵션 없음` 또는 `원문에 명시 정보 없음`이면 옵션 이름을 비움. 단일 색상이라는 뜻으로 해석하지 않음.
- `raw_yt_product_mention`: 영상별 언급 1행. 원본 행 ID와 조사 레코드 ID로 역추적 가능.
- `yt_oy_product_match`: 올리브영 상품·옵션 후보와 검수 결정. 이름 유사도만으로 `confirmed`를 만들지 않음.
- `yt_catalog_product_link`: 검수된 유튜브 원본 상품 ID와 앱 서빙 상품 ID의 연결. 한 원본을 두 상품으로 나누거나 여러 원본을 한 상품으로 합친 경우도 표현함.
- 유튜브 조사값을 먼저 원본 테이블에 적재하고, 확인된 중복 여부에 따라 앱 서빙 대상과 미취급 상품을 구분함. 원본 행은 삭제하지 않음.

## 실행 순서

1. 로컬 DB의 Alembic을 현재 develop head까지 적용. 유튜브 원본 테이블은 0015에서 추가됨.
2. `load_products.py --validate-only`로 파일 구조·건수 확인. 현재 파일의 예상값: 영상 언급 1,617건, 제품·옵션 조합 1,490건.
3. 같은 스크립트를 쓰기 옵션 없이 실행해 DB 제약과 이전에 잘못 적재된 옵션 미확인 행의 정리 건수까지 검증한 뒤 트랜잭션 롤백.
4. 로컬 DB에 `--apply`로 적재하고 두 테이블의 건수·원본 행 ID 유일성 확인.
5. `match_products.py`의 기본 미리보기로 `brand_review.csv`, `unknown_brand_products.csv`, `product_candidates.csv`, `unmatched_products.csv` 생성. `확인 필요` 브랜드는 별도 목록에서 조사하고 유사 브랜드 추천으로 자동 대체하지 않음. 브랜드 별칭은 검수자와 검수일이 있는 CSV만 사용.
6. 검토 후 후보를 저장하려면 `match_products.py --apply` 실행. 후보 상태는 모두 `candidate`; 상품·옵션 확인 뒤에만 `confirmed`로 전환.
7. `enrich_confirmed.py`로 확정 연결의 기존 올리브영 색상·제형을 미리보기. 상품 옵션을 특정했거나 올리브영 활성 옵션이 정확히 하나일 때만 색상 사용. 기존 유튜브 조사값은 보존.
8. 데이터 담당자의 로컬 `vishue_db`에서 적재·검수를 마친 뒤 팀원용 DB 덤프를 만들어 전달. 팀원은 덤프를 자신의 로컬 DB에 복원. AI-Hub처럼 개별 이용권한이 필요한 데이터는 기존 덤프 정책에 따라 제외. 현재 스크립트는 `127.0.0.1` 또는 `localhost`의 PostgreSQL만 허용.
9. 이미지·색상·제형 누락분을 보강할 때는 아래 `enrich_product_assets.py` 절차를 사용.

## Glowpick 가격·카테고리 보강

- `enrich_glowpick.py`는 로컬 `raw_yt_product`에서 `price_krw IS NULL`인 행을 대상으로 Glowpick 검색 후보를 CSV로 수집함. 기본 단계는 미리보기이며 DB에는 쓰지 않음.
- 검색은 상품명 단독과 확인 가능한 브랜드명+상품명 모두를 사용하고 결과를 합침. 제품 검색 결과뿐 아니라 전체 검색의 리뷰 결과에 태그된 상품도 후보로 수집함. CSV의 `candidate_source`에서 `product_search`, `review_tag` 또는 두 경로 모두인지를 확인할 수 있음. `확인 필요` 같은 placeholder 브랜드는 검색어로 사용하지 않음.
- 검색 후보는 상품명 유사도와 브랜드 일치 여부를 함께 보여주며, 점수만으로 자동 확정하지 않음. 검수자가 상품이 맞는 후보 한 행에만 `approved`를 `yes`로 표시함.
- `no_results`는 두 검색어의 제품 및 리뷰 검색 결과에 후보가 없었다는 뜻일 뿐, 해당 상품이 Glowpick에 없다는 확정 판정이 아님. 기존 결과를 새 검색 기준으로 다시 만들 때 `--refresh` 사용. 이전 버전 CSV도 새 `candidate_source` 열을 자동으로 보완해 이어서 갱신 가능함.
- `--phase verify`는 승인한 Glowpick 상품 상세 페이지에서 구조화 가격과 카테고리 경로를 다시 확인해 CSV에 기록함. 상세 페이지 검증에 실패한 행은 적재할 수 없음.
- `--phase apply`는 검수·상세 확인이 끝난 승인 행만 로컬 DB에 반영함. 가격과 카테고리는 비어 있는 값만 채우고 기존 값은 보존함.
- Glowpick 카테고리는 `raw_yt_product.category`가 비어 있는 경우에만 상세 페이지의 분류 경로 그대로 저장함. 앱 서빙 카테고리로의 변환은 별도 단계임.
- iPhone Safari User-Agent를 사용해 모바일 브라우저로 요청하되, Glowpick 웹 API를 호출함. `--workers` 기본값은 10이며, 전체 작업자가 요청 간격을 공유함.
- HTTP 403 또는 429 발생 시 전체 작업자가 1분·3분·10분 순서로 대기한 뒤 같은 요청을 재시도함. 세 번의 대기 뒤에도 차단되면 체크포인트를 저장하고 중단함.
- 수집·상세 확인은 10건 단위로 진행 로그와 CSV를 저장함. Ctrl+C 또는 차단 중단 뒤 같은 CSV로 이어갈 수 있음. Excel에서 CSV를 열어 파일 교체가 잠기면 최신 진행본을 `*.recovery-*.csv`로 저장하고 경로를 출력함.

## 이미지·색상·제형 보강

- `enrich_product_assets.py`는 `raw_yt_product`의 빈 `image_url`, `hex_code`, `texture`를 보강하는 로컬 전용 스크립트임.
- 확정된 올리브영 상품·옵션 연결은 원본 올리브영의 대표 썸네일, 정확히 연결된 옵션 색상칩, 제형값을 우선 사용함. 유튜브 옵션이 없을 때는 올리브영에 활성 옵션이 하나뿐인 경우에만 그 색상을 사용할 수 있음.
- 그 외 상품은 기록된 `product_url` 또는 `image_source_url`의 Open Graph / JSON-LD 메타데이터에서 확인 가능한 이미지, 명시적 HEX, 명시적 제형만 제안함. 상품 썸네일에서 색상을 추정하지 않음.
- 상품 페이지 주소가 없는 행은 Google 검색 링크를 검수 CSV에 생성함. 검색 결과의 첫 이미지를 자동 채택하지 않음. 확인한 상품 페이지 주소를 CSV의 `source_page_url`에 입력하고 다시 실행해 근거를 확인함.
- 미리보기 후 CSV의 `approved` 열을 `yes`로 표시한 행만 `--apply`로 DB에 반영함. 기존 값은 덮어쓰지 않음. 승인한 제안이 미리보기와 달라지면 적용되지 않음.
- 실행 중에는 웹페이지 수집과 상품별 분석 진행 상황을 각각 10개 단위로 터미널에 출력함.
- 외부 페이지의 구조화 정보가 없는 경우 색상·제형을 자동으로 채울 수 없으며, 해당 값은 검토 대상으로 남음.

## 이미지·색상 주의

- 현재 조사 파일의 1,490개 조합 중 직접 이미지 URL은 5개, 상품 페이지 URL은 642개, HEX는 0개임.
- 상품 페이지 URL은 이미지 URL이 아님. 일반 썸네일에서 색상을 임의 추정하지 않음.
- 매칭 실패 상품의 대표 이미지와 옵션별 색상칩은 `unmatched_products.csv`를 근거로 공식 상품 페이지·옵션 이미지를 별도로 확인해 확보해야 함. 출처 URL을 함께 기록하고 실제 옵션과 맞는지 검수할 것.
- `확인 필요` 브랜드와 이름 유사 후보는 미확정으로 유지. 매칭 실패가 곧 올리브영 미취급이라는 뜻은 아님.

## 올리브영 미취급 상품의 앱 반영

- `verified_non_oy_products.csv`에는 공식 페이지에서 가격과 상품 사진까지 확인한 행을 기록함. 검증된 이미지·가격이 있는 기존 상품은 이 값을 유지함.
- `non_oy_source_price.csv`에는 올리브영 미입점 브랜드로 확인되고 상품을 식별할 수 있으며 원본 가격이 양수인 행의 ID와 앱 카테고리를 기록함. 이 경로는 원본 가격을 사용하고 이미지 URL을 비움. `추정 정가`는 `price_estimated` 태그를 추가함. 가격이 없는 행, 소도구, 하나의 행에 두 상품이 섞인 경우, 중복 표기와 상품을 식별하기 어려운 행은 넣지 않음.
- `build_verified_catalog.py --output <검토용 JSON 경로>`는 원본 유튜브 ID와 DB 값을 대조하고, 이미 올리브영 상품에 확정 연결된 행을 거부함. 기존 시드에 선택된 상품만 더한 검토용 JSON을 만들며 DB에는 쓰지 않음.
- 앱 `category`는 `lip`/`cheek`/`eye`/`base` 등으로 변환하고 `tags`에는 `youtube`와 원본의 세부 카테고리를 보관함. `name`, `nameKo`, `description`, `volume`, `priceKRW`는 원본 값을 사용함. `position`과 `search_text`는 시드 적재기가 생성하고, `searchKeyword`는 브랜드와 상품명으로 생성함.
- 색상·제형이 비어 있으면 `makeupZone`을 `null`로 둠. 앱의 AR 상품은 검증된 색상과 제형을 모두 요구함. 유튜브 상품의 빈 이미지 URL은 실시간 쇼핑 이미지 검색으로 채우지 않음.
- 검토용 JSON과 기존 `backend/api/seed/catalog.json`의 차이를 확인한 뒤 시드 파일에 반영하고 `app.jobs.seed_catalog`로 로컬 DB에 적재함. 전체 시드 적재는 기존 서빙 카탈로그를 교체하므로 변경 건수와 기존 시드 보존을 먼저 확인할 것.
- 검증된 유튜브 전용 상품은 보통 원본 `yt_product_id`를 서빙 상품 ID로 사용함. 원본 ID와 서빙 ID가 다르거나 분리·통합되는 예외는 별도 연결 테이블을 사용함. 색상값이 검증되지 않은 경우 호수 링크와 AR 적용은 생략함.
- 검수 카탈로그의 원본 ID와 서빙 ID가 다르거나 분리·통합된 상품은 `link_approved_catalog.py`가 `yt_catalog_product_link`에 연결을 기록함. 기본 실행은 미리보기이며 `--apply`를 지정한 경우에만 로컬 DB에 반영함.
- `yt_catalog_product_link`는 카탈로그 전체 재적재에서도 유지됨. 한 원본에서 분리된 쿠션 두 상품은 같은 영상 언급에 각각 연결되어 영상 목록에서도 두 서빙 상품으로 표시됨.
