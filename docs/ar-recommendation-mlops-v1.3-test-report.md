# AR 추천 MLOps v1.3 검증 보고서

검증일 2026-11-23 · 모델 재학습, 구매 A/B 판정, 교체 및 롤백

**격리된 환경에서 A/B를 통과한 `v2`로 교체한 뒤 추천 API가 새 버전을 사용했고, 롤백하자 `v1`으로 돌아왔다.** 같은 회원과 입력 후보를 사용한 새 요청에서 모델 버전과 첫 번째 추천 칩이 함께 바뀌었다. A/B 판정과 교체는 기존 운영 절차대로 각각 실행했다.

## 1. 검증 환경

임시 PostgreSQL 17.11 컨테이너에 AR 추천과 구매 귀속 테이블이 포함된 Alembic 리비전 `0031`을 적용했다. CatBoost 1.2.10과 현재 백엔드 코드를 사용했다. 추천·노출·담기·주문·결제 확인은 FastAPI의 ASGI 테스트 클라이언트로 기존 엔드포인트를 호출했다. 가상 회원 인증과 결제 제공자의 승인 응답은 테스트 대역으로 처리했다. 번들 로딩에는 `ENV=production`의 오프라인 통과 요건을 적용했다.

학습과 A/B의 모든 관측은 합성했다. 초기에는 핑크를, 추가 이력에서는 코랄을 담도록 했고, A/B 구매 건수는 승격과 유지 분기를 확인할 수 있게 고정했다. 아래 지표는 이 시나리오에서의 동작을 검증한다.

## 2. 기준 번들 생성과 재학습

기존 `export`로 추천 시점의 입력 스냅샷과 담기 이력을 읽었다. 첫 추출에는 요청 42건, 두 번째에는 새 요청 84건을 추가했다. 두 번 모두 요청당 칩 3개가 노출됐고 담긴 칩은 1개였다. `train`은 각 추출에서 시간순 70:15:15 분할과 PairLogit의 RandomSearch 16회를 적용했다. 두 번째 학습은 `--baseline`에 `v1`을 지정해 동일한 최신 테스트셋에서 비교했다.

| 번들 | 추출 요청 / 노출 | 테스트 요청 | 비교 기준 | 기준 NDCG@3 | 후보 NDCG@3 | 오프라인 판정 |
| --- | ---: | ---: | --- | ---: | ---: | --- |
| `v1` | 42 / 126 | 7 | 기록된 룰 순위 | 0.6309 | 1.0000 | `offline_pass=true` |
| `v2` | 126 / 378 | 19 | `v1` | 0.5000 | 1.0000 | `offline_pass=true` |

두 번들에 최소 NDCG@3 `0.90`과 최소 개선 폭 `0.10`을 적용했다. 회원 단위 95% 신뢰구간의 하한도 `v1`은 `+0.3691`, `v2`는 `+0.5000`으로 모두 양수였다. 각 모델의 버전은 `model.cbm` 해시에서 생성돼 추천 정책 기록에 들어갔다. [학습과 오프라인 판정 코드](../backend/api/app/services/ar_palette_training_service.py)

## 3. 구매 A/B 판정

`AR_PALETTE_MODE=experiment`에서 A에 `v1`, B에 `v2`를 고정했다. 서로 다른 가상 회원 16명씩에게 추천 1회를 요청하고 노출, 담기, 구매를 기록했다. 32개 요청 모두 배정된 번들 버전 하나를 사용했다. 구매 집계는 기존 `experiment` 명령의 추천 세션 대비 구매율을 사용했다.

| 그룹 | 모델 버전 | 추천 세션 | 담기 세션 | 구매 세션 | 추천 세션 대비 구매율 |
| --- | --- | ---: | ---: | ---: | ---: |
| A | `m-bfac7f3a4b1106db` | 16 | 12 | 3 | 18.75% |
| B | `m-14702b082aae319e` | 16 | 12 | 12 | 75.00% |

| 집계 시점과 설정 | 실제 반환값 |
| --- | --- |
| 실험 종료 1시간 후를 집계 기준으로 설정 · 구매 관찰 창 72시간 | `pending` · 관찰 미완료 32세션 |
| 실험 종료 4일 후를 집계 기준으로 설정 · 그룹당 최소 16세션 · 최소 개선 폭 +5%p | `passed` · 개선 폭 +56.25%p · 95% 신뢰구간 +31.25~+81.25%p |
| 같은 완료 데이터 · 대조 조건의 최소 개선 폭 +80%p | `retain_baseline` |

종료 이후 시점은 `--as-of`를 바꿔 재생했다. 운영 기준과 관찰 기간의 설정 방법은 MLOps 설계서에 있다. [구매 A/B 기준과 실행 명령](ar-recommendation-mlops-v1.0.md#5-실제-사용자-ab-테스트와-전환)

## 4. 번들 교체와 롤백

`passed` 확인 후 `AR_PALETTE_MODE=model`을 적용하고 `AR_PALETTE_MODEL_DIR`에 `v2` 번들 경로를 지정했다. 각 단계에서 설정 캐시를 비우고 FastAPI 앱을 다시 만든 뒤 같은 회원·후보로 요청했다. 응답의 추천 순서와 PostgreSQL 요청 행 및 피처 스냅샷의 `policy_version`을 대조했다.

| 확인 단계 | `policy_version` | 추천 순서 |
| --- | --- | --- |
| 교체 전 새 요청 | `ar1:-:-:m-bfac7f3a4b1106db` | 핑크 → 레드 → 코랄 |
| `v2` 교체 후 새 요청 | `ar1:-:-:m-14702b082aae319e` | 코랄 → 핑크 → 레드 |
| 교체 후 `v1` 요청 ID 재전송 | `ar1:-:-:m-bfac7f3a4b1106db` | 핑크 → 레드 → 코랄 |
| `v1` 롤백 후 새 요청 | `ar1:-:-:m-bfac7f3a4b1106db` | 핑크 → 레드 → 코랄 |

재전송에서는 교체 전의 후보 ID와 순서가 그대로 반환됐다. 롤백은 `AR_PALETTE_MODEL_DIR`을 다시 `v1` 경로로 지정해 실행했다. 이 검증의 승격과 롤백은 설정 변경으로 수행했고 실서비스 A/B와 배포는 이후 운영 단계다.

## 5. 재현 자료

`export`, `train`, `experiment`는 `python -m app.jobs.ar_palette_ml`의 하위 명령이다.

| 단계 | 실행 경로와 주요 옵션 |
| --- | --- |
| 임시 DB와 학습 데이터 | 로컬 Docker `postgres:17-alpine` → `alembic upgrade 0031` → 두 차례의 `ar_palette_ml export` |
| 번들 생성 | `ar_palette_ml train --min-ndcg 0.90 --min-lift 0.10`, 두 번째 학습에 `--baseline v1` 경로 지정 |
| A/B | `ar_palette_ml experiment --id ar-release-qa --purchase-window-hours 72 --min-sessions 16 --min-lift 0.05`와 시점별 `--as-of` 지정 |
| 교체와 롤백 | `AR_PALETTE_MODE=model`에서 번들 경로 `v1` → `v2` → `v1` 적용 후 새 추천 확인 |

검증에 사용한 스크립트 `verify.py`와 요청별 결과 `evidence.json`은 실행한 작업공간의 `ml/runs/ar-palette-release-20261123/`에 보관했다. 실행 때 생성한 DB 컨테이너, 임시 데이터셋과 모델 번들은 검증 후 정리했다.
