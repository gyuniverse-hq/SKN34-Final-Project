> 상태: **ACCEPTED-USER** — 2026-11-15 작성·재확인. 팀 합의·실제 구현·검증 여부는 별도.
> 연계: [설계 허브](README.md) · [결정 로그](DECISIONS.md) · [2단계 목표 구조](02-architecture.md)

## 1. 서비스 목표와 확정 정책

VISHUE는 **K-뷰티 중심의 자유 대화형 AI 뷰티 상담사**다. 사용자는 정해진 명령어나 질문 유형을 외우지 않고 고민을 설명하고, 상품·전성분·룩·화장법·수정화장·AR 체험을 한 대화에서 탐색한다. AR 카메라·피부 분석·사용자 제공 이미지·영상·STT·TTS·다국어 경험을 목표에 포함한다. **기존 한·영·일 3개 언어 기획과 현재 중국어 포함 4개 로케일 코드가 모두 존재하나, 언어별 실제 지원 범위와 시점을 최종 결정한 것으로 보지 않는다.**

| 정책 | 채택 원칙 |
| --- | --- |
| 자유 대화 | K-뷰티 중심. 범용 무제한 서비스가 아니라 뷰티 중심의 자유로운 의사소통 |
| 대화 주도성 | **적극적 뷰티 상담사**: 적절한 질문·다음 행동 제안, 사용자가 원하지 않는 제안 강요 금지 |
| 현재 맥락 | 현재 대화의 취향·조건·이전 상품·룩은 이어서 사용 |
| 장기 기억 | 저장에 **동의한** 취향·프로필·보유 제품만 보관·변경·삭제 가능 |
| 과거 방 조회 | **명시적 요청 B**: 현재 방 + 동의한 장기 기억을 기본 사용; 요청 시 권한 확인 후 이전 방 조회. 향후 자동 검색 C를 위한 정책 경계 보존 |
| 정보 우선순위 | 사용자 최신 명시적 의사는 **선호·목표**의 기준; 실제 상품·성분·AR 사실은 검증된 시스템 상태가 기준 |
| 자동 실행 | 상담용 조회·추천은 자율 실행; 실제 AR 변경·기억 저장·외부 행동은 사용자 의사와 권한·실제 상태를 검증 |
| 동시 요청 | **작업 성격에 따른 조정 C**: 새 의사는 즉시 반영; 취소 가능한 조회·분석은 취소·재계획, 이미 진행 중인 실제 변경은 결과 확인·복원 |
| 멀티모달 | 앱 자료 + 사용자 제공 **이미지·영상**; 기기·서버 혼합. 기존 AR 실시간 카메라 프레임 전송 금지 원칙 유지. 명시적 업로드는 별도 동의·처리 정책 |
| 신뢰성 | 일반 설명은 가능하나 상품·옵션·성분·영상 속 행동·AR 적용 성공은 근거·실행 결과 없이는 확정하지 않음 |

사용자 의사가 명확하면 불필요한 되묻기 없이 수행한다. 명시적 요청 없이 AR을 조작하거나 현재 대화의 일회성 선호를 자동으로 장기 저장하지 않는다. 특히 피부 분석의 experimental_unvalidated 결과를 의료적 진단으로 표시하지 않는다.

## 4. 모든 시나리오를 교차 검토할 변형 축

1. 사용자 표현: 직접 명령 / 간접 고민 / 모호한 표현 / 비정형 발화 / 다국어 / STT 오인식.
2. 대화 과정: 이어 말하기 / 지시어 / 조건 변경 / 질문 거절 / 오류 정정 / 목표 변경 / 다른 방 참조 요청.
3. 데이터 상태: 확정된 근거 / 일부 누락 / UNKNOWN / 출처 철회 / 미승인 자료 / API 오류 / 오래된 상품·가격.
4. 실행 상태: 조회 진행 / 분석 취소 / 실제 AR 실행 중 / 중복 요청 / ACK 유실 / 복원 실패 / 앱 재시작.
5. 미디어·개인정보: 업로드 동의 / 동의 철회 / 삭제 / 원본 접근 불가 / 장기 저장 요청 / 민감 정보 미보유.
6. 사용자 환경: 무음·음성 응답·TTS 중단, 카메라 권한 거절·추적 끊김·비지원 기기.

대표 시나리오가 12개라는 이유로 모델에 12개의 의도만 허용하지 않는다. 평가에는 모르는 표현·장기 대화·다단계 과업을 별도로 포함한다.

## 5. 사용자 경험 판단 경계

- **친절한 질문 vs 반복 질문**: 이미 충분한 정보가 있으면 질문 없이 답하거나 도구 호출.
- **미디어 출처 구분**: 영상 제목·설명만 관찰한 것과 실제 프레임·음성 전사·검수 레시피를 엄격히 분리.
- **상품 호수 일치**: 실제 AR 적용 상품·호수는 서비스 카탈로그의 검증된 항목만 사용. 추정 색상을 실제 판매 호수로 가장하지 않음.
- **AR 상태**: 제안·적용 요청·실제 렌더·서버 ACK를 별개로 기록. 취소·Undo·복원은 별개 기능.
- **개인정보**: AR 실시간 카메라 프레임은 기기 내 처리. 별도 참고 미디어 업로드·피부 분석 서버 경로는 다른 동의·전달·보존 정책.
- **의학적 단정 금지**: 의료적 진단·치료 주장과 화장법/성분 설명을 구분.
- **일상 대화의 경계**: 뷰티와 무관한 일반 대화를 제품의 주목적으로 확장하지 않음.

## 7. 1단계 승인과 구현의 차이

본 문서는 **서비스 목표에 대한 승인**이다. S01~S12의 실제 서비스 구현이나 품질을 보증하지 않는다. 현재 구현 근거와 차이는 [기존 문서 대조](04-gap-analysis-and-2-5.md)에 기록한다.

## 8. 다국어 지원 범위: 기존 3개 언어 목표와 4개 로케일 차이

> **VAI-D-013 / ACCEPTED-USER:** 1차 AI 개발·평가는 **한국어(`ko`)만 필수**. **OPEN-LANG-01 부분 해소:** 기존 한·영·일 3개 언어 기획과 현재 중국어 포함 4개 로케일의 차이는 남아 있지만, 1차 언어는 확정됐다. `en/ja/zh`의 AI·STT·TTS·AR 음성 정식 제공 시점은 **미결정**이다. [07 상세 정책](07-ko-first-language-and-evaluation.md).

| 층위 | 코드·문서에서 확인한 내용 | 실제 지원·최종 결정 |
| --- | --- | --- |
| 초기 서비스 범위 | 기존 사용자 기획의 한·영·일 3개 언어 | 이전 기준으로 기록. 중국어 확대 결정일·범위 확인 필요 |
| UI 로케일 | `lib/i18n/languages.ts`의 `LANGUAGES=['en','ko','ja','zh']`, `lib/i18n/index.ts`의 네 사전·영어 대체 문구 | **EXISTING-CODE**. 전 화면 번역 품질·실기기 UI·버튼 동작의 E2E 미확인 |
| 앱 로케일 리소스 | `app.json`의 `ko`, `ja`, `zh-Hans`; 영어는 기본 | **EXISTING-CODE**. `zh`와 `zh-Hans`의 어댑터·단말 언어 설정 동작 점검 필요 |
| 챗봇 요청 | `backend/chatbot/app/schemas/chat.py`의 `Locale=Literal['en','ko','ja','zh']` | **EXISTING-CODE**. AI 최초 구현·평가 범위는 `ko` 확정. 네 언어의 자유·복합 대화 품질 통과는 미확인 |
| 스타일·AR 설명 | `style_recipe_service.py`에 네 언어 문구, AR_SPEC §로케일 네 사전§ 규칙 | **부분 기반 존재**. 의미 일치·전체 기능 경로·품질 미확인 |
| STT(음성 입력) | `docs/design/functional-spec.md`는 계획(PLANNED)으로 표기, `app.json`은 Android 녹음 권한 차단 | **미검증/지원 범위 미결정**. 언어별 엔진·동의·권한·테스트 필요 |
| TTS(음성 출력) | 전체 음성 상담의 실제 TTS 배포·언어별 검증 증빙 없음 | **미검증/지원 범위 미결정**. 언어별 음성 품질·중단/재생 UI 필요 |

**언어 지원은 한 묶음으로 승인하지 않는다.** `UI 언어`, `LLM 대화`, `STT 인식`, `TTS 합성`, `AR 음성 명령`의 각 언어별 상태를 별도 매트릭스로 관리하고 2-6/4단계에서 실측한다. 중국어 로케일 존재만으로 네 언어 전체를 출시·실기기 지원하는 사용자 결정으로 기록하지 않는다.
