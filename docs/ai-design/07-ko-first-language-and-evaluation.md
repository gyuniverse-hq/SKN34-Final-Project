## 1. 확정된 범위와 변하지 않는 목표

- **1차 AI 구현 및 평가의 필수 언어: 한국어(`ko`)**. 자유 대화, 실제 상품·성분 상담, 스타일 코칭, AR 자연어 제어, STT·TTS의 첫 기술 검토 및 평가를 한국어로 진행한다. 단 **STT/TTS의 구현·실기기 동작 가능성이 이미 입증됐다는 의미가 아니다**.
- **14개 사용자 능력(C01~C14), 대표 시나리오 S01~S12, 기존 대화·개인화·멀티모달·AR 정책은 유지**한다. S10의 다국어·음성 능력은 목표 능력으로 보존하고 첫 검증 언어만 한국어로 설정한다.
- 기존 `en`, `ja`, `zh` UI 사전·로케일 코드와 챗봇 타입을 삭제하지 않는다. **해당 언어의 AI·STT·TTS·AR 명령 정식 제공 시점과 테스트 기준은 미결정**.
- 기존 초기 한·영·일 기획과 현재 `en/ko/ja/zh` 네 코드 로케일 간 차이는 역사적으로 유지하되, **1차 언어 결정은 해소**, 나머지 공식 출시 언어·기능별 지원은 `OPEN-LANG-01`로 남긴다.

| 영역 | `ko` 1차 범위 | `en`·`ja`·`zh` |

| 일반 자유 대화 | 1차 **개발·평가 필수** | 정식 AI 지원 범위·시점 **OPEN** |

| 스타일·룩 | 1차 개발·평가 필수 | 번역·룩 태그·기법 설명 품질 OPEN |
| AR 자연어 제어 | 1차 개발·실기기 확인 필수 | 다른 언어 명령 해석·기기 검증 OPEN |
| STT | **한국어 우선 기술 선택·구현 가능성·오인식 검사** | 언어·권한·모델·운영 지원 OPEN |
| TTS | **한국어 우선 음성 품질·중단·재생 검증** | 자연스러운 억양·발화 중단·지원 OPEN |

| 데이터/RAG | 한국어 질문·용어·성분 표준명·검색 품질 우선 | 원문 언어·대조 용어·임베딩/언어별 색인·재순위화 확장 OPEN |

**1차 필수 범위**는 목표 단계와 검증 우선순위의 정의다. 아직 `ko` AI/STT/TTS가 실제로 통합·검증된 상태로 표시하지 않는다.

## 4. 언어 중립적인 상태·Agent·Tool 계약

권장 불변조건:

1. `threadId/turnId/requestId/planId/taskId/actionId`, `productId/shadeId/optionId/evidenceId/sourceVersion`, 상태·에러 코드, `ToolName`, `ToolResult`, Agent 간 Handoff, DB PK는 특정 언어의 단어를 이용해 만들지 않는다.
2. `locale`은 **사용자 입력/응답 언어를 지정하는 속성**이고, 사용자 목표·상품/성분/근거 ID의 일부가 아니다. `inputLanguage`, `responseLocale`, `sourceLanguage`를 필요 시 구분하고 `requestedLocale`이 미지원일 때 별도 기능 제공 상태를 반환한다.
3. Agent에 전달되는 사용자 목표는 한국어 표현과 표준화된 구조값을 함께 보존한다. 필터 키·성분 연산자는 `includes/excludes`, `MATCH/NOT_MATCH/UNKNOWN/ERROR` 등 언어 중립 코드를 쓴다. 번역된 문자열을 ID·권한·상태 비교에 사용하지 않는다.
4. Tool의 데이터 반환은 언어와 무관한 정본 사실로 유지하고 최종 대화·설명·카드 안내만 `responseLocale`에서 처리한다. 근거의 원문·번역·출처를 혼동하지 않는다.
5. 한국어 지원 정책으로 다른 언어 요청을 임의 한국어 입력으로 조작하지 않는다. 현재 화면에 따라 지원 상태 안내와 **사용자 확인 후 한국어 AI 기능 진입**을 제공한다.

### 언어 확장 가능한 입력 계약 (목표 예시, 미구현)

```json
{
  "schemaVersion": "v1-proposed",
  "threadId": "opaque-thread",
  "turnId": "opaque-turn",
  "requestId": "opaque-request",
  "input": {"kind": "text", "text": "립 조금 연하게 해줘", "inputLanguage": "ko"},
  "responseLocale": "ko",
  "capability": "ar_natural_language",
  "contextRef": "opaque-screen-state"
}
```

`inputLanguage`/ `responseLocale`을 내부 메시지 외피(envelope)로 관리하되, 기존 `ChatRequest.locale`의 지원 범위나 `requestType`과 충돌하지 않도록 버전 어댑터를 사용한다. 현행 `/api/chat`이 이미 이 입력을 받는다고 주장하지 않는다.

## 5. 미지원 언어 UI의 AI 진입 UX (PROPOSED)

사용자가 영어·일본어·중국어 UI에서 AI 상담·음성 명령·STT/TTS를 선택할 때 **실제 제공되는 기능만 안내**한다.

- 화면 표시 언어는 그대로 유지한다.
- 선택 언어가 AI 기능의 지원 범위에 없는 경우, 그 언어의 UI 문구로 **"현재 AI 상담은 한국어로 먼저 제공됩니다. 한국어로 상담을 계속하시겠어요?"**라는 의미의 안내를 보여준다.
- 사용자가 수락하면 **해당 AI 대화의 언어만 한국어로 사용**한다. 전체 앱 언어·장기 선호를 임의로 변경하지 않는다.
- 거절하면 기존 탐색·상품 화면으로 복귀하고, 이미 제공 중인 비 AI UI 기능은 계속 사용할 수 있어야 한다.
- STT/TTS가 준비되지 않았다면 한국어 모드에서도 음성 버튼을 지원된 것처럼 노출하지 않고 **텍스트 상담 대안**을 제공한다.
- 선택 언어의 AI가 실제 제공되기 시작하면 기능별 지원 매트릭스/버전에 따라 안내를 제거할 수 있도록 feature capability로 관리한다.
- 접근성이 떨어지지 않도록 자막/텍스트 답변, 권한 거부, 취소·뒤로가기, 빈 상태, 다국어 안내 문구 길이를 검증한다.

**추가 사용자 결정 필요:** 위 미지원 언어 UX는 **추천 설계**다. 미지원 AI 진입을 완전히 숨길지, 안내 후 한국어 전환을 허용할지, 일부 기능만 허용할지는 사용자·프론트 합의 전 **OPEN-LANG-02**로 유지한다.

## 6. 3단계 한국어 우선 RAG·임베딩 전처리 고려

- **원문 보존:** 한국어 텍스트와 원문 언어, 브랜드/영문 상품명, 공식 성분 표준명·동의어·번역어를 별도 필드로 유지. 한글 치환으로 원본을 지우지 않는다.
- **검색 전처리:** 띄어쓰기·정규화(NFKC 등)를 검토하고 한국어 형태소·동의어/표기 변형을 독립 평가. 신제품·색상 호수·금액·성분의 정확한 표기는 키워드/정확 매칭과 의미 검색을 병합.
- **임베딩:** 한글 질의·설명·룩 레시피를 우선 임베딩 평가하되, 모델이 한국어 외 언어를 지원할 수 있는지, 언어별 score calibration·동일 문서의 번역 중복·권리 승인 상태를 추후 평가. **모델·차원·VectorDB 제품은 미결정**.
- **색인/언어 필드:** `sourceLanguage`, `contentLanguage`, `localizedTextRefs`, `embeddingModelVersion`, `indexVersion`, `sourceVersion`, `rightsStatus`, `reviewStatus`, `publicationStatus`를 구분. 언어별 색인을 추가해도 상품/옵션 ID와 근거 승인 원칙은 동일.
- **검증셋:** 한국어의 직접·간접 질문, 상품/호수·성분 질의, 형태소·오타·신조어·외래어, 근거 부족·철회, 룩 영상/사진 질문, 순차/병렬 요청 등으로 검색 recall/정확도·실제 응답 근거 검증. 품질 임계치는 4단계 사용자 승인.
- **권리:** AIHub 71961 등 권리·발행 미승인 자료는 한국어 임베딩 실험이라도 서비스 색인·외부 모델 제공을 허용한 것으로 취급하지 않음.

## 8. 4단계 평가 언어 분리

- **1차 필수 평가:** 동일한 14개 능력·S01~S12 전체를 사용자 목표의 구조로 유지하면서, 1차 구현 대상 기능의 **한국어 질문·응답·Tool·멀티턴·복합 요청·상태 변경·오류 복구**로 평가. 아직 구현되지 않은 STT/TTS는 별도 미실행/BLOCKED이며 실기기 통과를 주장하지 않는다.
- **후속 확장 평가:** `en/ja/zh`로 동일 Tool 사실·상품/성분 근거·의도 이해·AR 명령·STT/TTS 품질을 검증. 기존 **TC-22는 `TC-22-I18N-FOLLOWUP`으로 이관**하여 1차 필수 검증의 통과 조건에서 제외.
- **1차 언어 독립 불변조건:** ID·Tool status·Pydantic 데이터 타입·원본 성분/가격·증거 ID·색상 링크가 언어에 따라 달라지지 않는지를 **한국어 기반 API·스키마 테스트**로 별도 검증(`TC-KO-STRUCTURE-01` 제안). 4개 언어 실제 품질 평가를 이 테스트로 대체하지 않는다.

## 9. 남은 결정·검증

- **OPEN-LANG-01:** 1차 `ko`는 확정. `en/ja/zh`의 UI 외 AI·STT·TTS·AR 음성의 지원 목표/순서·출시 시점 미결정.
- **OPEN-LANG-02:** 미지원 언어 UI에서 AI 진입 안내/한국어 전환/기능 숨김 정책, 한국어 STT/TTS 미구현 시 화면 표시, 팀 UX 합의 필요.
- **OPEN-STT-01:** 한국어 STT/TTS 엔진·오디오 권한·Expo Go vs 개발 빌드·외부 모델 제공·지연/성능·비용/품질 미결정.
- **TEST REQUIRED:** 한국어 AI 실제 모델·실기기·마이크/스피커 테스트, 한국어 검색·임베딩 정량 평가 및 3개 언어 후속 E2E.
