## 사용자 경험과 책임

**기존 확정.** C01~C14, S01~S12, 한국어 우선, 현재 대화와 동의한 기억, 일반 LLM과 AR 소유권을 유지한다. 사용자는 관리법과 조건부 상품 추천을 한 번에 요청하고 후속 메시지에서 조건을 바꿀 수 있다. 사람의 명시적 변경은 이전 조건에 우선한다. 지식은 일반적인 관리 설명을 뒷받침하고 특정 상품의 가격·성분 사실은 해당 판매 옵션의 조회 근거가 뒷받침한다. AIHub에 대한 기존 사용 결정을 따른다.

**이번 구현 결정.** 피부 목표 복합 요청을 부모 LangGraph에 넘긴다. 모델은 현 발화의 목표·명시 조건·지식 요청·변경 여부를 구조화한다. 부모가 허용 도구, 의존성, 데이터 연결 및 다음 행동을 결정하며 각 전문 경로는 실제 결과를 확인한 뒤 반환한다. 실행 ID, 계획 버전, 작업 ID, 입력 fingerprint로 결과를 식별한다. 서비스 클라이언트와 실행 중 상태는 요청 수명에만 둔다.

## 저장과 후속 대화

로그인 상담의 소유권·요청 버전·중복·동의·최종 저장은 `ConversationService`가 맡는다. 최종 상담에 필요한 후보/옵션/목표와 사용자가 본 결과만 허용된 필드로 저장한다. 기존 v1 대화와 이전 앱 응답의 선택 필드를 읽을 수 있어야 한다. G7 checkpoint에는 요청 ID와 실행 상태만 보관한다. 게스트 단기 문맥은 기존 소유권·TTL 검사를 거친다. 게스트의 로그인 이전과 다른 상담방 자동 참조는 제공 범위에 없다. 실행 중 교체·취소·프로세스 재시작 후 미완료 계획 재개, 동의 철회 후 늦은 결과 차단의 완전한 경험은 ⑤에서 검증한다. 기존 명시적 기억 요청의 답변 덮어쓰기도 ⑤에서 다룬다.

## 실행 방법과 현재 구현 범위

로컬 챗봇의 `G8_ENABLED=true`로 일반 `POST /api/chat`의 한국어 피부 복합 경로를 켠다. 기본값은 false이며 이번 작업에서 배포 설정을 변경하지 않았다. G7 로그인 검증에는 기존 로컬 영속 설정 및 DB가 필요하다. 실제 지식 작성에는 G5의 기존 검색·모델 설정과 허용된 원문 전송 범위가 필요하다. 앱 SDK는 58.0.20이다.

비영속 한국어 후속 요청에서 클라이언트의 recentMessages를 사용할 때는 기존 입력 계약상 G1_SUPERVISOR_ENABLED=true도 필요하다. G1 OFF에서는 이 클라이언트 입력이 제거된다. G7 영속 경로는 인증·소유권·버전 확인 후 서버가 PG 대화에서 history를 복원하므로 이 클라이언트 입력 전제를 일반화하지 않는다. 원래 N01의 영속 질문→답변 복원은 G1 ON/OFF 모두 실제 PG와 대역 모델·Catalog로 검증했다. 이는 실제 모델의 의미 판단이나 운영 배포 설정 검증을 뜻하지 않는다.

부모는 `plan → execute → assess → finish`로 진행한다. 같은 세대에 속한 준비된 작업을 동시에 실행하고, 검증 작업은 추천 작업의 후보를 복사해 호출한다. 빈 후보는 옵션 API를 생략하고 일시적 추천 읽기 실패는 남은 예산 안에서만 재시도한다. 입력 참조의 작업 ID·계획 ID·세대가 다르면 거부한다. 이 버전은 완료된 턴에서 조건을 바꿔 새 계획을 시작할 수 있다. 실행 중 다른 턴을 병합하거나 임의의 전문 에이전트가 새 실행을 제출하는 기능은 ⑤ 과제다.

개발 중 G7 체크포인터가 중첩 그래프에 자동 상속되는 것을 실제 DB에서 확인했다. G8 하위 그래프는 `compile(checkpointer=False)`를 명시한다. 최종 결과의 G7 저장과 루트 실행 영수증만 소유권·버전 검사 후 남긴다.

**2026-11-26 사용자 요청과 표시 결정.** 상담은 근거로 뒷받침되는 관리법부터 안내한다. 일반 설명 앞에 ‘검증된 관리 원칙’이라는 수식어를 붙이지 않는다. 본문의 번호와 ‘참고한 자료’를 연결한다. 추천 카드에는 선택한 옵션과 해당 옵션의 금액을 표시한다. 가격을 확인한 시점은 카드의 ‘가격 정보’에 둔다. 예산 판정에는 조회 당시 해당 판매 옵션에 기록된 금액을 사용한다. 상품 상세의 대표 가격을 카드를 채우는 데 쓰거나 실시간 결제 가격을 보장하지 않는다. 실제 판매 가격과 카탈로그 옵션 가격을 동기화하는 정책은 이번 표시 변경 범위 밖이다.

## 2026-11-26 ④ 보완과 ⑤ N01

기준은 게시된 5ed8ac159af50cbe459eaea445c285e0ff2c9529다. 후보의 생성 목표 candidateGoals를 저장하고 부모·상담 진입점에서 비교한다. 설명 전용 턴에서 목표가 바뀌면 후보를 비운다. 생성 목표가 없는 구버전 후보는 재조회한다. 예산 변경은 같은 후보를 다시 검증한다.

계획기에 구매 요청·가격 분리와 제품 종류·사용 순서·상황·방법 보존을 지시한다. _SHOP 일치로 질문 전체를 교체하는 처리를 제거했다. 실제 모델의 의미 보존은 별도 검증 대상이다.

K1은 기존 G5 답변을 받고 제품 조회가 필요한 경우 현재 상담 LLM으로 성분 검색 조건을 추출한다. 제안은 성분명, 포함/제외 연산, 주장 인덱스, 근거 ID와 원문 구절을 가진다. P1은 사용자 목표로 V4를 조회한다. K1과 P1은 독립 실행하며 V1이 두 결과를 기다린다. 지식의 성분 제안은 Catalog ingredientConditions에 연결한다. 두 InputBinding에 계획·작업·버전 검사를 적용한다.

부모는 G5 resolve가 남긴 최종 주장과 인용 연결, 원문 근거 안의 정확한 인용 구절, 주장과 인용 각각의 성분명을 검사한다. 최종 주장이 원문을 의역했다는 이유만으로 거절하지 않는다. findings.index는 탈락한 초안 주장 번호이므로 최종 claims 배열 위치와 비교하지 않으며 추출 모델 입력에서도 제외한다. 성분명 자체가 번역되어 정규화 후에도 일치하지 않으면 적용하지 않는다. 의미상 포함/제외 및 적용 범위 판단은 추출 모델과 기존 G5 검증에도 의존하므로 실모델·사람 검토가 필요하다. 일반 지식을 특정 상품 효능 근거로 승격하지 않는다. 이 검사는 2026-11-26 실제 G5 의역 답변이 원문 문자열 불일치로 모두 탈락한 실행을 근거로 보완했다.

사용자 제외 조건을 우선하며 향료/fragrance/parfum은 동일하게 비교한다. 미확인 별칭은 기존 Catalog 정규화·UNKNOWN 계약을 따른다. 지식 제안의 포함·제외가 충돌하면 그 제안을 제거한다. 예산·무향료·제외 조건을 지식으로 덮어쓰지 않는다. 지식 실패 또는 추출 실패 시 가능한 상품 조회를 진행한다.

새 한도는 제안 최대 6개, 인용 구절 최대 500자, 추출 1회다. Catalog의 총 성분 조건 6개 한도 안에서 사용자 조건을 먼저 유지한다. compound_consultation_service.py의 KNOWLEDGE_CONDITION_TIMEOUT_SECONDS=5는 임시 추출 제한이다. 기존 부모 마감 80초 안에서 적용하고 초과 시 빈 제안으로 상품 조회를 진행한다. 실제 지연·빈 제안 비율·전체 응답 시간으로 조정한다.

## f7b97e1 검토 반영 — 진입과 원래 N01
