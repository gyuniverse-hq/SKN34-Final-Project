**승인 주체 구분:** `VAI-D-010`은 사용자가 **14개 능력·12개 시나리오의 사용자 경험 범위를 채택**했다는 결정이다. 그 범위가 아키텍처 설계의 충분한 기준선이라는 **검토자의 적합성 판단**은 별도 `REVIEW-CONCLUSION`이며 사용자의 기술적 승인 또는 실제 동작 검증을 뜻하지 않는다. 문서에 '승인'이 나타나더라도 판단 범위와 승인 주체를 함께 표기한다.

## 2-5 설계 검토 종료 기록 (2026-11-15)

- **결론 상태: REVIEW-CONCLUSION**, 사용자 결정이나 팀 승인 아님. Tool Registry·권한·원본/색인 책임, 가격 조건의 기준/시점에 한정된 판정, `ELIGIBLE/REFERENCE_ONLY/EXCLUDED`, `UNKNOWN/ERROR` 구분 및 철회·캐시·동기화 접근 불변조건을 정의해 2-5 검토 범위가 충분하다고 판단했다.
- **확정 사용자 정책**: VAI-D-001~013 그대로 유지, **VAI-D-014**는 대화에서 지시된 문서화 운영 변경을 뒤늦게 기록.
- **미확정 기술 선택**: OPEN-T01(기존 GET 후처리 vs Catalog 복합 옵션 API), OPEN-SYNC-01(전체/증분), OPEN-VECTOR-01(pgvector/독립), OPEN-EVIDENCE-01(공통 Envelope), OPEN-RIGHTS-01(정본 승인·철회 API). 추천안은 확정 결정으로 승격하지 않는다.
- **인계**: 2-6 앱·AR ACK·음성·후보 표시, 2-7 운영/장애·성능·보안 실증, 3단계 데이터·벡터 엔진·검색 품질, 4단계 한국어 평가 수치, 5~6단계 실제 API·DB·팀 구현 합의.
- **기술 구현과 검증은 수행하지 않음**. 새로운 데이터 수집, API/DB 수정·통합 테스트·실기기 검증·Notion 갱신 없음.
