# AR 대화 모드의 화면 반영 시간, 첫 음성 시간과 API 비용

2026-11-16 측정. “립 색을 조금 연하게 해줘”를 사용해 파일 전사 경로의 답변 생성 변경 전후를 비교했다. 아래에는 변경 전 네 모델을 비교한 실험과 모델별 단가도 함께 기록했다. 지연 수치는 Windows PC에서 실제 모델을 호출한 결과다.

## 파일 전사를 유지하고 Luna 답변을 앞당긴 결과

같은 한국어 녹음 “립 색을 조금 연하게 해줘”를 변경 전 5회, 최종 변경 후 5회 재생했다. 두 경로 모두 `gpt-transcribe`와 `gpt-6-luna`를 실제로 호출했고, 같은 PC의 Chrome 한국어 TTS로 측정했다. 매회 립 색상 패치 강도를 0.55로 되돌렸다. 10회 모두 올바른 조작을 선택해 0.45로 표시했다.

| 중앙값 | 변경 전 | 변경 후 | 차이 |
|---|---:|---:|---:|
| 발화 끝 → 화면 변경 | 4.422초 | 4.623초 | 0.201초 늦음 |
| 화면 변경 → 첫 음성 | 2.415초 | 0.028초 | 2.386초 단축 |
| 발화 끝 → 첫 음성 | 6.837초 | 4.710초 | 2.126초 단축 |

각 행은 개별 회차의 해당 구간에서 계산했다. 앱은 상대 강도를 올리거나 낮추거나 절반으로 줄일 때, 첫 툴 호출에서 Luna가 작성한 `onAppliedReply`를 받을 수 있다. 앱이 `APPLIED`와 해당 부위의 실제 강도 변화 방향을 확인하면 그 문장을 기기 TTS에 바로 전달한다. 최종 측정에서는 5회 모두 추가 답변 호출을 생략했다. 실제 생성 문장에는 “립 색을 조금 더 부드럽고 은은하게 바꿨어요.”와 “립 컬러를 조금 부드럽게 낮췄어요. 이 정도가 괜찮으실까요?”가 있었다.

| 방식 | 1회 | 2회 | 3회 | 4회 | 5회 |
|---|---:|---:|---:|---:|---:|
| 변경 전 화면 / 음성 (초) | 6.174 / 9.418 | 4.422 / 6.837 | 4.955 / 7.539 | 3.780 / 6.023 | 4.163 / 6.404 |
| 변경 후 화면 / 음성 (초) | 5.309 / 5.761 | 4.623 / 4.710 | 5.094 / 5.122 | 4.321 / 4.346 | 4.384 / 4.412 |

제품 추천·조회, 강도 한계, 렌더 실패, 초안 누락 등에서는 앱이 실제 결과를 보내면 Luna가 답변한다. 이 경로의 `gpt-6-luna`에는 짧은 결과 설명을 위해 `reasoning_effort=none`을 사용한다. 위 시간은 상대 강도 조절 한 문장에 대한 값이다. 전후를 순차 측정했으므로 서버 부하·네트워크 변동이 포함되며, 스마트폰의 얼굴 렌더링과 스피커 지연은 별도로 측정해야 한다.

실제 로컬 챗봇을 연결한 React Native 화면 통합 테스트에서도 “이거 조금만 연하게 해줘.”를 보냈다. 렌더 완료 전에는 답변이 보이지 않았고, 완료 뒤 “입술 색을 살짝 부드럽게 낮춰드렸어요. 이 정도가 괜찮으신가요?”가 표시됐다. 이어서 립을 지운 뒤 착용 제품 조회, 새 핑크 립 추천, 카탈로그의 핑크 계열 조회가 각각 실제 결과에 맞게 응답하는 것도 확인했다.

## 최초 네 모델의 같은 명령 지연 비교

각 칸은 사용자 발화 끝부터의 시간이다. 각 구성 3회, 최종 설정에서 예상 동작 성공 3/3. 괄호 안은 파일 전사 대비 중앙값 차이다.

| 음성 경로 | AR 동작을 고르는 모델 | 색상 패치 변경 | Luna 첫 음성 |
|---|---|---:|---:|
| `gpt-transcribe` 파일 전사 → 텍스트 추론 → 기기 TTS | `gpt-6-luna` | 4.35초 | 6.51초 |
| `gpt-live-transcribe` 전사 → 텍스트 추론 → 기기 TTS | `gpt-6-luna` | 6.77초 (+2.42초) | 9.20초 (+2.70초) |
| `gpt-realtime-2.1-mini` 음성 입력·툴 호출·음성 출력 | 같은 Realtime 모델 | **2.07초 (−2.28초)** | **1.57초 (−4.94초)** |
| `gpt-live-1` 음성 대화 + Responses 위임 | 위임받은 `gpt-6-luna` | 2.29초 (−2.06초) | 1.90초 (−4.61초) |

Realtime 2회와 GPT-Live-1 3회에서 첫 음성이 패치 변경보다 먼저 나왔다. 따라서 첫 음성이 들린 시각만으로 “조정이 끝났다”는 결과를 언제 들었는지 판단할 수 없다. 실제 조작을 기다리는 사용자의 관점에서는 화면 변경 열이 더 직접적인 지표다.

| 구성 | 1회 화면 / 음성 (초) | 2회 화면 / 음성 (초) | 3회 화면 / 음성 (초) |
|---|---:|---:|---:|
| 파일 전사 | 4.56 / 6.87 | 3.80 / 6.50 | 4.35 / 6.51 |
| Live 전사 | 6.77 / 9.20 | 6.52 / 8.54 | 7.39 / 10.40 |
| Realtime 단독 | 2.07 / 1.31 | 1.36 / 1.98 | 2.13 / 1.57 |
| GPT-Live-1 + 위임 | 2.29 / 2.02 | 3.47 / 1.84 | 2.25 / 1.90 |

### 조건과 해석 범위

- **입력.** 동일한 2.55초짜리 한국어 합성 음성을 AAC/M4A로 재생했다. 녹음을 20ms씩 나눠 음성이 검출된 마지막 구간을 발화 끝으로 잡았다. 초기 상태는 립 강도 0.55, 색상 보기 모드였다. 강도 올리기·낮추기·절반·립 제거·현재 립 조회·블러셔 선택을 함께 제시했다. 기대값은 한 단계 낮추기였으며 모델마다 실행 순서를 회차별로 바꿨다.
- **입력 전송.** 두 전사 구성은 앱과 같이 발화 종료를 기다린다. 재생 실험에서는 발화 끝에서 1.2초 뒤 같은 녹음 파일을 보냈다. 현재 `gpt-live-transcribe` 어댑터는 그때 WebSocket을 열고 PCM을 보내므로, 발화 도중부터 자막을 생성하는 방식의 성능은 이 표로 판단할 수 없다. 두 통합 음성 구성은 세션 준비를 마치고 발화 중 WebRTC로 마이크 트랙을 보냈다. 세션을 여는 시간은 발화 전이다.
- **화면 변화.** PC 실험은 올바른 툴 호출을 받은 뒤 캔버스 패치를 0.55에서 0.45로 그렸다. 두 애니메이션 프레임을 기다리고 픽셀 값이 실제로 달라졌는지 확인했다. 카메라, 얼굴 추적, 스마트폰 GPU 부하는 포함하지 않는다. 앱에서는 기존 `ar_control`이 현재 상태를 검사하고 렌더러가 반영을 확인한 결과를 사용한다.
- **음성 시작.** 두 전사 구성은 실제 Luna 답변에 브라우저 TTS가 보낸 재생 시작 이벤트를 사용했다. 통합 음성은 원격 오디오를 재생하면서 20ms 간격으로 첫 음성 신호를 검출했다. 두 방법은 재생 시점의 근사값이며 스피커 앞에서 측정한 음압과는 차이가 있다. 네 경로에 동일한 한 문장만 사용했으므로 추천·조회 등 다른 요청의 정확도나 일반적인 속도 순위까지 보장하지 않는다.
- **실패 이력.** 최종 표는 수정한 설정으로 새로 교차 실행한 12회 전체다. 앞선 실험에서는 GPT-Live-1이 기대와 다른 조작을 고른 회차가 3회 중 2회 있었다. 최종 설정은 사용자의 요청을 끝까지 듣고 위임하도록 지시하며 백엔드 추론 강도는 `none`이다. 문장을 특정 AR 명령에 매핑하는 규칙은 넣지 않았다.

이전 파일 전사 5.58초, Live 전사 7.83초는 **파일 전송부터 서버 답변 텍스트 완성까지**의 중앙값이다. 당시에는 앱의 무음 대기, 화면 그리기, TTS 시작을 측정하지 않았으므로 위 표와 직접 대조하면 안 된다.

## 모델별 공식 가격

2026-11-16 확인한 OpenAI API 표준 USD 단가. 토큰 단가의 단위는 **100만 토큰**이다. 세션 길이와 토큰 사용량을 달리 계산하므로 이 표의 숫자를 그대로 합산해 명령 1회 비용으로 해석할 수 없다.

| 모델 | 과금 대상 | 공식 단가 |
|---|---|---|
| `gpt-transcribe` | 전사한 오디오 길이 | **$0.0045/분**. [모델 가격](https://developers.openai.com/api/docs/models/gpt-transcribe) |
| `gpt-live-transcribe` | 실시간 전사 오디오 길이 | **$0.017/분**. [모델 가격](https://developers.openai.com/api/docs/models/gpt-live-transcribe) |
| `gpt-realtime-2.1-mini` | 오디오 토큰 | 입력 **$10.00**, 캐시 입력 **$0.30**, 출력 **$20.00**. [공식 가격표](https://developers.openai.com/api/docs/pricing) |
| `gpt-realtime-2.1-mini` | 텍스트 토큰. 화면 정보·툴 정의·툴 결과 등에 해당 | 입력 **$0.60**, 캐시 입력 **$0.06**, 출력 **$2.40**. [모델 가격](https://developers.openai.com/api/docs/models/gpt-realtime-2.1-mini) |
| `gpt-live-1` | Live 음성 세션을 유지한 시간 | **$0.05/분**, 초 단위 청구. 위임 모델·툴 비용 별도. [공식 가격표](https://developers.openai.com/api/docs/pricing) |
| `gpt-6-luna` | 텍스트 추론 및 답변, 또는 Live 위임 | 입력 **$0.10**, 캐시 입력 **$0.01**, 출력 **$0.50**. [표준 가격표](https://developers.openai.com/api/docs/pricing) |

파일 전사와 Live 전사 경로는 각각의 전사료에 Luna의 명령 선택·답변 생성 토큰 비용을 더한다. 기기 내장 TTS는 OpenAI TTS API를 호출하지 않는다. Realtime 단독은 같은 모델의 오디오·텍스트 사용량으로 계산한다. GPT-Live-1 구성은 Live 세션료에 위임 모델 사용량을 더한다. 예를 들어 세션이 60초 열려 있었다면 음성 세션료는 $0.05이고, 그 안에서 발생한 위임 비용이 별도로 붙는다. 이번 측정에서 개별 요청의 실제 청구액은 수집하지 않았다.

## 각 경로에서 누가 툴을 호출하는가

**Realtime 단독**에서는 `gpt-realtime-2.1-mini`가 한국어 음성을 듣고 현재 화면에서 제공한 `ar_control`의 인자를 직접 선택한다. 앱이 실행 결과를 같은 세션에 돌려주면 모델이 음성으로 이어 말한다. 별도의 STT, `gpt-6-luna`, 스마트폰 TTS 호출이 없다. [OpenAI 음성 에이전트 가이드](https://developers.openai.com/api/docs/guides/voice-agents)

**GPT-Live-1**은 듣고 말하며 언제 위임할지 판단한다. 이번 버전은 Live의 `responses` 위임을 사용해 `gpt-6-luna`가 툴 인자를 고른다. 앱이 툴 결과를 반환하면 Live가 말한다. 기존 앱의 `/api/chat` 라우터를 한 번 더 호출하지 않는다. 이 측정에 붙인 `gpt-6-luna`는 선택한 백엔드 모델이고, 사용자에게 들리는 **Luna**는 모든 구성에 공통인 메이크업 아티스트 페르소나다. [OpenAI Live 위임 문서](https://developers.openai.com/api/docs/guides/live-delegation)

## Expo Go에서 비교하는 방법

네 모델을 비교할 당시 로컬 챗봇의 전사는 `gpt-live-transcribe`였다. 이번 답변 지연 개선을 적용하면서 로컬 전사 설정을 `STT_MODEL=gpt-transcribe`로 돌렸다. 앱의 실험 모드는 다음 실행 설정으로 선택한다.

1. 기존 로컬 Docker 게이트웨이와 같은 Wi-Fi에서 앱을 연다. 개발용 통합 음성 모드는 한국어 AR 대화 화면에서 마이크 버튼으로 시작한다. 한 세션에서 한 요청을 시험하며, 같은 강도로 립을 복원한 뒤 다음 회차를 시작한다.
2. 파일 전사 또는 Live 전사는 앱의 `EXPO_PUBLIC_AR_VOICE_MODEL`을 비우고 서버의 `STT_MODEL`을 각각 `gpt-transcribe`, `gpt-live-transcribe`로 지정한다. 서버 설정 변경 후 저장소 루트에서 `docker compose -f infra/compose/compose.yaml --env-file .env up -d --no-deps --build chatbot`을 실행한다.
3. Realtime 단독 또는 GPT-Live-1은 Expo 개발 환경의 `EXPO_PUBLIC_AR_VOICE_MODEL`을 각각 `gpt-realtime-2.1-mini`, `gpt-live-1`로 지정하고 Metro를 재시작한 다음 Expo Go에서 다시 로드한다. 이 경로에서는 서버가 현재 화면의 툴 목록과 오디오 전용 SDP로 세션을 만든다. 폰은 마이크 트랙만 추가한다. API 키는 서버에 둔다.
4. 얼굴 보기 상태에서 같은 명령을 말하고 `[ar-voice-timing]` 로그의 `screenMs`와 `speechMs`를 기록한다. 파일 경로는 마지막 발성 미터 샘플에서 렌더 확인·기기 TTS 시작까지, 통합 경로는 마이크 신호에서 렌더 확인 결과가 WebView로 돌아온 시각·원격 음성 시작까지 잰다. 추적 실패, 다른 액션 선택, 값이 이미 최솟값인 경우는 화면 변경 성공에서 제외하고 실패 사유를 기록한다.

PC 재현용 스크립트는 [ar_voice.py](../backend/chatbot/benchmarks/ar_voice.py)다. 저장소 루트에서 챗봇 uv 환경을 준비하고 PowerShell로 아래와 같이 실행한다. 실제 모델 요금이 발생한다.

```powershell
$env:PYTHONPATH = 'backend/chatbot'
backend/chatbot/.venv/Scripts/python.exe backend/chatbot/benchmarks/ar_voice.py command.m4a --browser 'C:\Program Files\Google\Chrome\Application\chrome.exe' --runs 3
```
