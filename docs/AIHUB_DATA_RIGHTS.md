# AI-Hub Data Rights and Storage Decision

AI-Hub 「문제성 피부 메이크업 추천 데이터」(datasetSn 71961)의 보관 위치와 이용 범위
결정입니다. `VISHUE_AIHUB_DB_Handoff_20261102` 요청서의 **0단계 산출물**입니다.

- 결정일: 2026-11-03
- 갱신일: 2026-11-22 (G5 팀원 공유 확인 추가)
- 결정 주체: 데이터 담당
- 상태: 초기 1·2단계 결정과 G5 후속 승인 범위를 구분합니다. G5 로컬 저장·조회와
  승인된 외부 처리의 현재 범위는 §1-2를 따릅니다. 공용 Supabase 적재는 보류입니다.

## 1. 결정

**AI-Hub 원본과 그 발췌는 공용 DB(Supabase)에 올리지 않습니다. 원본은 각자 국내
로컬 환경에만 둡니다.**

## 1-1. 2026-11-04 당시 결정 (이후 사용자 확인은 다음 절)

공용 Supabase 의 저장 용량이 한도에 닿아 팀이 운영 방식을 바꿨습니다. 한 달 뒤 AWS
한국 리전으로 옮길 때까지 각자 국내 로컬 PostgreSQL 을 쓰고, 적재할 때마다 덤프를
떠서 공유합니다. 팀 합의 사항입니다.

**§6 의 재검토 조건 중 "국내 리전 DB 확보" 가 충족되었습니다.** 보관 위치가 전부
국내이므로 국외 반출 쟁점이 이 데이터에는 더 적용되지 않습니다.

이에 따라 두 가지를 바꿨습니다.

- **보관 테이블을 `aihub` 전용 스키마에서 `public` 의 `aihub_` 접두사 테이블로 옮겼습니다.**
  전용 스키마를 쓴 이유는 공용 DB(도쿄)에 만들어지지 않게 하려는 것이었고, 공용 DB를
  쓰지 않으므로 그 이유가 없어졌습니다. 마이그레이션 `0014` 가 테이블을 만들고 분류 축
  2종을 넣습니다. `scripts/data/aihub/schema.sql` 과 `setup_schema.py` 는 없앴습니다.
- **팀원에게 주는 덤프에서 AI-Hub 테이블을 제외합니다.** `pg_dump --exclude-table='aihub_*'`
  한 줄로 전부 빠집니다. 접두사를 붙인 이유 중 하나가 이것입니다.

**바뀌지 않은 것:** 팀원 간에 원본 데이터를 주고받지 않습니다. 이것은 리전 조항이
아니라 제3자 제공 금지 조항에 따른 것이며 §6 에 이를 바꾸는 조건이 없습니다. 스키마는
Git 으로 공유하고 데이터는 각자 본인 AI-Hub 계정으로 받아 적재합니다.

또한 테이블 생성은 이제 alembic 이 하므로 적재 스크립트의 "로컬이 아닌 host 거부"
가드가 걸리지 않습니다. `alembic upgrade head` 가 도는 곳에는 빈 `aihub_*` 테이블이
생길 수 있고 공용 Supabase 도 그에 해당합니다. 데이터는 적재 스크립트만 넣고 그
스크립트는 로컬만 허용하므로, 빈 테이블이 생기는 것은 국외 저장에 해당하지 않습니다.

## 팀원 간 G5 데이터 공유에 대한 사용자 확인 (2026-11-22)

사용자는 G5 데이터의 팀원 간 공유를 허용한다고 확인했다. 기존 §1-1의 원본 공유
금지 기록은 당시 결정으로 보존하며, 제공기관의 팀원 간 제공 승인 여부와 제공 범위는
이 확인만으로 확정하지 않는다. 실제 덤프를 만들거나 전달하기 전에 적용되는 제공기관
조건을 확인하고, 대상·범위·보관 위치를 기록한다. 아직 덤프 전달은 수행하지 않았다.
## 1-2. G5 후속 승인 범위 기록

이 절은 작업 대화에서 사용자가 확인한 후속 승인 범위를 기록합니다. 제공기관 승인서
원본·승인기관명·승인일은 이 저장소에 제시되지 않았으므로 추정해서 기재하지 않습니다.
위의 기록일은 문서 갱신일이며 제공기관의 승인일을 뜻하지 않습니다.

- 사용자는 OpenAI 임베딩에 이어 Responses API의 원문·발췌 전송과 발췌 기반 답변
  생성까지 승인받았다고 확인했습니다(대화 확인: "이번 원문·발췌 전송까지 승인받음").
- 사용자는 G5의 문서 이용·검수를 본인이 승인하고 서비스 조회 모드에도 반영하도록
  지시했습니다. 승인된 문서의 원문·청크·벡터는 별도 로컬 DB에서 보관·검증합니다.
- 외부 API에는 승인된 G5 임베딩·상담에 필요한 입력만 보냅니다. 이 승인을 다른
  외부 서비스나 목적의 전송 허가로 확대하지 않습니다.
- 문서별 이용·검수 상태 필터는 유지합니다. 이용 범위 승인과 서비스 기능 활성화는
  별개이며, G5 기본 OFF·실행 환경별 활성화 계약을 유지합니다. 공용 클라우드 적재와
  실제 운영 배포는 별도 작업입니다.
- 원문 ZIP·발췌·본문·임베딩과 이를 포함한 실행 원본은 Git·공개 채널에 올리지 않습니다.
  소스 코드·스키마·원문을 포함하지 않는 집계와 검증 절차만 공유합니다.

§2·§5의 미합의·미확정 설명은 초기 조사 시점의 기록입니다. 현재 G5 작업의 허용
범위에는 이 후속 결정을 적용하고, 그 밖의 범위는 초기 제한을 유지합니다.

## 2. 근거

공용 Supabase 프로젝트의 리전은 `ap-northeast-1`(도쿄)입니다. 도쿄 리전에 업로드하면
데이터가 국외 서버에 저장되므로 국외 반출에 해당합니다. AI-Hub 이용정책에 다음 조항이
있습니다.

> "본 AI데이터 등의 국외 반출을 위해서는 수행기관 등 및 한국지능정보사회진흥원과
> **별도로 합의가 필요합니다.**"

> "국외에 소재하는 법인, 단체 또는 개인이 AI데이터 등을 이용하기 위해서는 수행기관 등
> 및 한국지능정보사회진흥원과 별도로 합의가 필요합니다."

금지가 아니라 사전 합의 요건이며, 초기 조사 시점에는 그 합의가 없었습니다.
G5 후속 승인에 대한 사용자 확인은 §1-2에 별도로 기록합니다.

"해외에서의 다운로드 금지"는 접속 지점에 관한 별개 조항이며 국외 저장을 허용하지
않습니다. 작업자가 모두 국내에 있고 데이터를 외부에 공개하지 않는다는 사실은 저장
위치 요건을 충족시키지 못합니다.

출처: [AI-Hub 이용정책](https://aihub.or.kr/intrcn/guid/usagepolicy.do)

## 3. 보관 위치와 접근 주체 (초기 결정 기록)

| 대상 | 위치 | 공유 |
| --- | --- | --- |
| 원본 ZIP, 압축 해제본 | 각 담당자의 국내 로컬 환경 | **공유하지 않음.** 각자 본인 AI-Hub 계정으로 내려받음 |
| 로컬 DB `public.aihub_*` 테이블 | 각 담당자의 로컬 PostgreSQL `vishue_db` | 공유하지 않음. 팀원 덤프에서 `--exclude-table='aihub_*'` 로 제외 |
| 마이그레이션, 적재·검증 스크립트 | 저장소 | Git |
| 필드 사전, 고민 13종·피부 4종 코드표 | 저장소 | Git |
| 검증 결과 집계(건수·분포·실패 유형) | 저장소 | Git |
| 원문 인용, 발췌, DOC 본문, 임베딩 | G5 로컬 보관·승인된 외부 처리 범위는 §1-2 | Git·공개 채널 제외 |

팀원 간에 원본을 전달하지 않습니다. 이용정책에 "제공 받은 AI데이터 등을 승인을 받지
않은 다른 법인, 단체 또는 개인에게 열람하게 하거나 제공, 양도, 대여, 판매하여서는
안됩니다" 라는 조항이 있어, 각자 본인 계정으로 내려받는 편이 안전합니다.

**데이터를 공유하지 않고 절차를 공유합니다.** 저장소의 스키마와 적재 스크립트가 있으면
각자 원본을 받아 같은 명령으로 같은 로컬 DB를 만들 수 있습니다. 올리브영 수집본을
서로 주고받지 않고 각자 적재하는 방식과 같습니다.

## 4. 착수 가능 여부

| 범위 | 가능 여부 |
| --- | --- |
| 0단계 저장·권한 결정 | 완료 (이 문서) |
| 1단계 원본 보존·구조화 (로컬) | **가능.** 초안이 아니라 실제 적재까지 |
| 1단계 ERD·필드 매핑·수량 대조 보고 | 가능 |
| 2단계 검증 등급 구조·조회 계약 설계 | 가능 |
| 2단계 샘플 조회 결과 | 로컬에서만 확인. 공유 시 발췌 제외 |
| 공용 DB 적재 | **보류** |
| 서비스 RAG 색인·원문 노출 | §1-2의 사용자 확인 승인 범위 적용. 문서별 필터와 별도 활성화 유지 |
| 외부 LLM API 에 원문 전달 | §1-2의 승인받았다고 확인한 OpenAI 임베딩·Responses 처리 범위 적용 |
| 원본·발췌를 Git·공개 채널에 업로드 | 금지 |

요청서가 요구한 1·2단계 산출물은 이 결정 아래에서 모두 생산할 수 있습니다. 요청
범위에 공용 DB 적재와 서비스 활성화는 포함되지 않았습니다. G5 후속 승인 범위는
해당 초기 요청서와 구분해 §1-2를 적용합니다.

## 5. 아직 확정되지 않은 쟁점

**이용 목적 범위.** 개방데이터 일반 조항에 "본 AI데이터는 인공지능 학습모델의
학습용으로만 사용할 수 있습니다" 라는 문구가 있습니다. 검색 증강 생성(RAG)이나 서비스
지식 조회가 '학습용'에 해당하는지는 이 문구만으로 확정되지 않습니다. 데이터셋 71961의
개별 이용조건을 확인해야 합니다.

**문서별 이용 제한.** `Other.zip` 의 지식문서 메타데이터에 `Purpose`(연구·학습에만
사용 가능), `Cautions`(재판매, 2차 저작물 제작 등 금지) 표기가 있습니다. 문서별 조건이
일반 조항보다 좁을 수 있어 적재 시 함께 보존하고, 우선순위는 제공기관 확인이
필요합니다.

**2차 저작물 범위.** 위 `Cautions` 때문에 파생 산출물을 공용 DB에 올리는 것도 단정할 수
없습니다. 집계 통계와 코드표는 원본 재현이 불가능하므로 범위가 다르다고 보지만, 발췌를
포함한 파생물은 보류합니다.

## 6. 이 결정이 바뀌는 조건

| 조건 | 결과 |
| --- | --- |
| 수행기관·한국지능정보사회진흥원과 국외 반출 합의 체결 | 도쿄 리전 적재 가능 |
| 국내 리전 DB 확보 | **충족(2026-11-04).** 각자 국내 로컬. §1-1 참조 |
| 데이터셋 71961 개별 이용조건에서 서비스 이용 허용 확인 | 서비스 조회 검토 착수 가능 |

국내 리전 DB는 서비스 연결을 하려면 결국 필요하므로, 필요해진 뒤가 아니라 미리
논의하는 편이 낫습니다.
