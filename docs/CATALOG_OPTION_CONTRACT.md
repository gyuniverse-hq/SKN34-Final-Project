# I-2 Catalog 상품·옵션 계약

## 조회 경로

`GET /api/catalog/categories`는 올리브영 분류 트리에서 `categoryId`, `parentId`,
`name`, `path`, `depth`를 반환합니다. `POST /api/catalog/options/search`는 요청한
카테고리와 하위 분류에 속한 카탈로그 상품의 실제 옵션을 평가합니다. 분류 코드로
검색하므로 크림 세부분류를 지정하면 같은 상위 그룹의 아이크림은 범위에서 빠집니다.

카탈로그의 `products.id`와 수집 상품의 `goods_no`를 연결한 뒤, 그 상품을 소유자로
가진 활성 옵션을 조회합니다. `optionId`를 요청하면 `productId`가 필요합니다.
상품·옵션 관계가 일치하는 후보만 검색 범위에 들어갑니다. `catalogCategory`는 기존
카탈로그의 대분류이고, `category`는 옵션이 속한 원천 분류입니다.

```json
{
  "categoryId": "1000001000100150001",
  "priceBasis": "collected_sale",
  "maxPriceKRW": 20000,
  "ingredientConditions": [
    { "ingredientName": "글리세린", "operator": "includes" },
    { "ingredientName": "향료", "operator": "excludes" }
  ],
  "offset": 0,
  "limit": 12
}
```

두 경로는 `Cache-Control: no-store`를 사용합니다. 기존 상품·룩·성분 경로는 기존
응답 계약으로 동작합니다.

## 옵션별 가격과 성분

| 응답 필드 | 의미 |
| --- | --- |
| `price.referencePriceKRW`, `referenceSource` | 서빙 카탈로그가 제공하는 상품 참고가 |
| `price.collected` | 같은 옵션의 최신 저장 스냅샷. 판매가, 정가, 수집 시각 원문, 수집 당시 품절 상태, 출처 URL, 근거 ID 포함 |
| `price.currentSalePriceKRW`, `currentStockStatus` | 동일 옵션의 현재 판매가·재고 확인 결과. 현 계약은 확인 가능한 현재 정보가 없어 각각 `null`, `unknown` |
| `ingredients.observed` | 수집 고시에서 해당 옵션에 연결된 파싱 행과 출처. 원문 전체 대신 표시명, 순번, 행 수, 수집 시각 원문, 출처 버전과 URL을 전달 |
| `ingredients.review` | #225의 선택·버전 검증 결과. 매핑과 검수 상태, 전성분 범위, 표준명 검증 상태, 날짜, 근거 ID 및 개별 조건 포함 |

기본 가격 기준은 `current_sale`입니다. 현재 판매가를 검증할 근거가 없으면 예산은
`UNKNOWN`입니다. `collected_sale`을 명시한 요청에서만 해당 옵션의 양수 수집 판매가를
`maxPriceKRW`와 비교합니다. 경계 금액을 포함하며, 금액 또는 수집 시각이 없으면
`UNKNOWN`입니다. 시각 원문에 시간대가 없으면 원문 형식을 보존합니다. 최신 저장
행의 시각·품절 값은 수집 당시의 관측입니다.

성분 판정은 #225의 동일 옵션 검수 기록, 카탈로그·고시 버전, 현행 식약처 표준명 규칙을
재사용합니다. 표시명은 관측 데이터에 남으며, 조건 판정은 검증된 출처를 사용합니다.
근거가 부분적이면 확인된 성분의 존재를 판정할 수 있습니다. 부재에는 검수된 전체
표시 목록, 유효한 순번, 전체 성분의 표준명 확인이 필요합니다. `향료`는 한 성분
표기 또는 확인된 표준명 범위의 조건입니다. 향을 내는 모든 성분의 부재와 무향 여부는
이 API의 판정 범위 밖입니다.

`ingredientEvidenceSince`를 시간대가 포함된 시각으로 지정하면 검수 시각을 우선
비교합니다. 검수 시각이 없으면 시간대가 확인된 수집 시각을 비교합니다. 날짜가 기준
이전이거나 확인되지 않으면 개별 판정은 `UNKNOWN`입니다. 근거는 확인된 시점과 버전에
대한 정보로 유지합니다. 기준 시각을 생략한 요청은 저장된 검수 버전에서 판정합니다.

## 결과 해석

개별 예산 판정은 `budgetCondition`, 개별 성분 판정은
`ingredients.review.conditions`에 있습니다. 각각 `MATCH`, `NOT_MATCH`, `UNKNOWN`,
`ERROR`와 사유, 연결된 근거 ID를 반환합니다. `requiredVerdict`는 예산과 성분
필수조건을 함께 판정합니다.

| 응답 목록·상태 | 뜻 |
| --- | --- |
| `matches` | 모든 필수조건이 `MATCH`인 옵션 |
| `excluded` | 확정 위반이 있는 옵션. 다른 조건의 `UNKNOWN`, `ERROR`도 개별 기록에 남음 |
| `unconfirmed` | 확정 위반이 없고 `UNKNOWN` 또는 `ERROR`가 있는 옵션 |
| `no_matches` | 이번 응답에서 범위를 전수 평가했고 충족·미확인·오류 옵션이 없음 |
| `search_incomplete` | 이 페이지에 충족·미확인 옵션이 없으며 전체 범위에 대한 결론은 보류 |
| `partial_failure` | 개별 성분 조회 등에 오류가 있음. 확인된 가격과 다른 조건의 결론은 응답에 보존 |
| HTTP 400 `unsupported_category` | 요청 분류 코드가 원천 분류에 없음 |
| HTTP 503 `catalog_option_lookup_failed` | 카테고리 또는 옵션 후보를 조회할 수 없음 |

`scope`에 요청, 분류, 후보 수, 이번에 평가한 수, 다음 오프셋, 전수 평가 여부 및
오류가 있는 옵션 수가 있습니다. 페이지는 최대 32개 옵션, 요청은 최대 6개 성분 조건을
평가합니다. 수집가 예산을 적용한 페이지는 유효한 수집 판매가가 낮은 옵션부터
읽습니다. 그 외에는 카탈로그 순서와 실제 ID로 정렬합니다. 페이지 사이의 카탈로그
변경 가능성은 별도 계약에 남습니다.

옵션 고시·표시 행·검수 가능한 상품과 호수·표준명은 페이지 단위로 묶어 읽습니다.
조건의 표준명 조회는 이름별로 한 번 수행하며 옵션 수에 따라 반복하지 않습니다.
옵션·성분·가격은 한 요청의 읽기 전용 PostgreSQL 스냅샷에서 확인합니다.

## 검증 범위와 I-3 연결

실제 검증은 로컬 카탈로그 스냅샷에 읽기 전용으로 접속했습니다. 크림 세부분류에는
상품 716개와 옵션 808개가 있으며, 수집 판매가가 2만 원 이하인 옵션은 183개입니다.
`oy-a000000257838`의 `-001`, `-002`, `-003` 옵션에서 수집 판매가
84,600원·40,610원·54,990원과 표시 행 수 58개·69개·0개를 각각 확인했습니다. 이
스냅샷에서 실제 옵션의 성분 승인은 확인되지 않았습니다. 금액 경계, 검수된 성분 부재,
낡은 근거, 누락된 가격, 조회 실패와 복합 조건의 우선순위는 테스트 픽스처에서 검증합니다.

실제 스냅샷의 예산과 성분 두 조건을 같은 요청으로 측정했습니다. 준비 요청 이후
각 세 번 실행했으며, 4개와 32개 페이지 모두 SQL 문 6개를 실행했습니다. 로컬 HTTP
테스트 클라이언트 기준 지연 중앙값은 각각 506ms와 673ms였고, 응답 본문은 약
18KB와 143KB였습니다. 이 측정은 미검수 스냅샷의 결과입니다. 검수된 페이지에서는
상품·호수와 표준명 조회가 추가됩니다.

로컬 스냅샷을 사용할 때는 `TEST_CATALOG_SNAPSHOT_URL`에 읽기 전용 검증 대상 DSN을
지정하고, `INGREDIENT_MAPPING_PATH`에 해당 스냅샷의 검수 산출물 경로를 지정합니다.
`backend/api`에서 다음 검증을 실행할 수 있습니다.

```powershell
uv run pytest -q -s tests/test_catalog_options.py
```

I-3는 발행된 주장 개정본, 허용 적용 범위, 검수된 식약처 성분 ID와 사전 버전을 읽고,
이 API의 동일 상품·옵션 결과에 연결합니다. 현재 가격·재고를 필수조건으로 쓰려면 동일
옵션 ID를 확인하는 현재 조회 출처와 확인 시각이 필요합니다. 전성분 부재 조건에는
옵션별 원천 고시 버전과 완전성 검수가 필요합니다. 상담이 전체 일치 없음으로 응답할
때는 검색 범위, 미확인, 조회 실패를 함께 확인합니다.
