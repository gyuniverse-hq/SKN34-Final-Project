# ADR-0011 별도 정적 관리자 웹과 관리자 API

- 상태: 로컬 구현, DB·결제 담당자 검토 대기 (2026-11-12)

## 배경

팀 내부에서 테스트 결제 주문, 상품 노출·재고, AR 숫자 평가를 확인할 도구가 필요하다. 모바일 번들과 독립적으로 로컬 검증하고 DB 담당자에게 변경을 전달한다.

## 결정

- `admin/`은 별도 Vite·React·TypeScript 정적 웹이다. 한국어 전용 내부 도구로 모바일 i18n을 사용하지 않는다. Expo 검사에서 제외하고 자체 lint·typecheck·Vitest·build로 검사한다.
- Supabase 이메일 코드 인증과 공개 URL·publishable 키만 사용한다. 서버의 기존 `require_user`로 검증하고 `staff_roles`를 확인한다. 직원 조회 의존성은 계층을 지키기 위해 `services/admin_auth_service.py`에 둔다. core는 repository를 import하지 않는다.
- 조회는 admin·viewer, 변경과 감사 로그 조회는 admin만 허용한다. 권한 지정은 운영자 잡만 수행한다. 회원 약관 기록이 먼저 있어야 한다.
- 관리자 변경과 감사 로그는 같은 트랜잭션이다. actor 탈퇴는 SET NULL, staff 역할은 CASCADE다. 보관 기간과 추가 익명화는 DB 담당자가 확정한다.
- 가격·이름·색은 카탈로그 원본이다. 시드 전면 교체 시 유지되는 상품의 관리자 상태를 보존하고 실제 제거 상품만 FK CASCADE로 삭제한다.
- 평가는 검증한 숫자 집계만 저장한다. 얼굴 픽셀·이미지 식별자·경로·해시·개별 응답을 저장하지 않는다. benchmark manifest의 집계 digest는 허용한다. 비상업 모델은 관리자 웹에 포함하지 않는다.
- 단일 사진의 MDC를 버전 평균의 합격선으로 사용하지 않는다. 동일 얼굴의 짝 차이 CI가 있으면 방향을 표시하고 없으면 판정 불가로 표시한다.
- `ADMIN_ENABLED` 기본값은 false. 로컬 검증 후 DB 담당자와 migration 및 주문 시각 컬럼 소유권을 합의한다. 공용 DB 적용·배포는 별도 단계다.

## 결과

권한과 데이터 쓰기가 백엔드에 집중되고 모바일과 독립적으로 배포할 수 있다. 개발 전용 미리보기로 DB 없이 화면을 검토할 수 있다. 정적 사이트·권한 운영이 추가된다. 외부 결제와 DB commit은 원자적이지 않으므로 멱등 키·잠금과 함께 결과 불명 시 운영자 대조가 필요하다.
