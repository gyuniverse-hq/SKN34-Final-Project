# ADR-0001 백엔드를 `api`와 `chatbot` 두 서비스로 나눈다

- 상태: 채택 (2026-10-23)

## 배경

백엔드가 맡는 기능은 카탈로그, 셰이드 추천, 회원, 챗봇입니다. 이 중 챗봇은 성격이 다릅니다.

- 응답이 수 초 걸리고, 요청마다 LLM 비용이 듭니다.
- LLM API 키와 Neo4j가 필요합니다. 다른 기능은 둘 다 필요 없습니다.
- 외부 LLM이 장애를 겪어도 쇼핑 기능(검색, 상세, 장바구니 연동)은 살아 있어야 합니다.

반대로 카탈로그, 셰이드 추천, 회원은 같은 PostgreSQL 데이터를 쓰고 함께 바뀌는 일이 많습니다.

## 결정

- `backend/api`: 카탈로그, 셰이드 추천, 회원. PostgreSQL을 소유합니다.
- `backend/chatbot`: 챗봇과 그래프 동기화. Neo4j를 소유합니다.
- 두 서비스는 각자의 uv 프로젝트, Docker 이미지, Deployment, HPA를 갖습니다.
- 공통 코드(`core/`의 에러, 로깅, 인증)는 공유 패키지로 만들지 않고 각 서비스에 둡니다. 공유 패키지를 두면 한쪽을 고칠 때 다른 쪽도 다시 배포해야 해서 독립 배포의 이점이 사라집니다.

## 결과

- 챗봇만 따로 확장하거나 제한할 수 있습니다(사용자당 분당 요청 수, HPA 최대치).
- LLM 키는 챗봇 Pod에만 주입됩니다([ADR-0006](0006-secrets-per-service.md)).
- `core/` 일부가 중복됩니다. 수정할 때는 두 서비스를 함께 고칩니다.
- 서비스를 더 쪼개지는 않습니다. 카탈로그를 별도 서비스로 빼면 서비스 간 호출과 데이터 복제가 늘어나는데, 현재 규모에서는 얻는 것이 없습니다.
