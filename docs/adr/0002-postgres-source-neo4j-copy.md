# ADR-0002 PostgreSQL이 원본이고, Neo4j는 `api` HTTP를 통해 한 방향으로 복사한다

- 상태: 채택 (2026-10-23)

## 배경

챗봇은 "건성 피부에 맞는 글로시 립" 같은 관계형 질문에 답하려고 제품, 성분, 태그, 룩 사이의 그래프가 필요합니다. 하지만 같은 데이터를 두 DB에서 수정하면 금방 어긋납니다.

## 결정

1. 카탈로그의 원본은 PostgreSQL이고, `api` 서비스만 접근합니다.
2. Neo4j는 챗봇 전용 읽기 사본입니다. `chatbot`의 `sync_graph` 잡이 `api`의 공개 계약(`GET /api/products`, `GET /api/looks`)을 읽어 채웁니다. 챗봇은 PostgreSQL 접속 정보를 갖지 않습니다.
3. 동기화는 트랜잭션 하나 안에서 전체를 교체합니다. 읽는 쪽은 이전 그래프나 새 그래프 중 하나만 봅니다.
4. 동기화는 30분마다(CronJob), 그리고 배포 직후 한 번(Helm post-install/upgrade 훅, Argo CD의 PostSync) 실행합니다.

## 결과

- 데이터베이스를 서비스별로 소유하는 원칙을 지킵니다. PostgreSQL 스키마를 바꿔도 `api` 응답 형태만 유지하면 챗봇은 영향을 받지 않습니다.
- 그래프에는 최대 30분의 지연이 생깁니다. 카탈로그는 자주 바뀌지 않아서 괜찮습니다. 즉시 반영이 필요해지면 PostgreSQL에 outbox 테이블을 두고 변경 이벤트를 소비하는 방식으로 바꿉니다.
- 카탈로그가 수만 건 이상으로 커지면 전체 교체 대신 변경분만 반영(upsert + 삭제분 정리)하도록 바꿉니다.
