# VISHUE AR 팔레트 추천 BPR 실험 계획서

2026-11-23 · 설계안

## 1. 문제 정의

VISHUE의 직접 탐색 화면은 평점과 과거 행동을 이용한 룰로 립·블러셔의 첫 추천 팔레트를 구성한다. 추천 MLOps의 기준 학습 방식은 `CatBoostClassifier`로 색상칩별 장바구니 추가 확률을 추정하고, 그 확률순으로 정렬하는 것이다. 이 실험의 기준 모델은 해당 방식을 공통 학습 데이터에서 학습한 분류기다. [AR 추천 MLOps 설계서](ar-recommendation-mlops-v1.0.md)

확률의 상대 순서를 정확히 추정하면 분류기로도 좋은 추천 순위를 만들 수 있다. 이 실험은 **같은 추천 요청에서 장바구니에 담긴 상품이 담기지 않은 상품보다 뒤에 놓이는 경우를 비교 쌍 학습으로 줄일 수 있는지** 확인한다. 서비스 관점의 목표는 장바구니에 담길 상품을 사용자가 먼저 보는 추천 상단에 배치하는 것이다.

| 관측 행동 | 선호 신호 | 실험에서의 의미 |
| --- | --- | --- |
| 장바구니 추가 | 매우 강한 긍정 | 분류의 양성 라벨이자 순위 비교 쌍에서 앞설 후보 |
| 클릭 후 AR 시착만 | 보조 긍정 | 장바구니 미추가로 집계하며, AR을 쓰는 실험에서는 무반응보다 앞설 후보 |
| 노출 후 무반응 | 약한 상대 신호 | 같은 요청에서 더 강한 반응이 있었던 후보와 비교할 수 있는 노출 |
| 미노출 | 판단 보류 | 해당 요청에서 선호를 판단할 행동 관측이 없는 후보 |

## 2. 가설

- **H1.** 장바구니 추가 상품과 같은 요청의 노출된 미추가 상품을 쌍으로 학습하면, 분류기의 확률순 정렬보다 순위 역전율이 낮아지고 장바구니 기준 NDCG@K가 높아질 것이다.
- **보조 가설.** 장바구니 비교 쌍에 `AR 시착만 > 노출 후 무반응` 쌍을 더하면 장바구니 기준 NDCG@K가 추가로 개선될 수 있다.

## 3. 데이터와 비교 쌍

### 목업 데이터

기존 룰 기반 사용자 데이터와 추천 흐름을 활용해 **첫 팔레트 색상칩 노출 1,000행**을 만든다. 행의 단위는 노출 한 건이고, 추천 요청 수와 고유 사용자 수는 별도로 기록한다. 사용자별 색·제형 선호와 후보 적합도를 행동 확률에 반영한다. 추천 상위 칩의 무반응, 뒤쪽 칩의 클릭·담기, 클릭만 한 경우, 시착만 한 경우가 모두 발생할 수 있게 한다. 가상 사용자의 특성, 난수 시드와 행동 생성 조건을 기록한다. [기존 목업 구성 사례](ar-recommendation-mlops-mock-test-report.md)

### 공통 입력과 라벨

- **요청과 노출.** `request_id`로 추천을 묶고 `impression_id`로 색상칩의 실제 노출과 연결된 행동을 식별한다. 학습 쌍과 평가 후보는 화면 노출이 기록된 칩으로 한정한다. [AR 행동 이벤트 명세](AR_SPEC.md#6-14-행동-이벤트-기록-f15)
- **입력.** 세 모델은 기존 MLOps에서 정의한 추천 시점 피처를 공통으로 받는다. 추천 이후의 행동은 라벨과 비교 쌍 구성에 사용한다. [기존 MLOps 입력 정의](ar-recommendation-mlops-v1.0.md)
- **장바구니 라벨.** 관찰이 마감된 노출에서 같은 회원·세션·노출에 귀속된 `cart_add`가 있으면 `added_to_cart=1`, 없으면 `0`으로 둔다. 실데이터는 기존 추출 방식의 노출 후 24시간 관찰과 추가 24시간 수신 대기를 따른다. [MLOps 데이터 정의](ar-recommendation-mlops-v1.0.md)
- **기본 비교 쌍.** 같은 요청 안에서 장바구니에 담긴 칩을 `i`, 노출됐지만 장바구니에 담기지 않은 칩을 `j`로 둔다. 하나의 요청에 담긴 칩과 미담기 칩이 모두 있을 때 `i > j`를 구성한다. 분류기는 같은 노출 데이터의 이진 라벨을 사용한다.
- **AR 보조 쌍.** 목업에서는 장바구니 추가 없이 AR 시착한 칩을, 클릭·시착·담기가 모두 없던 칩보다 앞에 둔다. 현행 AR 행동 테이블에 기록되는 유형은 `try_on`과 `cart_add`다. 이 로그로 AR 쌍을 평가할 때는 비교 신호를 **시착·담기 미관측**으로 명시한다. [AR 행동 테이블](../backend/api/app/models/ar_personalization.py)

### 데이터 분할

오래된 추천 요청부터 기존 MLOps의 시간순 **70:15:15** 학습·검증·테스트 분할을 적용한다. 요청의 후보는 한 구간에 두고, 세션이 경계에 걸치면 기존 분할 규칙에 따라 앞 구간의 해당 세션 행을 제외한다. 학습용 비교 쌍은 분할 뒤에 생성한다. 모델 설정과 최종 후보는 검증셋에서 고르고, 모든 최종 비교는 같은 미사용 테스트 요청과 노출 후보에서 수행한다. [MLOps 분할 및 평가 방식](ar-recommendation-mlops-v1.0.md)

## 4. 실험 설계

| 실험군 | 모델 | 학습과 정렬 |
| --- | --- | --- |
| **A** | 기준 `CatBoostClassifier(Logloss)` | 기존 MLOps의 클래스 가중치 설정으로 노출 행의 장바구니 추가 여부를 학습하고 예측 확률 내림차순으로 정렬한다. |
| **B** | `BPR-OPT`와 `LearnBPR`을 적용한 모델 | 공통 입력 피처를 받는 점수 모델에 BPR-OPT를 적용한다. 기본 비교 쌍으로 만든 triplet을 균등 복원 추출하고 SGD로 학습한 점수로 정렬한다. |
| **C** | `CatBoostRanker(PairLogit)` | B와 같은 기본 비교 쌍을 요청 그룹별로 전달하고, 부스팅으로 학습한 점수로 정렬한다. |

`BPR-OPT`는 두 상품 점수의 차이에 로그 시그모이드를 적용하는 순위 학습 목적함수이며 규제 항을 포함한다. `LearnBPR`은 그 목적함수를 학습하기 위한 복원 추출 기반 SGD 절차다. `PairLogit`은 CatBoost 안에서 같은 형태의 비교 쌍 손실을 사용하는 순위 학습 설정이다. [BPR 원 논문 §4](https://arxiv.org/pdf/1205.2618) · [CatBoost PairLogit](https://catboost.ai/docs/en/concepts/loss-functions-ranking#pairlogit)

1. **A와 B를 비교**해 기준 확률 정렬 대비 LearnBPR 방식의 순위 개선을 측정한다.
2. **B와 C를 비교**해 같은 비교 쌍을 사용하는 두 순위 구현의 성능을 확인한다. 이 차이에는 점수 모델 구조와 최적화 방식의 영향이 포함된다. **A와 C**도 같은 결과표에서 비교해 CatBoost 계열에서 분류 학습과 순위 학습의 차이를 확인한다.
3. **AR 신호를 추가**할 때는 검증셋에서 선정한 순위 모델의 기본 버전과 보조 쌍을 추가한 버전을 비교한다. 두 버전 모두 장바구니를 정답으로 평가한다.

## 5. 평가지표

| 지표 | 계산과 해석 |
| --- | --- |
| **장바구니 NDCG@K** | 도입 후보를 비교하는 오프라인 주지표다. 장바구니 추가를 관련도 1로 두고, 상위 K개 안에서 더 앞에 배치된 정답에 더 큰 점수를 준다. 담기가 있는 요청에서 계산해 요청 단위로 평균한다. 첫 팔레트는 최대 3개 추천 칩을 표시하므로 이 실험의 기본 K는 **3**이다. |
| **논문식 사용자별 AUC** | 각 사용자의 테스트 요청에서 장바구니 칩의 점수가 노출된 미담기 칩보다 엄격히 높은 쌍의 비율을 구한 뒤, 유효 쌍이 있는 사용자를 동일 가중치로 평균한다. 동점에는 0을 부여한다. 논문의 계산식을 사용하고 비교 후보와 시간 분할은 VISHUE의 노출 로그에 맞춘다. |
| **순위 역전율과 동점률** | AUC와 같은 쌍과 집계 방식을 사용한다. 장바구니 칩의 점수가 더 낮은 쌍의 비율이 역전율이고, 두 칩의 점수가 같은 쌍의 비율이 동점률이다. |
| **1위 적중률** | 장바구니에 담긴 칩을 하나 이상 포함한 요청에서, 맨 위 칩이 장바구니에 담긴 비율이다. 기존 오프라인 평가와 함께 확인하고, 후보 풀이 K보다 넓은 경우에는 Recall@K도 함께 산출한다. |

예를 들어 후보가 3개이고 그중 하나를 담은 요청이 두 건 있다고 하자. 담긴 칩을 각각 **1위·3위**에 놓은 모델과 **2위·2위**에 놓은 모델의 쌍 비교 AUC는 둘 다 0.50이다. NDCG@3는 각각 0.75와 약 0.63이므로 두 모델이 추천 맨 위를 활용하는 차이를 보여 준다. [BPR 원 논문 §6.2](https://arxiv.org/pdf/1205.2618) · [CatBoost NDCG 정의](https://catboost.ai/docs/en/concepts/loss-functions-ranking#ndcg)

지표와 함께 평가 요청 수, 고유 사용자 수, 장바구니 양성 노출 수, 유효 비교 쌍 수를 기록한다. 모델이 같은 점수를 내는 경우 순서가 필요한 지표에는 공통 동점 규칙을 적용한다.

## 6. 결과 판정

- **목업 검증.** 세 모델의 입력, 학습, 순위 생성, 지표 계산이 이어지는지 확인한다. 점수 차이는 목업의 행동 생성 조건에서 해석한다.
- **실데이터 검증.** 최종 순위 모델과 기준 분류기를 동일한 미사용 테스트 요청에서 직접 비교한다. 장바구니 NDCG@K 개선을 우선 보고, 사용자별 AUC와 순위 역전율로 H1을 확인한다. 결과는 기록된 노출 후보 안에서의 재정렬 성능으로 해석한다.
- **운영 전환.** 실데이터 오프라인 결과를 바탕으로 검증할 후보를 고른다. 운영 도입은 기존 MLOps의 온라인 A/B에서 전체 추천 세션 대비 구매율을 기준으로 판단한다. [운영 A/B 판정 기준](ar-recommendation-mlops-v1.0.md#5-실제-사용자-ab-테스트와-전환)

## 7. 기본 학습 후보와 실험 자료

기본 MLOps 학습은 `CatBoostRanker(PairLogit) + RandomSearch` 후보를 생성한다. 전체 후보를 복원한 목업의 순환 없는 조건에서 랭커 NDCG@3는 0.2258, 분류기는 0.2241이었다. 기존 노출 후보 기준으로는 분류기가 0.8390, 랭커가 0.8237이었다. 실데이터에서 오프라인 기준을 통과한 번들을 첫 A/B의 B에 사용하고, 추천 세션 대비 구매율로 운영 승격을 결정한다. [학습 및 운영 흐름](ar-recommendation-mlops-v1.0.md#4-첫-학습과-오프라인-비교)

공통 목업 노출 1,000건과 시간순 분할은 [목업 생성 스크립트](../ml/scripts/run_ar_palette_bpr.py)로 재현한다. 당시 비교 수치와 그래프는 실행한 작업공간의 `ml/runs/ar-palette-*-20261123/`에 보관했다. 재생성한 데이터셋은 당시 `results.json`의 `dataset_sha256`으로 대조할 수 있다.

저장소 루트에서 다음 순서대로 실행하면 각 비교의 결과 JSON과 순환 실험 그래프를 새 폴더에 만든다.

```powershell
uv run --project backend/api --group recommendation python -B -m ml.scripts.run_ar_palette_bpr ml/runs/ar-palette-bpr-replay
uv run --project backend/api --group recommendation python -B -m ml.scripts.run_ar_palette_bpr_mf ml/runs/ar-palette-bpr-replay ml/runs/ar-palette-bpr-mf-replay
uv run --project backend/api --group recommendation python -B -m ml.scripts.run_ar_palette_search_comparison ml/runs/ar-palette-bpr-replay ml/runs/ar-palette-bpr-mf-replay ml/runs/ar-palette-search-replay
uv run --project backend/api --group recommendation python -B -m ml.scripts.run_ar_palette_rotation ml/runs/ar-palette-bpr-replay ml/runs/ar-palette-search-replay ml/runs/ar-palette-rotation-replay
```
