# VISHUE 일반 챗봇 v0.3 — 상품 슬라이드 1차 구현·평가 기준선

> 기준: `develop` 8ef8b0fe6ed9aa838cf26b020c9b7b4982aa17b8 (2026-11-09 확인)
> 범위: 일반 챗봇의 상품 표시 및 명시적인 제품 선택. 스타일/성분 검수 정책, AR 렌더러, 홈 탭은 변경하지 않는다.
> 이번 문서는 실행 결과 리포트가 아니라 **실행해야 할 평가 계약**이다. 미실행 항목을 통과로 표기하지 않는다.

## 사용자 경험 결정

1. 상품 후보는 채팅 말풍선 바로 아래에서 가로 스크롤한다.
2. 좌우 스와이프는 **보는 카드**만 변경한다. `BeautyChatContext.selectedProductId`를 바꾸지 않는다.
3. `이 제품 선택`은 실제 로드된 후보 + 서버 세션이 존재할 때만 표시/처리한다. 선택 후 후속 질문을 위한 `screenContext.productId`를 보낸다.
4. 선택한 제품의 호수가 지정되지 않았다면 **호수를 만들어내지 않는다**. 성분 확인 요청은 기존 백엔드의 선택/근거 검증을 거친다.
5. 서버 `candidateIds` 순서와 응답의 후보 번호는 보존한다. 상품 조회 일부 실패 시 응답에 포함된 제품의 원래 자리를 `불러올 수 없음`으로 표시한다. 오래된 다른 후보로 대체하지 않는다.
6. 입력창 위의 빠른 질문은 **실제 선택과 유효 세션이 있을 때만** 활성화한다.
7. 근거가 부족한 성분에 대해 `UNKNOWN`을 `미포함`으로 바꾸지 않는다.

## 기존 구조 대비

- `components/chat/ChatProducts.tsx`: 기존 카드 내용을 재사용하고, 바깥 배치를 캐러셀로 구성. 페이지 이동 버튼·진행 번호·선택 버튼 추가. `onSelectShade`, `onOpenProduct`, `onOpenAr`, 정가와 조건·근거 상태 표현을 유지.
- `app/chat.tsx`: 기존 `ChatSessionRef` 및 세션 버전·응답 지연 보호 코드를 변경하지 않고, 명시적 선택과 빠른 질문 연결만 추가.
- `hooks/useChat.ts`: 기존 요청 경로 및 `requestType` 분기 유지. 자유 질문 자동 라우팅은 별도 백엔드 변경 전까지 제공하지 않음.
- `lib/i18n/{en,ko,ja,zh}.ts`: 새 조작 문구 번역.

## 4EVR0 연구에서 채택한 평가 원칙

참고: [4EVR0-Server/eval](https://github.com/4EVR0/4EVR0-Server/tree/main/eval), [멀티턴 평가](https://github.com/4EVR0/4EVR0-Server/blob/main/eval/run_multiturn_eval.py), [품질 게이트](https://github.com/4EVR0/4EVR0-Server/blob/main/eval/gate_config.json).

- **결정론적 검사 우선**: 카드 순서/호수 참조/근거 누락/세션 오염은 LLM Judge의 주관적 점수 대신 기계 규칙으로 검증한다.
- **평가 실행 격리**: 서로 다른 사용자·평가 케이스의 추천 후보와 세션을 섞지 않는다.
- **제품 관련 주장의 근거 검증**: 추천 이유는 Catalog 원천으로 확인할 수 있는 내용만 확정적으로 표시한다.
- **비교 실험 전 기준선**: GraphRAG/SSE/프롬프트 변경은 이전과 같은 사례의 검색 결과 정확도·응답지연·실패율을 비교한 뒤 채택한다.
- **계측 분리**: 카드가 처음 표시될 때까지의 시간과 전체 LLM 응답 완료 시간을 분리한다. 현재 React Native API는 일괄 응답이므로 구조데이터 SSE 선행표시는 이번 범위 밖.

## 테스트 계약

| ID | 검증 시나리오 | 필수 판정 |
|---|---|---|
| C-01 | 1번→2번 스와이프 | 서버 선택 제품 **불변** |
| C-02 | 2번 명시적 선택 후 후속 질문 | 서버 후보 ID, 선택 ID와 `screenContext` 일치 |
| C-03 | 2번 보고 있다가 3번으로 이동 | 이미 선택된 2번 유지 |
| C-04 | 1번 조회 실패, 2번 조회 성공 | 2번을 1번으로 재번호 매기지 않음 |
| C-05 | 정확한 호수 미확인 | 임의 `shadeId` 생성 없음 |
| C-06 | 성분 검수 부족/부분 목록 | `UNKNOWN`, 무향료 확정 금지 |
| C-07 | 세션 만료·권한 변경·409/410 | 오래된 후보로 후속 조회하지 않음 |
| C-08 | 실패 재시도 | 동일 requestId·원래 스냅샷 유지 |
| C-09 | 계정 변경 | 이전 사용자의 선택 및 세션 참조 제거 |
| C-10 | 가로 스크롤·페이지 이동 | 기존 상세/AR/호수 터치 동작 유지 |

## 평가 데이터 단계

1. 기존 Jest(`chatProducts.test.ts`, `chatScreen.test.ts`) + TypeScript 검사 실행.
2. 기존 상담 멀티턴/Redis 관련 pytest·API 회귀 검사 실행.
3. 실제 iPhone에서 카드 스와이프와 세션 상태 확인.
4. 검수된 359개 평가 사례에서 사용자 질문/상태 전이 라벨을 분리해 동일 세션과 케이스 격리 A/B 실행.
5. 정답 없는 예시나 단순 합성 발화를 실제 사용자 빈도로 간주하지 않음.

## 합격 판정 규칙

코드 변경만으로 '완료'라고 판단하지 않는다. 최소한 PR CI의 타입 검사·Jest 회귀와 기존 API 검증, Expo 실기기 확인을 구분해 보고한다. 테스트 실행 결과가 없는 항목은 **미검증**이다.

## UI 2차 구현: 비교 바텀시트·첫 화면

- `ProductCompareSheet.tsx`: 채팅 내부에서 모든 로드된 후보를 가로 열로 비교. 제품명·가격·등록 제형·호수 수·주요 성분 자료 유무만 표시. 성분 부재/피부 적합성/실제 발색을 추정하지 않음.
- `ChatProducts.tsx`: 비교 화면 열기 버튼. 비교 화면 열고 닫아도 기존 후보 ID, 채팅, 명시적 선택은 바뀌지 않아야 함.
- `app/chat.tsx`: 기존 큰 3분류 카드를 사용자 고민 예시 4개로 교체. 예시 탭은 카테고리와 입력 문장을 함께 설정하고 **자동 전송하지 않음**. 자유 입력은 기존 카테고리 분기를 사용하며 자동 의도 분류는 미구현.
- `__tests__/chatProducts.test.ts`: 비교 모달 진입/닫기, 서버 후보 순서 유지, 선택 의도 없을 때 불변성 확인.
- `__tests__/chatScreen.test.ts`: 첫 화면 질문 탭의 입력/카테고리 동기화, 전송 전 호출 없음, 스타일 선택 분기 검증.

### UI 후속 검증

- 현재 코드는 비교 대상이 로드된 상품만 표시. 서버 응답 ID 일부가 누락됐을 때의 안내 문구와 레이아웃 실기기 확인 필요.
- 여러 회차의 카드가 채팅 안에 유지되는 경우, 비교 화면이 현재 회차별 후보를 올바르게 보여 주는지 확인.
- 실제 상품 데이터에는 피부 적합성, 실제 발색·제형 감각에 대한 독립적인 신뢰도 근거가 없을 수 있음. 그런 주장은 UI에 추가하지 않음.
- 드래프트 PR은 개발 중 검증용으로만 유지하며 사용자의 명시적 승인 전 병합하지 않음.
