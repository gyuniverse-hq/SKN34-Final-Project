E1~E7은 난이도 순위나 자동 승급 단계가 아니다. 각 환경에 독립 PASS/FAIL/BLOCKED/NOT_RUN/NOT_APPLICABLE를 부여한다. G1은 적어도 E0, E1, E3, E5 및 기존 AR/ACK 계약의 적절한 회귀 증빙이 필요하다. 단, 모델을 호출하지 않는 G1-REG-03(ACK 단독)은 E0 필수이며 E3 적용 대상에서 제외한다. E3 실모델 증빙은 모델을 실제로 호출하는 해당 사례에서 수집한다. 팀 공동 G9는 E7이 별도로 필요하다. iOS 테스트가 불가능하면 Android 통과를 iOS로 외삽하지 않는다.

## 3. 실행 결과 레코드

`runId, caseId, caseRevision, runStartedAt, gitCommit, branch, evaluatorVersion, environmentId, envFingerprint, sourceSnapshotId, graphGeneration, indexVersion, revocationEpoch, embeddingModelVersion, llmProvider, llmModelId, llmModelVersion, promptVersion, toolRegistryVersion, rightsPolicyVersion, testDataKind, isMock, isSynthetic, toolTraceRef, requestId, threadId, resultSetId, latencyMs, tokenUsage, estimatedCost, assertionResults, adjudicationStatus, reviewer, evidenceArtifactRefs, errorCode, skipReason`.

- 환경 식별자는 도메인·토큰·DB 접속 문자열을 기록하지 않고 해시/허용된 식별자로 보존.
- `isMock`, `isSynthetic`가 true면 결과가 실제 모델·데이터 평가 합격으로 승격되지 않음.
- 테스트가 건너뛰어지면 `SKIPPED`와 `skipReason`을 기록. 필수 검증의 skip은 PASS 금지.
- 동일 케이스의 E0 Mock PASS, E3 실제 LLM FAIL은 서로 독립 기록. 집계는 각 환경/모델/버전/데이터/실행일로 분리.
- 오류를 `UNKNOWN`으로 합치지 않음. 권리 차단, 데이터 미확인, 네트워크 실패, 근거 부족을 구별.

## 4. 평가 사례 및 정답 관리

- 기존 `docs/ai-alignment/VALIDATION.json`: 359개 검수 대상(승인 후보 25, 정책 보류 10, 미검수 324), **Gold 승인 0건**, Mock 1-A 케이스 11, 과거 실행 기록. 359를 전부 골든셋으로 부르지 않음.
- 기존 한국어 1차 정책 `VAI-D-013`: 기능별 `ko` 우선, `TC-22-I18N-FOLLOWUP`은 이후 en/ja/zh 별도 평가.
- 12개 시나리오는 제품 기능의 커버리지 기준이며 질문 화이트리스트 아님. 비정형 자유 질문과 목표 전환·장문/신조어/오타도 변형 추가.
- Gold 승인 기준: 실제 정본/권한/근거 검수 확인, 시나리오 기대 결과와 필수·금지 단정 명확, 리뷰어·기준일·데이터/정답 버전 기록, 합성·실데이터 구분. 정답 ID가 스냅샷마다 달라지면 기대 응답을 검증된 버전 단위로 고정하고 새 버전에서 재검수.
- 분할: 질문 동일/유사 표현은 같은 그룹, 동일 사용자·상품/호수/영상/출처 문서/주장 클러스터의 과도한 분포 누출 방지. RAG의 ‘골든 QA’를 색인에 넣어 검색해서 정답을 맞춘 것처럼 평가하지 않음.

## 5. AIHub 71961 RAG 평가 세부 분할

- 데이터 담당 기존 보고: 학습 QA 8,031/검증 QA 1,000, **양쪽에 걸치는 대상자 339명**, 검증 QA 중 **403/1,000**건이 교차 대상자에 속함. 문서/QA 콘텐츠 중복을 추가로 검사해야 함.
- `splitGroupKey`에는 원문 대상자 ID를 직접 내보내지 말고 로컬 평가용 안정적 익명 키를 사용. 같은 대상자, 동일/유사 QA/문서/claim 등은 같은 split으로 묶도록 클러스터 분리.
- **검색 평가**: 질의/정답 근거 식별자는 사람이 확인한 문서·주장 단위. 해당 평가 QA 자체·동일 질문 패러프레이즈 문서를 ‘retrieval corpus’에 넣으면 자기검색이 되어 왜곡될 수 있으므로 누출 측정과 분리 평가를 수행.
- **근거 검증**: direct/indirect/insufficient/contradicting 및 출처 없음·권리 미확정·철회·동일 주장 버전 불일치·메타데이터 누락·부분 인용·근거와 답변의 상충을 별도 사례로 평가.
- **권한 규칙**: 로컬 데이터 사용·청크/임베딩/로컬 모델 전달·외부 LLM 제공·공용 발행에 각각 정책/권리 상태를 기록. 허용되지 않은 원문은 검색 색인·모델/평가 로그/서비스 응답에 넣지 않는다. 파이프라인 개발은 합성/권리 확인 자료를 병행하여 추진한다.

## 6. 4-1 완료 기준(설계 L2, 실행 미확인)

1. E0~E7의 독립 PASS/FAIL/BLOCKED/N/A와 증거 범위 정의.
2. 케이스/실행 데이터 스키마 및 민감 원문 비공개 저장·익명 집계 규칙 정의.
3. 정답 검수/Gold 승격, Mock/실모델 구분, 권리/발행 상태 및 환경별 데이터 버전 추적 방식 정의.
4. AIHub 대상자/동일·유사 문서/claim 누출 방지와 로컬/서비스 권한 Gate 명문화.
5. G1 첫 수직 PR 필수 환경을 E0/E1/E3/E5+AR 회귀로 명시, E6/E7은 관련 기능과 담당자의 공동 범위로 인계.
6. 4-2 G1 구체 테스트와 4-3 G2~G9 지표/threshold/병합 Gate에 같은 스키마를 사용.

**현재 상태:** 4단계 L2 논리 설계 종료로 편입. 이 문서 자체는 평가 실행 로그나 실제 Gold 승인 결과가 아니다.
