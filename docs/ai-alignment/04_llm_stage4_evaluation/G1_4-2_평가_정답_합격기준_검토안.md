## 1. 평가 설계 결론

1. G1은 **자연어 자유 상담 + 실제 상품 검색 수직 경로**를 함께 평가한다. 일반 지식 질문에 Catalog 검색을 강제하지 않는다.
2. G1의 합격은 `LangGraph 실제 실행 → (필요 시) Catalog Tool → 실제 Catalog API → 검증된 상품 ID/호수/근거 → ChatResponse → 앱 카드` 전체 증빙이다. 모델 답변에 상품 이름이 있다는 사실은 Tool 실행 증거가 아니다.
3. 가격·제형·성분이 질문에 포함되어도 G1은 **검증됨/미확인**으로 구분한다. G3의 검수된 전성분 판단과 G4의 옵션별 완전 교집합/현재가 확정은 요구하지 않는다.
4. 기존 일반 chat·beauty_consultation·AR 명령·ACK·Redis session의 **실제 계약별 회귀**는 필수. 특히 일반 `chat`의 requestId가 기존 코드에서 제거되는 부분을 G2 멱등성 완성으로 오인하지 않는다.
5. 실제 LLM 사용(E3), Catalog/DB(E1), 앱 카드(E5), E0 Mock 테스트는 각기 독립한 **실행 증빙**을 남긴다. E6/E7은 해당 AR/공동 작업의 게이트이며 G1 새 기능 자체에 전부 강제하지 않는다.

## 2. 사례 집합의 의미

- 전체 **47개 검증 행동의 검토 후보**: conversation 12개, catalog 14개, fault 10개, suite 11개. 수량은 목표가 아니며 실제 실패유형 커버리지/중복 점검 후 늘리거나 줄인다.
- 기존 G1-01~09는 이름과 시나리오를 보존·보완했다. 기존 G1-10(잘못된 JSON/ID 불일치)은 ERR-03/ERR-04로 분할, G1-11은 RUN-01 별도 실모델 실행, G1-12는 REG-01~07 별도 회귀에 매핑.
- 새로운 자유질문, 초보 설명, 모호성, 정보/추천 분리, 동의어/오타, 미지원 기능 정직성, Tool 오염/권한, 상품-셰이드 정합성 및 UI 0건/재시도를 추가했다.
- **시험 질문은 whitelist가 아니다.** 같은 의도를 가지는 말투·띄어쓰기·오타·장문 변형을 모델 미공개 홀드아웃(holdout)으로 추가한다.

## 3. 정답을 정의하는 네 층

- `expected.factsOrBehaviors`: **사실과 행동**. 어떤 사실을 확인하고 어떤 행동/명확화/도구 선택을 해야 하는지.
- `expected.forbiddenClaims`: **절대 말하면 안 되는 주장**. 시점 불명 가격을 현재가로, 미검수 전성분을 무향료로, 화면 실행 안 한 AR을 적용 완료로 단정하면 차단.
- `expected.requiredTools/requiredHttpPaths`: **호출·인자·출처**. 제품 확인이 필요한 경우 실제 Tool/HTTP trace. 단순 자유 안내는 도구 불필요.
- `assertions.humanReview`: **대화 품질**. 문장 일치/키워드 포함이 정답 아님. 자연스러움·유용성·명확화 적합성은 사용자 리뷰 점수와 근거를 받는다.

## 4. 자동 채점 가능 범위와 한계

| 구분 | 자동 결정 | 사람 판단 |
| --- | --- | --- |
| 제품 ID/호수 존재·귀속 | 해당 소스 스냅샷에 대한 API 조회로 가능 | 원본 적재/검수 의미 확인 |
| 실 LLM·Tool·HTTP 실행/인자 | 모델/Tool/HTTP trace로 확인 가능 | 올바른 질문 해석인지 필요하면 검토 |
| JSON 스키마/HTTP 오류/중복 ID | 자동 가능 | 보통 불필요 |
| 가격·성분 확인 상태 | 구조화된 근거/시각·검증 필드 기반 자동 가능 | **자유 문장 단정·암묵적 오도**는 사람 검토 필요 |
| 한국어 설명의 유용성/정중함/적절한 질문 | 제한적 자동 지표/LLM 심사 보조 | **사람 평가가 기준** |

**환경별 판정:** 각 사례의 `assertions.automaticByEnvironment`를 사용한다. 예를 들어 UI 카드 검사는 E5, 실제 모델 실행은 E3에서만 판정하며 E0에서는 해당 검사 결과를 `NOT_APPLICABLE`로 기록한다. 실행 중 누락된 필수 E5/E3가 있다면 G1 전체 PASS로 합산할 수 없다.

**중요:** `g1_predicate_registry_PROPOSED.json`은 체크 함수 명세 목록이지 구현된 채점기가 아니다. Codex가 실제 실행기에서 등록되지 않은 predicate를 만나면 PASS가 아니라 NOT_RUN으로 처리하도록 한다. 추적 로그가 없는데 답변에 ‘검색했다’는 표현만으로 실제 Tool 호출을 인정하지 않는다.

## 5. 필수 병합 차단 게이트 (추천)

- E0 관련 계약·회귀 필수 항목 실패 또는 누락, E1 실제 상품/호수 불일치, E3 실제 LLM·Tool/HTTP trace 누락, E5 실제 앱 상품 카드/상태 검증 누락은 **G1 PR 병합 차단**.
- 없는 상품·셰이드를 반환, 검증되지 않은 현재가/무향료/안전성 확정, 기존 AR 명령·ACK 회귀, 외부/비허가 데이터 전송, 타인 세션 접근은 발생 건수가 1건이어도 **차단**.
- 중복 requestId는 기존 요청 타입에 맞는 계약을 검사한다. `beauty_consultation` 재전송/충돌/세션 소유권, `chat` requestId의 기존 무시 동작을 명확히 구분한다. 모든 chat의 전역 멱등 보장을 G1에 요구하거나 현재 구현되었다고 주장하지 않는다.
- LLM 응답 자연스러움·검색 적중률·지연·토큰·비용은 **초기 기준선 측정 후 권장 임계치**를 설정한다. 예: 별도 최소 평가표본을 확보한 뒤 심각한 오류를 차단하고 0~4점의 사용자 평가 평균/분포를 보고 개선 목표를 정한다. **달성 수치는 현재 없음**.

## 6. 사람 평가표(0~4점 척도, 제안)

| 점수 | 설명 |
| --- | --- |
| 0 | 핵심 목적 완전히 불이행/위험·허위 사실(차단 원인) |
| 1 | 핵심 의도 오해, 대부분 도움이 되지 않음 |
| 2 | 일부 맞지만 이해·명확성/구체성 부족 |
| 3 | 목적에 맞고 대체로 자연스럽고 유용 |
| 4 | 목적 정확 이해, 명확·실행 가능하며 불확실성도 적절히 표현 |

평가 항목은 `factualAccuracy`, `intentUnderstanding`, `clarity`, `naturalness`, `uncertaintyHonesty`. **인간 평가 점수가 높아도 사실/권한/AR 안전 차단 실패를 상쇄하지 못함.** 사용자 직접 평가용 CSV는 비어 있는 점수 템플릿으로 제공한다.

## 7. Codex 실행 설계

1. G1 기능을 실제 구현하는 **별도 PR**에서, 사례 JSONL을 읽고 현재 develop의 `ChatRequest/ChatResponse`와 E0 Mock/실제 E1+를 나누는 평가기를 작성한다.
2. 평가 전에 fixture binding의 `${FIXTURE.productId}`, `${FIXTURE.shadeId}`, `${FIXTURE.foreignShadeId}`를 **실제 Catalog 스냅샷에서 검증된 ID만** 연결한다. 미확정 fixture는 `BLOCKED_DATA`, 성공으로 세지 않는다.
3. `assertions.automatic`의 predicate를 runner 함수에 매핑한다. **구현되지 않은 함수/실행되지 않은 환경은 PASS가 아닌 `NOT_RUN`**.
4. E3는 실모델 ID·버전·실제 호출·Tool/span 및 HTTP 연결, 모델 비용/지연과 재실행 설정. E0의 `FakeLlm`, `MockTransport`, 합성 데이터와 분리한다.
5. E5는 같은 실제 응답의 제품·호수 ID와 UI 카드/상세 이동/조건 라벨/오류·재시도를 실제 화면에서 검증한다. 리렌더/늦은 응답·화면 이동도 확인.
6. 필수 증빙은 `runId,caseId,caseRevision,environmentId,gitCommit,sourceSnapshotId,modelId,promptVersion,toolRegistryVersion,isMock,isSynthetic,requestId,traceRef,assertions,coverage,errors,latencyMs,estimatedCost`. **요청/답변에 개인정보·AIHub 권리 미확정 원문을 로그로 내보내지 않는다.**
7. 같은 합격셋과 회귀셋을 각 후속 G PR에서 재실행하여 `develop` 병합 전후 비교. G1 성공을 G2~G9의 전체 능력 검증으로 확대하지 않는다.

## 8. 결정이 필요한 검토 포인트

- 자유 상담에서 **기본 일반 지식의 설명**은 G1에 포함하고, 권리·검수·인용이 필요한 전문 지식 RAG는 G5로 유지하는 경계.
- 자연어 한 번의 질문에서 **간단한 설명 + 상품 검색**은 G1에서 허용하고, 여러 Tool/Agent 종속 계획은 G8로 유지하는 경계.
- 한국어 **최소 사용자 평가 표본 수/사람 평가 임계치**는 실제 기준선 측정 이후 채택. 사람 평가 0~4점과 자동 위반 사항의 분리.
- 기존 UI의 `priceKRW` 기반 조건 일치 표시가 검증된 현재가처럼 오해되지 않도록 E5에서 문구/표시를 필수 검증. 화면 변경 소유권·리뷰는 5단계 팀 협의.

### 11. 대표 사례 상세 평가 계약: G1-CAT-02

- 입력: `requestType=beauty_consultation`, `locale=ko`, 예산 20,000원·촉촉한 립, 최초 턴, 이전 채팅 맥락 없음.
- 사전 조건: 실제 Catalog 스냅샷 및 해당 시점의 ID/셰이드·가격 참고값 보존. 실제 E1과 E3의 DB·서비스/모델 버전 별도 기록.
- 기대: LangGraph 최소 Supervisor → `catalog.search_products` → 실제 `GET /api/products` → 검증된 상품 ID → `ChatResponse` 및 E5 상품 카드.
- Tool 인자: 내부 의도 `category=lip`, `maxPriceKRW=20000`, `moisturizing=true`는 유지. 하지만 `GET /api/products`에 존재하지 않는 `maxPriceKRW`·`fragranceFree` HTTP 필터를 있는 것처럼 호출하지 않음.
- 사실 정답: 실제 상품 존재와 카테고리/참고가 조건을 확인할 수 있으나, `moisturizing`에 대한 개별 상품 검수 없이 촉촉함을 확정하지 않는다. 현재 판매가는 원본 관측 시각/가격 종류가 확인될 때만 확정.
- 자동 assertion: 실제 Tool+HTTP trace, 상품/셰이드 귀속, 응답 스키마, 확인/미확인 구조, E5 카드·조건 문구 정합성.
- 사람 평가: 답변이 초보에게 유용하고 과장 없이 자연스러운가(0~4점 척도). 금지 주장: 실제 검증 없는 “현재 2만원 이하 확정”, “보습 효과 입증”, “무향료”.
- 차단: 중요한 사실/근거/스키마 위반 또는 E1/E3/E5 필수 실행 누락. 사람 품질 점수는 기준선 측정 이후 별도 평가.

### 12. 실제 앱의 자유 입력 경로: G1-CAT-01 필수 변형

현재 `hooks/useChat.ts`는 category/context 없이 메시지를 보내면 `requestType=chat`, 상품 카테고리를 전달하면 `beauty_consultation`을 사용한다. 따라서 `G1-CAT-01.input.requiredVariants`에 두 경로를 **모두 필수**로 지정했다. 상품 탭에서 검색이 성공했더라도 자유 입력창에서 “립 제품 추천해줘”를 일반 생성 답변으로만 처리하면 G1의 자유 대화형 상품 검색 경로는 미완이다. 기존 공개 `ChatResponse`는 내부 `supervisor`와 `tool_result`를 제외하므로 실제 Tool 호출 증빙은 별도 내부 트레이스로 기록해야 한다.

### 13-1. 누락·충돌 수정 결과

- **G1-CAT-14**: 명시적인 '입문용 립도 보여줘'에 따라 `catalog.search_products` 및 `GET /api/products`를 필수로 명시. E1을 **필수** 환경에 추가하고 `trace.catalog_called`, 상품 ID 정본 검증, E5 카드 비교를 각 환경에 연결. 간단한 정보 설명+단일 Catalog 조회이지 G8 복합 Agent 요구가 아님.
- **환경/검사 대조**: 모든 47개 `environments.required/optional`와 `assertions.automaticByEnvironment.appliesTo`를 정합화. 선언 외 E0~E7 참조 0건, 필수 환경 무검사 0건, 중복 환경 선언 0건. Catalog와 무관한 E2 옵션은 삭제해 Neo4j가 G1의 불필요한 PR 게이트가 되지 않도록 함. 오류 주입 E1은 실제 프로덕션 장애를 만들지 않는 **격리 프록시 검증일 때만 선택**.
- **G1-CAT-01**: `category_entry`(`beauty_consultation`)와 `free_chat`(`chat`) 두 입력을 **모든 필수 환경에서 각각 실행**하고 독립 결과/trace 기록. 한 경로 PASS로 다른 경로 PASS 추정 금지.
- **G1-CAT-04/06/12/13**: 화면 상품·호수/다른 상품 소유 호수 fixture를 관측 DB의 검증값으로 묶고, 이전 대화 기억을 요구하지 않음. CAT-06은 해당 상품의 참고가와 미검증 **현재가**를 분리. CAT-12는 실제 다른 상품의 `05` 호수로 고의 불일치 주입.

- **G1-REG-04/05/06**: 기존 `beauty_consultation` 세션에서 R0 초기 세션 발급과 R1 후속 요청을 분리하고, **R1의 동일 sessionRef·requestId·본문**을 재전송(또는 본문만 변경)하는 시퀀스로 정의. 일반 `chat`의 requestId 처리까지 새로운 멱등성 보장으로 바꾸지 않음.

### 13-3. 유효한 타 사용자 세션 fixture

`g1_manifest_PROPOSED.json.sessionFixtureResolver`의 절차대로 실행할 때마다 소유자 A/B를 분리하고 **유효한 A의 세션**, A의 정상 토큰/`resultSetId`/`stateVersion`/`expiresAt`을 서버로부터 받는다. A 자신이 조회 가능하고 `now < expiresAt`임을 먼저 확인한 뒤, B가 같은 세션을 요청한다. 기대 응답은 **403 소유권 거부**, 타인의 후보/대화/토큰 정보 비노출, 세션 변경 없음. `expiresAt` 등 동적 값은 템플릿에서 실제 유형으로 치환하고 평문 토큰은 증빙에 저장하지 않는다. 만료 발생 시 410을 권한 거부 성공으로 세지 않는다.

### 13-4. 사람의 **핵심 상담 수행** 검증을 병합 게이트로 연결

대화의 정답 문장을 고정하지 않고 `expected.semanticOracle.essentialBehaviors`의 **내용상 필수 요소**를 충족했는지 사람이 평가한다. 기본 한국어 상담 **GEN-01~12 전부**, 실제 자유 상담 RUN-02, 설명+상품 CAT-14, 중요한 과장 경계 CAT-02/05/06/13, **총 18건**에 이 게이트를 적용한다. E3 실제 LLM 답변·응답 참조·검수자·핵심 요소별 판단을 남기며, 비어 있거나 의미 없는 답변·범용 사과·질문의 핵심 회피는 `FAIL`. 핵심 충족 평가가 미실행이면 `NOT_RUN`으로 **G1 PR 병합 차단**. 단순 `response.schema_valid`나 `route.intent_general` 통과로 대신할 수 없다. 사람 평가 0~4점 평균 임계치는 기준선 실측 후 결정하며, 필수 내용 충족의 이진 판정과 분리한다.

**평가 예:** GEN-01은 화장 순서/방법과 초보 눈높이 설명이 있어야 하며, "저는 도움을 드릴 수 있습니다"만 답하면 불합격. GEN-02는 쿠션/파운데이션 차이 실질 설명이 필요하며 단순 "제품마다 다릅니다"만으로 불합격. GEN-07은 명확화 질문 또는 유용한 둘 이상의 방향이 허용되며 특정 스타일을 강제하는 답은 불합격. CAT-14는 설명과 실제 조회 결과가 **둘 다** 있어야 함.

### 13-5. 자동 평가 준비 상태와 병합 판단

`validate_cases_STRUCTURE_ONLY.py`는 47개 사례 형식·환경↔검사 일치·fixture 참조·predicate 등록을 검사하는 **정적 검증기**이며 E0 테스트, 실제 Catalog/Redis/LLM/앱 호출 및 70개 predicate 평가를 전혀 실행하지 않는다. `g1_predicate_registry_PROPOSED.json`의 70개는 모두 구현할 함수 명세다. 실제 runner가 `predicate → callable`에 연결되고 각 환경의 실제 관측값을 평가할 때까지 **자동 평가 준비 완료/성공이라고 주장하지 않는다.**

**G1 PR 병합 P0(제안 계약):** ① 실상품/호수/참고가/미검수 성분에 허위 확정 없음 ② 기존 일반 `/api/chat`·AR `ar_command`/ACK·세션/권한 회귀 없음 ③ GEN 기본 상담·RUN-02·CAT-14 등 필수 18건의 실질적 요구 충족 사람 판정 PASS ④ 실제 Catalog E1, 실제 LLM E3, 실제 앱 E5 및 각 필수 변형의 관측 증빙 ⑤ 70개 명세 중 **해당 케이스 필수 assertion에 실제 필요한 함수가 모두 구현·실행**. 미구현/미실행은 NOT_RUN으로 차단. 다른 G단계 기능(멀티턴·검수 전성분·G4 옵션 복합·G5 RAG·G8 고도화 Agent)을 완료했다고 요구하지 않는다.

**정합성 검토 종료 판단:** 47개 사례를 유지한 4-2 *설계 계약*은 종료 가능. 그러나 **G1 기능/자동 평가기 구현 준비 완료/실행 통과/Gold 승인·PR 병합 승인과는 다르다.** 사용자 검토·팀 공유 이후 4단계 문서에 일괄 반영할 수 있다. 새로운 코드·DB·GitHub·Notion 변경 없이 검토 패키지 파일만 수정했다.
