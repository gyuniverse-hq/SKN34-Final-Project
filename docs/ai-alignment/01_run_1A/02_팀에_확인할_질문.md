# VISHUE 팀 확인 질문 — 현재 1-A를 막는 것과 후속 정책을 구분

## A. 1-A Mock 평가를 위해 우선 확인할 두 가지 (LLM·백엔드·AR)

**Q1. 로컬 Codex worktree의 `/api/chat`에 `arContext`가 구현돼 있는가?** `screenId`, `stateVersion`, `activeZone`, `supportedActions`, `productId`, `shadeId` 및 반환 상태·명령 스키마를 실제 코드 기준으로 제시해 주세요. `develop` 브랜치에는 기존 채팅 요청·응답만 확인되었으므로 **로컬 worktree가 기준**입니다.

**Q2. 명령을 '제안'하는 것과 앱에 '적용'하는 것의 경계가 어디인가?** 1-A에서는 ACK 이전 완료 주장 금지, 상태를 직접 변경하지 않는 것이 원칙입니다. 테스트에서 실제 저장·실행 부작용이 없는지 무엇으로 관측할지(가상 store, Tool mock, 트레이스) 합의해 주세요.

> 이 두 가지는 Codex가 먼저 읽기 전용으로 확인할 수 있습니다. 실제 정책이 없다면 테스트가 추측한 상태 코드나 JSON 형태를 정답으로 확정하면 안 됩니다.

**바로 팀에 공유할 짧은 메시지**

> VISHUE LLM 평가셋 35건의 1차 검토를 마쳤고, 보류 10건 중 fixture 정합성은 별도 수정본을 만들어뒀습니다. AR 쪽은 기본 립 레이어/상대 강도/Undo, Product 쪽은 복합 필터·호수별 색상, Style 쪽은 레시피 검수·영상 권리·Style→AR 실행 계약만 답변이 필요합니다. 각 항목에 대해 **현재 구현 기준 / 목표 정책 / 담당자**를 구분해 확인 부탁드립니다. 1-A Mock 평가는 병렬로 먼저 진행하겠습니다.

지금 당장 모든 질문의 답을 받아야 하는 것은 아닙니다. **1-A Mock 실행은 A의 두 항목과 로컬 코드가 확인되면 시작**하고, B는 후속 작업으로 관리하면 됩니다.
