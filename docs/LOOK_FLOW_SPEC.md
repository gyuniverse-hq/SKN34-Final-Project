## 3. 수락 기준

**1단계 룩 적용**
1. 룩을 고르고 "AR에서 입어보기"를 누르면 그 룩의 모든 부위(최대 7개)가 한 번에 입혀진다.
2. 부위별로 끄고 켤 수 있고, 진하기만 바뀐다(제품 색은 그대로).
3. 누르고 있는 동안 맨얼굴이 보인다.

**3단계 세트 담기**
1. 룩 제품이 모두 매장에 있으면 구역 없이 그대로 담긴다.
2. 색이 없는 제품은 가장 비슷한 셰이드·양 조절, 또는 판매처·품절로 표시된다(6-5-10). 품절은 담기지 않는다.

**4~7단계 그리는 법 가이드**
1. "그리는 법"을 켜면 카메라 위에 점선이 보이고, 얼굴을 움직이면 같은 프레임에 따라 움직인다(오프라인 렌더로 정면·좌·우 확인, 폰 확인 필요).
2. 단계 바 4개를 눌러 단계를 바꿀 수 있다. 섀도·아이라인·립 부위 탭을 누르면 그 단계로 따라가고, 눈썹 단계는 부위 탭을 바꾸지 않는다.
3. 아이라인 단계의 각도·길이는 룩 값을 쓴다(없으면 15°). 안내 문구에 같은 각도가 나온다.
4. 가이드를 끄면 선이 모두 사라진다. 가이드는 색을 바꾸지 않는다(1-1).
5. 가이드는 얼굴 점만 읽고, 네트워크·저장을 하지 않는다(1-4, 테스트로 확인).

## 7. 룩 클릭 후 조절·추천 로직 (10-27 추가 요청 반영)

요청: 룩의 대표 컬러만 즉시 적용·강조하고, 농도·색을 미세 조절하게 하고, 최종 색에 맞는 제품을 추천해 담게 한다. 결정과 구현은 `AR_SPEC.md` 6-5-12.

| 요청 | 결정 |
|---|---|
| Stage Red Velvet을 립·섀도·블러셔(Bold)로 | **7부위 유지, 대표 3개(립·섀도·블러셔)만 강조.** 데이터 필드 `heroZones`. 룩 분위기 태그 `bold`와 이름이 겹쳐 "Bold 태그"라 부르지 않는다 |
| 대표 외 항목은 기본 상태로 | 룩이 정한 값 그대로(룩에 없는 부위는 꺼짐) |
| 농도·색 미세 조절 | 진하기 슬라이더 + **실제 셰이드 칩**(자유 hex 제외, 1-1·1-8) |
| 색을 바꾸면 룩 해제? | **해제하지 않고 "수정됨"** 표시. 부위별 되돌리기, 룩 모양 값은 유지(예전에는 색만 바꿔도 윙 각도가 기본으로 돌아갔다) |
| 최종 Hex에 맞는 제품 추천 | 고른 제품이 곧 추천. 색이 매장에 없으면 가장 가까운 셰이드 + 양 조절, 그래도 없으면 판매처(룩 화면, 6-5-10) |
| 피부 타입 맞춤 기초 | **제외 유지**(사용자 결정) |
| 장바구니 | 입은 구성대로 담고, 가까운 셰이드로 대신한 항목도 같이 담음. 항목에 원래 룩 ID를 남김 |

데이터 흐름:
```
룩 클릭 → applyLook(makeup, selections, colorLinks, heroZones, 원래 값 저장)
슬라이더 → setIntensity(렌더만, 추천 재계산 없음)
색 칩 → applyShade(색·제형만 교체, 모양 유지) → modified 재계산
되돌리기 → revertZone(룩 색·제품, 진하기 유지)
추천 → 고른 셰이드 / findColorGaps(최근접) / 판매처 검색 / 품절
세트 담기 → 선택 제품 + 최근접 대체 제품
```

남은 허점·후속:
- 자유 색(임의 hex)은 "가상 색" 표시와 최근접 제품 안내를 붙여 나중에 넣는다.
- 대표 부위를 끄면 별 표시는 남고 "룩에서 빠짐" 안내는 아직 없다.
- 매칭은 앱 안에서 계산한다. 카탈로그가 커지면 서버 API(`/api/products/match`)로 옮긴다.
