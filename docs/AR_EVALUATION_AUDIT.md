## 3. 새로 발견한 문제

### 3-1. [P0] 색 ΔE ≤1.5는 지금 데이터로 판정할 수 없다

Kaggle 20쌍은 맨입술 사진과 립 바른 사진이 **따로 찍힌 사진**이다. 립스틱이 닿지 않는 **입 주변 피부 띠**의 평균색을 두 사진에서 비교하면:

| 입 주변 피부 ΔE (맨얼굴 사진 vs 화장 사진) | 값 |
|---|---|
| 중앙값 | **2.90** |
| 범위 | 0.69 ~ 8.63 |
| ≤1.5인 쌍 | 5 / 20 |

즉 **화장과 무관한 피부도 사진 사이 조명·노출 차이로 ΔE 2.9만큼 다르다.** AR이 완벽해도 이 데이터에서 입술 ΔE 중앙값이 1.5 아래로 내려가기 어렵다. 그래서 자동 판정은 색상을 "불합격"이 아니라 **`not_valid`(이 데이터로는 판정 불가)**로 표시한다.

**해결:** 노출·화이트밸런스 고정, 삼각대, 컬러 체커를 넣은 **팀 촬영 쌍**이 필요하다. 그 데이터에서 피부 바닥값이 1.5보다 충분히 작은지 먼저 확인한 뒤 ΔE ≤1.5를 판정한다.

### 3-2. [P0] 문서 수치와 현재 코드 버전이 다르다

| 코드 | `faceTrackerHtml.ts` | ΔE 중앙값 | 질감 통과 | 결 SSIM | 노란 조명 ΔE |
|---|---|---:|---:|---:|---:|
| 평가 당시 (11/2 작업본, 파운데이션 수정 반영) | md5 `a2e45746` | 3.65 | 7/20 | 4/20 | 6.67 |
| **현재 HEAD** (`4e891358` 입술 광택·경계 개선 + `5f8c07cd` 포함) | md5 `65d800ad` | **3.86** | **7/20** | **6/20** | **6.61** |

- 입술 광택 개선 커밋은 결(SSIM)을 4 → 6쌍으로 올렸지만, 질감 통과 쌍 수는 그대로다. 색은 0.2 나빠졌다(커밋 메시지의 3.89 → 3.97과 같은 방향).
- **앞으로 모든 수치에 코드 해시를 같이 적어야 한다.** 이번 도구는 결과 JSON에 입력 파일 경로를 남긴다.

### 3-3. [P1] 넘침·빠짐: 중앙값을 평균 기준에 대고 있다

v2.0 매트릭스는 넘침·빠짐 기준을 평균으로 정의했는데, 문서의 13%·17%는 1,840장 **중앙값**이다. 평균으로 바꾸면 200장 14.2%·17.0%, 1,840장 16.1%·19.4%로 더 나쁘다. 기준 문서에 **집계 방식(평균/중앙값)과 데이터셋(200/1,840)**을 같이 적도록 고쳐야 한다.

### 3-4. [P1] IoU 0인 실패 사례 18장

1,840장 중 IoU 0이 18장, 0.2 미만이 23장이다. 사진 속 얼굴이 여러 명일 때 다른 얼굴을 잡은 것으로 보인다(`num_faces=1`). 평균을 0.705로 끌어내리고 있으며, 빼면 0.714다. 실패 사례 목록은 결과 JSON의 위치 통계에 개수로 남겼고, **원인 확인은 아직 안 함.**

### 3-5. [P1] 노란 조명에서 색이 무너진다 (HEAD에서도)

같은 20쌍에 따뜻한 조명을 합성하면 HEAD 코드도 ΔE 6.61, 합격선(이전 기준 4) 안 2/20쌍이다. 원인은 미확인(가설: 조명 색 보정이 입술 색을 치우치게 함). 실내 조명은 흔한 사용 환경이라 우선 확인이 필요하다.

### 3-6. [참고] IoU 0.90의 측정 상한

사람이 칠한 정답 마스크를 입 너비 1%만 옆으로 옮겨도 IoU 0.93, 1% 두껍게 하면 0.83이다(LaPa 463장). 현재 1,840장 중 0.90 이상은 9장(0.5%)이다. v2.0이 0.90을 최종 합격선으로 둔 것은 팀 결정이므로 유지하되, **정답 라벨 자체의 흔들림 때문에 0.90이 측정상 도달 가능한지**를 같은 사진에 두 사람이 정답을 그려 비교하는 실험으로 먼저 확인하길 권한다.

### 3-7. [P0] 설문 정답표 버전: 기존 응답은 v4, 저장소 루트는 v5

- 기존 5명 응답은 **v4 설문**(11/2 이전 코드로 렌더한 사진)에 대한 것이다. 정답표는 `_v4_카탈로그색/key.csv`에만 있다.
- 저장소 루트 `naturalness_test/key.csv`는 **v5**(11/2 코드로 다시 렌더, 사진 번호 새로 섞음)다. **v4 응답을 루트 정답표로 채점하면 모든 사진이 "정답표에 없음"이 된다.**
- 따라서 문서의 자연스러움 수치(86.7%, 4.07)는 **v4 렌더 기준**이다. 질감·색 수치(평가 당시 코드)나 HEAD 코드와도 버전이 다르다. HEAD 코드의 자연스러움은 v5 설문으로 새로 받아야 한다.

| `criteria_v2.json` | v2.0 기준을 기계가 읽는 형태로. 모든 값에 `stage`(final / milestone / sanity) 표시. 상태값 5종: `pass` `fail` `in_progress` `not_measured` `not_valid` |
| `eval_matrix.py` | 기존 도구의 결과 CSV만 읽어 상태 판정. 렌더하지 않음 |
| `skin_floor.py` | 쌍마다 입 주변 피부 띠의 맨얼굴↔화장 사진 ΔE를 계산해 `skin_floor.csv`로 저장 (색 판정의 측정 바닥값) |
| `test_eval_matrix.py` | 7개 테스트: 항상 AR만 누른 평가자 BA = 0.5, 동률 처리, 1차 목표 달성을 합격으로 세지 않음, 데이터 없음 = not_measured, 측정 바닥 > 기준 = not_valid 등. **7 passed** |

실행 (PC, 저장소 루트):

```bash
python research/eval_matrix/eval_matrix.py \
  --criteria research/eval_matrix/criteria_v2.json \
  --lapa research/data/reference/lapa/eval/baseline_landmarks.csv \
  --subset research/data/reference/lapa/eval/subset200.json \
  --lip research/data/hw01_compare.csv \
  --floor research/eval_matrix/data/skin_floor.csv \
  --key research/data/ar_eval_public/naturalness_test/_v4_카탈로그색/key.csv \
  --survey <v4 설문 CSV 폴더> --exclude 전진영 전진영5 \
  --out research/eval_matrix/result_<날짜>_<커밋>.json
```

AR을 고친 뒤 순서: ① `render_ar_offline.py`로 20쌍 렌더 ② `hw01_compare.py` (`research/data/hw01_compare.csv` 생성) ③ (입술 위치를 바꿨다면) `eval_lapa.py` ④ 위 명령. 결과 JSON은 날짜·커밋별로 새 파일로 저장하고 이전 결과는 덮어쓰지 않는다.
