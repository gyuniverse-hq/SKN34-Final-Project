# 피부 리포트: 임시 연결과 실데이터 인계

작성일: 2026-10-29. 브랜치: `feat/skin-profile-recommendations`.

사용자가 제공한 올리브영 화면은 **정보 순서와 인터랙션**의 참고 자료다. VISHUE의 아이보리·버건디·로즈
테마와 기존 Expo 구조를 유지한다. 이 문서의 임시 연결은 검증된 피부 진단·제품 효능 규칙이 아니다.

## 구현한 흐름

`분석 → 설문 → 저장 성공 → /skin-recommendations`

1. 피부 성향 요약과 기본으로 펼쳐진 리포트 정보. 분석일·분석 방식은 표시하지 않는다.
2. 먼저 살펴볼 케어 2개. 누르면 해당 항목의 상세 결과로 이동.
3. 고정 탭 **내 피부 솔루션 / 분석 결과**.
4. 솔루션: 고민별 성분 예시 → 아침·저녁·추가 케어 가로 카드 → 홈케어 노트 → 샘플 상품.
5. 상세: 이미지 분석이 있는 항목만 선택 → 피부타입 또는 좋음·양호·유의 상태 표시. 숫자 등급·등급 기준 안내·부위별 숫자는 표시하지 않는다.
6. 상품: 샘플 미리보기 모달 또는 사용자가 요청한 실제 카탈로그 추천. 실제 상품만 상세 페이지에 연결.

최근 리포트 버튼은 이 기기의 최신 저장 결과 한 건을 안내한다. 홈·뒤로·재분석·맨 위로 버튼도 연결했다.
새 촬영 결과는 사진과 입력 부위를 얼굴 윤곽 안에 임시 표시한다. 화면 이탈 시 사진을 지우며 이전 결과는 재촬영이 필요하다.

## 성분 매핑 전체 목록 (검수 전)

- 건조: 히알루론산, 세라마이드, 스쿠알란
- 유분: 나이아신아마이드, 판테놀
- 민감: 판테놀, 병풀, 세라마이드
- 트러블: 병풀, 판테놀
- 모공: 나이아신아마이드, 살리실산
- 색소침착: 나이아신아마이드, 판테놀
- 주름: 아데노신, 세라마이드

위 관계는 화면 시연을 위한 연결이며 제품 효과·적합성·사용 빈도를 보장하지 않는다.
수분량 측정치는 생성하지 않는다. 상세의 기존 건조 항목은 **피부타입**으로 표시하며 모델 60%·설문 40%의 분류를 사용한다. 피부타입 모델이 없는 과거 결과의 당김 설문은 상세에서 숨긴다.

## 예시 데이터의 경계

- 저장 결과가 있으면 그 결과를 사용한다. 없을 때만 별도 예시 입력을 보여 준다.
- 저장소 읽기 실패는 오류로 표시하며 예시 결과로 숨기지 않는다.
- 예시 입력은 `skinProfileStore`, AsyncStorage, 실제 분석 기록 또는 DB에 저장하지 않는다.
- 샘플 상품은 실제 결과가 있는 경우에도 기본 시연 목록이다. 화면에 샘플임을 명시한다.
- 실제 API가 실패하거나 빈 목록을 반환하면 해당 상태를 표시한다. 샘플 성공 응답으로 자동 대체하지 않는다.
- 사진은 기기 메모리에만 임시 보관하며 결과 화면 이탈 시 삭제한다. 서버로 전송하거나 프로필에 저장하지 않는다.
- 서버 DB, 마이그레이션, 실데이터 시드, 외부 결제·상품 API는 이 작업에서 수정하지 않는다.

## 실데이터 인계 순서

1. 카탈로그 담당: 실제 상품 ID/카테고리/케어 태그/전성분/가격/이미지/판매 상태 제공.
2. 콘텐츠 담당: 성분 사전, 고민–성분 근거, 루틴과 팁의 검수·다국어 콘텐츠 제공.
3. 추천 담당: 피부 타입·케어 우선순위·루틴 개인화 정책 확정 및 평가셋 검증.
4. 필요하면 별도 콘텐츠 API를 만들고 샘플 상수를 교체한다. 클라이언트에서 `data/`나 서버 DB를 직접 읽지 않는다.
5. 공개 전에 샘플 기본 노출 정책을 결정하고 실제 카탈로그 기반 사용 흐름을 실기기로 검증한다.

## 과거 저장 결과: SOS 설문 보완 v2 (2026-11-01)

- 원본 모델 softmax 평균과 ROI는 그대로 둔다. `SkinProfile.version: 2`는 설문 응답·버전, SOS 합계와 정책 설정·보정 점수·변화량·최종 타입·보정 이유를 저장한다. 읽기/쓰기 시 정책 버전별 일관성을 검증하되 저장 판정을 새 정책으로 교체하지 않는다. 기존 v1은 자동 변환하지 않는다. 저장 키와 최신 1건 저장 방식은 유지한다.
- SOS 출처: Baumann LS, Penfield RD, Clarke JL, Duque DK (2014), *A Validated Questionnaire for Quantifying Skin Oiliness*, Table 2, https://doi.org/10.4236/jcdsa.2014.42012 (CC BY). 앞 4문항 a–d=1–4, 마지막 2문항 a–e=1–5, 총 6–26점. 낮은 점수로 건성을 판정하지 않는다.
- BSTQ 출처: Ahn et al. (2017), *Baumann Skin Type in the Korean Female Population*, Appendix 1, Part Two 1·18번, https://doi.org/10.5021/ad.2017.29.5.586. 붉은 트러블과 화장품 반응은 각각의 자가응답이다. 전체 BSTQ 점수/유형으로 해석하지 않는다. 화장품 반응 c·d는 민감함 필터를 제안하고, 일반적 미사용(e)은 미확인으로 처리한다. 반응 때문에 제품을 피하면 원문 안내대로 d를 선택한다. 붉은 트러블은 보조 표시만 한다.
- 네 언어 번역은 별도 타당성 검증을 거치지 않았다. 설문 문항 출처·번역 버전은 `constants/skinSurvey.ts`, UI 번역은 `lib/i18n/survey.ts`에 있다.
- 실험 정책 `sos-oily-v1`: SOS≥20, 이미지가 지성이 아니고 최고 점수−지성 점수≤0.10일 때만 λ=min(0.10, 0.025×(SOS−19)), p′=(1−λ)p+λ[0,0,1]. 동점이면 이미지 타입 유지. 그 밖에는 이미지 판단을 유지한다. 모델 타입 출력이 없으면 unknown이다. 설정은 검증되지 않은 초기 정책이며 보정 점수는 진단 확률이 아니다.
- 리포트·추천은 같은 저장 결과를 사용한다. 최우선 고민은 첫 관리 항목과 기본 필터에 추가하며 ‘관리 필요’ 판정을 만들지 않는다. 상품 순위 계산과 서버 계약은 그대로다. 서버에는 확인한 고민 코드만 전달한다.
- 오프라인 비교: `node scripts/evaluate-skin-fusion.mjs input.json`. 입력은 `{ "prediction": { "label": "dry", "probabilities": [0.5,0.05,0.45], "roiCount": 3, "scoreType": "mean_uncalibrated_softmax" }, "sosTotal": 26 }` 형태의 행 배열이다. 모델이 없으면 prediction을 생략한다. 이미지·사용자 식별자는 입력하지 않는다.
- 출력에는 전체/비교 가능 표본 수, 비교 가능한 행을 분모로 한 변경률, 변경 방향, 평균 클래스별 변화량과 행별 기록이 포함된다. 출력은 stdout으로만 제공한다. 합성 입력은 규칙 검증이며 정확도 평가가 아니다. 실제 변경률과 정확도 검증에는 설문이 함께 수집된 별도 자료가 필요하다. 실기기 인수 확인은 별도로 수행한다.


## 과거 저장 결과: 자체 구성 보조 설문 v3 (2026-11-01)

- `SkinProfileV3.version=3`, `SkinSurveyV3.version=skin-support-1`. 기존 저장 키와 최신 1건 방식은 유지한다. v1·v2·v3를 분기해 읽고 신규 저장에만 v3를 사용한다. 과거 응답을 새 응답으로 추정 변환하지 않는다.
- 한 화면의 6문항을 모두 선택해야 저장한다. `unknown`은 미선택과 다르며 응답 완료로 인정한다. 피부 타입 4문항은 `postWashDryness`, `afternoonTzoneOil`, `cheekState`, `oilOnset`; 나머지는 `cosmeticReaction`, `priority`다. 범주형 응답을 그대로 저장하며 SOS 총점이나 가상의 보정 결과를 만들지 않는다.
- 질문은 최근 4주 평소 피부 상태를 기준으로 하며, 관찰을 위해 보습을 미루거나 세안을 반복하도록 요구하지 않는다. 오후 T존 유분은 정도, 유분 발생 시간은 최초 인지 시점을 묻는다. 시간 범위는 ≤1시간, >1~≤3시간, >3시간이다. `notNoticed`(하루 중 거의 못 느낌)와 `unknown`(미관찰·미확인)을 보존한다. 평소 스킨케어의 영향도 포함된 자가응답이며 피지 측정값이 아니다.
- 두 유분 응답이 달라도 저장을 막지 않는다. 향후 보정에서 이 둘을 독립적 근거로 중복 가중하지 않도록 검토한다. 현재는 4문항의 총점·가중치·추가 필터를 계산하지 않는다. unknown·variable·notUsed를 중성·0점·무증상으로 치환하지 않는다.
- v3 피부 타입과 점수는 원본 이미지 모델 결과를 사용한다. 출력이 없으면 unknown이다. SOS 보정은 v2를 읽는 경우에만 유지한다. 기존 `evaluate-skin-fusion.mjs`는 **v2 SOS 정책 비교 전용**이며 v3 응답을 SOS 점수로 변환해 입력하지 않는다.
- 화장품 반응 repeated(최근 4주 2번 이상)·avoided(과거 반응 때문에 최근 피함)만 민감함 필터를 제안한다. 이는 진단이나 검증된 민감성 임계값이 아닌 서비스 규칙이다. once는 보조 응답으로만 저장하며, notUsed·unknown은 미확인으로 둔다. 최우선 고민은 첫 관리 항목·기본 필터로 제안하지만 분석상 care 상태를 만들지 않는다. 필터는 사용자가 바꿀 수 있다.
- 결과 화면은 최종 피부 타입을 표시한다. 응답·모델 점수·SOS 총점·보정 이유·전후 비교는 일반 리포트에 표시하지 않는다.
- 평가 개념 참고: SOS/BSTQ(위 출처), Cho et al. (2023), https://doi.org/10.1111/jocd.15820. UX 참고: 아모레몰 스킨노트 소개 https://www.amoremall.com/kr/ko/display/event_detail?planDisplaySn=10347. 자체 6문항과 네 언어 번역은 별도 검증되지 않았으며 위 연구의 타당성·정확도를 계승하지 않는다. 모델이나 분류 정확도가 향상됐다고 표현하지 않는다.
- 백엔드·DB·모델 추론은 변경하지 않는다. 추천 API에는 사용자 확인을 거친 `{concerns, limit}`만 전달하며 설문과 점수는 기기에 저장한다. 실제 Expo Go 촬영·사진 선택→설문→저장→재진입 인수 확인은 별도로 수행한다.


## 신규 등록: 규칙 기반 Late Fusion v4

- 6문항과 원본 ROI별 softmax 평균 추론은 그대로 유지한다. 새 저장 프로필만 `version:4`와 별도 `fusion`을 사용한다. 기존 v1·v2·v3 결과를 새로운 정책으로 소급 보정하지 않는다. 기존 API에는 계속 확인한 고민 코드만 전달한다.
- 정책 `support-dry-oily-v1`의 **검증되지 않은 초기 휴리스틱**은 `lib/skinSupportFusion.ts`에 있다. 이 설정이 이미지+설문 결합 정확도를 높인다는 근거는 없으며 의학적 기준이나 보정된 확률이 아니다.
- 응답 강도: 세안 후 건조 none=0, mild=.5, marked=1; 오후 T존 none=0, slight=.5, marked=1; 발생 시간 within1h=1, after1to3h=.75, after3h=.25, notNoticed=0. 볼은 dry/oily일 때 각각 건조/유분 표시값 1, comfortable는 둘 다 0이다. unknown·variable은 0으로 치환하지 않고 보정을 건너뛴다.
- `T=(오후 유분+발생 시간)/2`, `D=.6×세안 후 건조+.4×볼 건조`, `O=.75×T+.25×볼 유분`. 두 T존 문항을 평균으로 묶어 중복 정보의 합산을 피한다. 민감성·최우선 고민은 신호 계산에서 완전히 제외한다.
- D≥.6 및 O≤.3이면 건성, O≥.6 및 D≤.3이면 지성을 보완 대상으로 삼는다. 둘 다 ≥.6이면 보정하지 않으며, 그 밖에 우세가 불명확해도 유지한다. 문항 누락·잘못된 응답·미확인·가변 상태·과거 설문 버전은 원본을 유지하고 이유를 기록한다. 모델 자체의 잘못된 점수는 오류로 거부한다.
- 이미지 상위 두 점수 차이가 ≤.10이고 보완 대상 점수와 최고 점수 차이도 ≤.10일 때만 적용한다. 중성은 보정 목표로 사용하지 않는다.
- 원본 p에 대해 `p0=p/Σp`, `α=.10×|D−O|`, `u=(1−α)p0+αe_target`, `p_final=u/Σu`. α≤.10이며 각 클래스의 실제 변화량도 10%p 이하가 되도록 제한한다. 동점이면 이미지 원래 클래스를 유지한다. α는 보정 계수이며 실제 점수 증가량과 다르다.
- 임계값·가중치는 `SUPPORT_FUSION_V1`에서 분리 관리한다. 실험 호출은 설정값을 전달할 수 있지만, 저장/로드는 저장 당시 설정 스냅샷으로 결과를 검증하므로 기본값을 조정해도 과거 결과를 바꾸지 않는다. 범주 점수 의미나 보정 공식을 변경할 때는 새 정책 ID와 재현 가능한 분기를 추가해야 한다.
- 원본 `analysis`는 수정하지 않는다. `fusion`에는 정책 ID, 설정, D/O 신호, 최종 점수·타입, 변화량, 계수, applied, changed, 이유를 별도로 저장한다. 적용됐어도 클래스가 같을 수 있으므로 applied와 changed를 구분한다. 읽기·쓰기 모두 일관성을 검증하고 저장 결과를 새 결과로 교체하지 않는다.
- 리포트·추천은 같은 저장 판정을 사용한다. 일반 리포트에는 보정 사유·원본 점수·응답을 표시하지 않는다. 개발 모드의 마이 → 피부 분석 벤치마크 → 개발용 피부 설문 기록에서 기기에 저장된 최신 응답·원본 타입·보정 기록만 확인한다. 원격 전송은 하지 않는다. 기존 v3는 계속 이미지 단독 판정이며, v2 SOS 비교 도구는 v4 평가에 사용하지 않는다.

설문 입력은 한 화면에 한 문항씩 총 6단계로 표시하며, 이전 단계로 돌아가도 입력을 유지한다. 개발용 기록 화면은 개발 빌드의 기기 로컬 점검 기능이며 서버 관리자 계정이나 원격 접근 권한을 제공하지 않는다.

신규 설문의 화장품 반응은 사용 후 반응 없음·1번·2번 이상·최근 미사용·미확인 중 선택한다. 과거 저장된 avoided 응답은 호환성을 위해 읽고 기존 민감함 제안을 유지한다. 새 최우선 케어 목표는 보습→dryness, 진정→sensitivity, 미백→pigmentation, 탄력→wrinkles, 모공→pores로 매핑한다. 피부 타입 보정은 이 두 응답을 사용하지 않는다.

과거 등급 모델의 사진 분석 상태는 등급 0–3 양호, 4 이상 유의로 표시한다. 현재 skin-analysis-v4 모델은 양호/유의 직접 이진 모델로, 부위별 sigmoid 점수 0.5 이상이면 유의다. 한 부위라도 유의이면 보고서와 추천 고민 제안에 동일하게 반영한다. 이진 결과를 등급으로 변환하지 않는다. 상세 탭은 사진에서 분석된 피부 타입과 부위별 결과만 표시하며 분석하지 않은 항목은 숨긴다. 화장품 반응의 최근 미사용·미확인은 신규 응답에서 하나로 묶고 기존 저장 값은 그대로 읽는다.
