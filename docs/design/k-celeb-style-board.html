원본에 수록된 메이크업 영상과 룩 데이터는 7명·34개 영상, 7그룹·73개 룩이다. 챗봇 탐색을 위해 연예인은 레퍼런스 활용 및 무드 스펙트럼을 고려한 3개 클러스터로 제안하고, 스타일은 ① TPO·일상성 ② 강조 부위 ③ 컬러·무드·보정의 3개 축으로 기존 그룹을 재배치한다. 검색·추천과 RAG 매칭에 활용할 수 있으나 효과는 평가가 필요하다.

04질문 처리 예시

“카리나처럼 쿨톤 메이크업 하고 싶은데 2만 원 이하 제품으로 알려줘”
01 오케스트레이터 →셀럽·쿨톤·예산 20,000원 추출. 모호한 톤은 확인 질문.
02 셀럽 영상 조회 →karina 영상과 제목·채널·영상 ID 확인. 커버 영상은 당사자 사용으로 단정 금지.
03 사용 제품 →제품명·옵션·출처·검토 상태를 추출. 쿨톤 여부는 근거 확인 필요.
04 상품 DB 매칭 →api 상품 검색 후 브랜드·제품명·옵션 비교. 검증된 동일 상품만 연결.
05 검증 →매칭·가격·예산·출처를 확인. 가격 없으면 예산 충족 단정 금지.
06 답변검증된 제품과 가격·영상 출처 제시. 매칭 실패 시 콘텐츠 참고만 표시하고 대안은 별도 구분.

08결정 필요 안건

  1. 그래프: Celebrity → Video, StyleLook → 제품 관계·ID·검수 이력 및 교체 동기화 방식을 확정.
  2. HTTP 계약: GET /api/celebrity-videos, /api/style-looks 목록은 존재. 필터·상세·증분 동기화 API 추가 필요 여부 확인.
  3. 근거 정책: “검토 필요” 및 “원본 기준 정리” 제품을 어떤 조건으로 답변에 쓸지 결정.
  4. 광고 출처: 유료광고·제품제공을 추천 이유와 화면에 어떻게 노출할지 결정.
  5. 상품 매칭: 브랜드·제품명·옵션 일치 기준, 수동 검수·대체 상품 및 미매칭 처리 확정.
  6. UC 대응: 기능 명세의 F ID와 팀의 UC-AI ID 연결 여부 확인.
집계: 각 JSON의 products 배열 원소 수(중복 상품 제거 안 함), 비율은 각 파일 전체 제품 등장 수 기준. 상위 분포는 원본 라벨 그대로. reviewStatus 매핑은 보수적인 제안이며 검증 완료·제외 상태는 원본에 없음.
