# NIA 배포 가중치 출처와 전처리 확인

확인일: 2026-10-23(KST). 대상은 사용자 제공 `checkpoint.zip`의 NIA ResNet-50 가중치
10개와 [전체 성능 평가](full-performance-evaluation.md)에 사용한 추론 경로입니다.
가중치 변경·재학습·테스트셋 기반 해상도 선택은 하지 않았습니다.

## 확인 결과

**현재 가중치는 논문의 장비별 CoAtNet-4 성능을 그대로 재현하는 묶음이 아닙니다.**
저장된 설정과 학습 스텝 수는 DSLR 학습 가중치라는 해석을 강하게 뒷받침합니다.
우리 평가는 같은 항목의 가중치 하나를 DSLR·태블릿·스마트폰에 각각 적용했으므로,
스마트폰 전용 모델의 성능을 재현했다고 해석하면 안 됩니다.

확정한 사실과 추론은 다음처럼 구분합니다.

| 확인 사항 | 결과 | 근거의 범위 |
|---|---|---|
| 아키텍처 | ResNet-50, 항목별 독립 모델 10개 | state dict와 strict loading으로 확인 |
| 저장된 batch size | 전 모델 256 | 원본 체크포인트 최상위 `batch_size` |
| 저장된 초기 학습률 | 전 모델 0.0001 | optimizer `initial_lr`, scheduler `base_lrs` |
| 학습 기기 | DSLR 학습일 가능성이 매우 높음 | 전 모델의 스텝 수가 DSLR Train+Val 조합과 일치. 실제 CLI는 없음 |
| 공개 평가 해상도 | 256×256 | 당시 공개 crop·loader 코드 |
| 실제 학습 해상도 | 확정 불가 | `res`와 실행 인자를 저장하지 않음. ResNet의 adaptive pooling으로 역추정할 수 없음 |
| 논문의 동일 가중치 여부 | 확인되지 않음 | 논문의 ResNet-50 비교 실험 batch size는 32이며 배포 파일은 256 |
| 독립 최종 Test 여부 | 확정할 수 없음 | 공개 학습 코드가 Test를 검증·체크포인트 선택에 사용 |

전체 집계 근거는 [감사 JSON](experiment-evidence.json)에 보존합니다.
사진·개별 인물·ROI ID·학습 실행 UUID·가중치 텐서는 포함하지 않습니다.

## 가중치 안에서 직접 확인한 설정

배포 ZIP은 약 2.83 GB이며, `checkpoint/{class,regression}/1st_cnn/save_model/` 아래의
`state_dict.bin` 10개만 들어 있습니다. YAML·CLI 로그·코드 사본·기기별 별도 폴더는 없습니다.
ZIP 엔트리의 수정 시각은 2025-12-02입니다. ZIP 시각에는 타임존이 없으므로 실제 학습일을
확정하는 근거로 사용하지 않습니다.

원본의 최상위 키는 `model_state`, `epoch`, `best_loss`, `batch_size`, `info`입니다.
`info`에는 등급별 표본 수·정답 예측 수, 저장된 Accuracy·상관계수, `global_step`, optimizer와
scheduler 상태가 있으나 `equ`, `res`, 전체 실행 인자는 없습니다.
원본을 변경하지 않고 텐서 storage를 읽지 않는 제한된 메타데이터 판독으로 10개를 조사했으며,
주름 모델은 기존 `weights_only=True` 판독 결과와도 대조했습니다.

## DSLR 학습이라는 해석의 근거

공개 코드는 Train+Val을 합친 표본 수만큼 샘플링하고, 마지막의 작은 배치를 버리지 않으며,
Train 배치마다 `global_step`을 1씩 증가시킵니다.
기존 스텝이 0이고 같은 크기의 데이터로 연속 학습했다는 조건에서 예상 스텝은 다음과 같습니다.

```text
예상 global_step = ceil((Train ROI + Val ROI) / batch_size) × (저장 epoch + 1)
```

| 항목 | DSLR Train+Val ROI | epoch당 배치 수 | 예상 스텝 = 실제 저장 스텝 |
|---|---:|---:|---:|
| 주름 분류 | 20449 | 80 | 960 |
| 입술 건조 분류 | 5964 | 24 | 288 |
| 색소침착 분류 | 14474 | 57 | 969 |
| 모공 분류 | 8530 | 34 | 646 |
| 턱선 처짐 분류 | 4245 | 17 | 170 |
| 색소침착 회귀 | 6327 | 25 | 675 |
| 수분 회귀 | 19946 | 78 | 1170 |
| 탄력 R2 회귀 | 19946 | 78 | 1092 |
| 눈가 주름 Ra 회귀 | 9007 | 36 | 648 |
| 모공 회귀 | 9008 | 36 | 648 |

스마트폰·태블릿 단독 및 세 기기의 가능한 비어 있지 않은 혼합 조합 7가지를 비교했을 때,
각 모델에서 DSLR 단독 조합만 일치했습니다. 분류의 저장 평가 표본 수도 모두 제공된
seed-1 DSLR Test의 전체 표본 수와 일치합니다. 특히 주름의 저장 표본 수 2200은
DSLR Test 2200과 같고, 태블릿 2192·스마트폰 2199와 다릅니다.

이는 **DSLR 학습이라는 강한 정황**입니다. 실제 실행 인자, 재개 학습 이력과 전체 원본
학습 데이터가 없으므로 수학적 일치를 학습 기기의 직접 기록으로 바꾸어 표현하지 않습니다.

## Test를 모델 선택에 사용한 공개 코드

2025-12-02 공개 커밋 `055c27b`의 `tool/main.py`는 다음 흐름을 사용합니다.

```python
merged_data = train_data + val_data
# merged_data로 trainset_loader 구성
test_data, _ = test_dataset.load_dataset(key)
# test_data로 testset_loader 구성
each_model = Model(..., train_loader=trainset_loader, valid_loader=testset_loader, ...)
```

`Model.valid()`에서 평가한 loss가 개선되면 가중치를 저장합니다. 따라서 이 코드의 Test는
체크포인트 선택과 early stopping에 영향을 주는 검증셋 역할을 합니다. 이름만 보고 학습
절차 전체에서 한 번도 사용하지 않은 최종 평가셋이라고 판단할 수 없습니다.

실제 배포 가중치가 정확히 이 CLI와 데이터로 만들어졌다는 실행 로그는 없습니다. 다만
위 스텝 수와 저장된 평가 표본 수가 이 흐름과 일관됩니다. 인물 중복 문제와 모델 선택에
Test를 사용하는 문제는 별개이며, 인물 미중복 부분집합만으로 후자를 해소하지 못합니다.

## 공개 전처리·네트워크와의 실제 입력 대조

2025-12-02 공개 코드에서 crop 연산, loader의 평가 transform·라벨 정규화, ResNet의
관련 함수·클래스만 발췌해 비교했습니다. 원본 스크립트의 디렉터리 순회·파일 쓰기·학습은
실행하지 않았고, 새로운 얼굴 이미지 파일도 저장하지 않았습니다.

| 검사 | 범위 | 결과 |
|---|---|---|
| 실제 ROI의 입력 텐서 | NIA 10항목 × 세 기기, 각 facepart별 대표 1개씩 총 72개 | 전부 완전 일치, 최대 절대 차이 0 |
| 라벨 정규화 | 위 72개 | 전부 일치 |
| 공개 저장소 동봉 ResNet과 현재 torchvision ResNet | 주름 분류·수분 회귀 각 입력 2개 | strict loading 성공, 출력 최대 절대 차이 0 |
| 당시 코드와 기존 조사 기준 코드 | main·loader·crop·utils·model 5개 | SHA-256 전부 일치 |

공개 코드의 crop·JPEG 왕복·RGB 변환·ImageNet 정규화와 현재 경로가 같은 입력을 만드는
것을 실제 표본에서 확인했습니다. 네트워크도 비교한 대표 모델·입력에서 같은 출력을
만들었습니다. 이는 확인한 범위에서 공개 코드와 다른 구현 때문에 성능이 떨어졌다는
설명을 뒷받침하지 않습니다.

72개는 기능 동등성 검사이며 전체 성능을 새로 추정한 표본이 아닙니다. 모든 ROI와 모든
체크포인트의 전체 출력을 비교한 것도 아닙니다. 실제 학습 때 `--res`나 원본 crop 생성
조건을 바꿨는지는 별개이며, 이 일치만으로 학습 해상도를 확정하지 않습니다.

## 저장된 평가 통계와 이번 결과의 비교

아래의 저장 Accuracy는 체크포인트의 `info.micro_precision`입니다. 공개 코드의 단일 정답
다중 분류에서는 전체 정확 일치 비율에 해당합니다. 논문의 공식 Test 점수라는 의미는 아닙니다.

| 분류 항목 | 저장 표본 수 | 저장 Accuracy | 이번 DSLR ROI 수 | 이번 DSLR Accuracy | 이번 스마트폰 Accuracy |
|---|---:|---:|---:|---:|---:|
| 주름 | 2200 | 43.41% | 1965 | 43.72% | 33.08% |
| 입술 건조 | 660 | 55.45% | 588 | 56.63% | 59.32% |
| 색소침착 | 1544 | 53.63% | 1374 | 53.93% | 32.82% |
| 모공 | 876 | 57.53% | 780 | 56.41% | 53.97% |
| 턱선 처짐 | 663 | 48.57% | 606 | 48.68% | 42.08% |

DSLR의 전체 Accuracy는 가깝지만 표본이 다르므로 정확한 재현으로 취급하지 않습니다.
누락 라벨 때문에 저장된 전체 등급 분포를 독립적으로 재구성하지 못했으며, 현재 라벨이
원저자 실행 당시 버전과 같은지도 확정하지 못했습니다.

추가로 등급별 수치를 대조하면 주름 4등급·입술 건조 3등급의 이번 정답 예측 수가 저장
수치보다 각각 1개 많습니다. 턱선 처짐도 여러 등급에서 누락 표본만으로 설명할 수 없는
차이가 있습니다. 따라서 모든 차이를 단순히 빠진 파일 탓으로 설명하지 않습니다.
입력 해상도·실행 환경·원본 crop·데이터 또는 라벨 버전의 완전한 대응은 미확인입니다.

## 공식 논문과 비교 가능한 범위

2026년 논문은 기기별로 별도 모델을 학습하고, 인물 단위 7:1:2 분할·네 번의 랜덤 분할
평균을 보고합니다. 주요 모델은 CoAtNet-4이며, 논문의 ResNet-50 비교 실험도 batch size
32로 기재돼 있습니다. 우리에게 있는 파일의 batch size 256과 다릅니다. 처짐 분류도 현재
가중치의 출력은 0~5의 6개인 반면, 논문 Table 3은 0~6 등급의 정답 분포를 보고합니다.
항목 이름이 같아도 라벨 범위가 동일하다고 가정할 수 없습니다.

따라서 같은 ResNet-50이라는 이름만으로 논문의 비교 실험 가중치와 동일하다고 판단하지
않습니다. 같은 배포 가중치 하나를 세 기기에 적용한 이번 결과와 논문의 기기별 전용 모델
성능은 조건이 다릅니다. DSLR에서 스마트폰으로의 성능 저하는 촬영 도메인 차이와
일관되지만, 이번 자료만으로 원인을 촬영 기기 하나로 확정하지 않습니다.

회귀에서는 논문의 정규화 오차·Pearson r과 우리의 원래 단위 MAE·MSE·RMSE·R²를
그대로 비교하지 않습니다. 이번 확인을 위해 새 성능 지표나 테스트 임계값을 추가하지 않았습니다.

## 운영 판단과 남은 확인 사항

네 항목의 입력 계약과 현재 가중치는 유지했습니다. 원본 성능 평가 수치도 변경하지 않았습니다.
스마트폰 등급 분류의 낮은 Macro F1과 회귀의 음수 R²는 현재 추론 조건에서 관찰한 결과로
유효합니다. 다만 이 결과를 논문 모델의 성능 재현 실패나 ResNet 자체의 한계로 단정하지 않습니다.

학습 기기별 실제 CLI·`res`·crop 파일 생성 조건, 가중치와 분할 버전의 대응, 모델 선택에도
사용하지 않은 인물 단위 최종 Test가 필요합니다. 해상도나 임계값을 이번 Test 점수에 맞춰
선택하지 않고 별도 Train/Validation에서 개선해야 합니다.
