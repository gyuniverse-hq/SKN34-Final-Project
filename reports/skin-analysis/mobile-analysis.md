# 모바일 기기 내 피부 분석 실험

마이페이지 → 피부 정보 등록 → 자동 촬영 → 기기 내 분석 → 설문 → 저장으로 진행합니다.
모바일 Expo Go에서는 WebView 안에서 전면 카메라·자동 촬영·WASM CPU 추론을 실행합니다.
Android 전용 네이티브 구현도 보존하지만 Expo Go 실행에 APK 빌드는 필요하지 않습니다.

## Expo Go에서 실행

준비된 자산이 없다면 `npm run skin:prepare`를 먼저 실행합니다. 루트 `.env`에
`EXPO_PUBLIC_ENABLE_SKIN_ANALYSIS=1`을 설정한 후 다음 명령으로 Expo 서버를 **재시작**합니다.
기존 `EXPO_PUBLIC_SKIN_ANALYSIS_MODE=server` 설정은 무시되며 사진은 서버에 전송되지 않습니다.

```powershell
npm run skin:validate
npm start -- --clear
```

휴대폰을 PC와 같은 Wi-Fi에 연결하고 Expo Go로 접속합니다. 마이페이지 → 피부 정보 등록 →
카메라 시작으로 진행합니다. 전면 카메라 가이드에 이마부터 턱까지 맞추고 약 1.5초간 유지하면
한 프레임을 자동 촬영합니다. 추론이 끝나면 필수 설문 세 문항과 저장·완료 안내로 이어집니다.
갤러리 사진 선택 방식이 아닙니다. 다중 얼굴·정면 방향·거리·중앙·안정 상태는 MediaPipe
랜드마크로 확인하며 머리카락이 이마를 가렸는지는 판별하지 않습니다.
촬영 전에는 카메라 영상과 얼굴 가이드만 준비합니다. OpenCV·ONNX·JPEG 실행 도구와 피부 분석 모델은 촬영 후 분석 화면에서 불러옵니다.
준비 안내는 촬영 화면 로딩 → 카메라 영상 시작 → 얼굴 가이드 준비로 구분하며, 각 단계가 60초 이상 멈추면 해당 단계의 오류를 표시합니다.

PC의 Metro는 `/skin-runtime/`에서 허용된 런타임·모델 파일을 내려주는 역할만 합니다.
추론은 **휴대폰 WebView의 WASM CPU(1스레드)**에서 실행합니다. 사진·ROI·텐서는 WebView
메모리에서 처리하며 서버 전송·파일 저장을 하지 않습니다. 결과 화면 미리보기용 사진과 영역 좌표는 앱 메모리로 전달되고 화면 이탈 시 삭제됩니다.
취소·백그라운드 이동 시 WebView와 카메라를 해제하며 기존 등록은 유지합니다.
얼굴 추적 런타임과 검출 모델은 기존 AR처럼 공개 CDN에서 받습니다. 첫 실행에는 모델
약 154MiB와 실행 자산을 휴대폰으로 내려받기 때문에 PC 연결과 인터넷이 필요합니다.
모델은 Cache API를 사용할 수 있는 WebView에서 해시 확인 후 캐시합니다. 지원·저장 공간에
따라 캐시가 유지되지 않을 수 있으며 모델별 `cacheHit`와 실제 읽기 시간을 기록합니다.
Expo Go에서의 이 경로는 완전 오프라인 APK 검증을 대신하지 않습니다.

모델별 전송/캐시 읽기(`downloadMs`), 세션 로딩, 검증, 전처리, 추론 시간을 구분합니다.
총 대기에는 전송·검증도 포함되므로 **순수 기기 추론 속도는 `inferenceMs`**로 확인합니다.
`startupMs`는 촬영 전 카메라·가이드 준비 시간이며, 촬영 후 실행 도구 초기화는 `imagePreparationMs`와 `totalMs`에 포함합니다.
매 촬영마다 새 WebView에서 실행하며 프로세스 최초/반복 구분은 Expo JS 세션 기준입니다.
WebView에서는 앱 전체 PSS를 얻을 수 없어 `memoryPssKb: null`로 기록합니다.

ROI는 기존 OpenCV Haar 얼굴 검출과 비율을 유지하고, 여드름 리사이즈·정규화는 기준 고정
픽스처와 비교합니다. 웹 libjpeg-turbo 코덱은 OpenCV JPEG와 픽셀 단위로 일치하지 않습니다.
따라서 v3 결과는 `skin-v3-embedded-enhancement`로 구분하고 crop 픽스처의
최대 텐서 차이(`jpegFixtureMaxError`, 현재 약 0.26144)를 기록합니다. 원본 전처리의 완전한
동일성이나 분석 정확도를 검증한 결과로 해석하지 않습니다. 모델 자체는 동일 입력 텐서에
대한 WASM 출력·등급·여드름 판정을 원본 PyTorch/ONNX 기준과 비교해 검증합니다.

```powershell
npm run skin:test-web
```

이 검사는 실제 WASM 모델 다섯 개의 기준 출력, 전처리, 자동 촬영 안정 조건, 자산 경로와
업로드 차단을 확인합니다. 실제 Expo Go 카메라 권한·촬영·메모리와 휴대폰 속도는 실기기에서
별도로 확인해야 합니다. 이 문서 아래 Android 절차는 네이티브 구현을 시험할 때만 사용합니다.

## 모델 준비와 빌드

Node.js와 uv가 필요합니다. v3 원본 모델은 `ml/runs/skin-analysis-v3/bundle-four-models-20261030/`에 둡니다.
여드름은 기존 [모델 인계](model-handoff.md)의 `ml/runs/nia-smartphone-sam-seed-42/recommendation-bundle/`에서 유지합니다.
저장소 루트에서 실행합니다.

```powershell
npm ci
npm run skin:prepare
npm run skin:validate
npx eas-cli@latest login
npx eas-cli@latest build --platform android --profile development
```

`skin:prepare`는 잠금 파일의 `mobile-export` 그룹으로 FP32 ONNX를 변환하고,
고정 입력 4개에서 원본 PyTorch·Pillow와 ONNX 출력을 비교합니다. 등급·피부타입·여드름 판정의 일치와
수치 오차(`atol=1e-4`, `rtol=1e-3`)를 검증한 결과만 앱 자산으로 복사합니다.
원본 가중치는 수정하지 않습니다. 출력은 `ml/runs/skin-mobile/<소스·변환기-해시>/`에
보관하며 이미 존재하는 출력은 해시를 다시 확인해 재사용합니다.

앱 자산에는 ONNX 5개, OpenCV 얼굴 검출 파일, 합성 전처리 검증 이미지·텐서,
Pillow 라이선스와 검증 manifest가 포함됩니다. 가중치는 Git에서 제외하고 `.easignore`가 준비된
앱 자산만 EAS 빌드에 포함합니다. EAS 후크와 Android Gradle 작업이 파일 누락·해시
불일치를 차단합니다. 모델 자산의 빌드 서버 업로드에는 얼굴 사진이 포함되지 않습니다.

### v3 결과 계약

- 모공·색소침착·주름: MobileNetV3-Large 회귀 출력에 sigmoid × 최대 등급(5·5·6)을 적용하고 `floor(score + 0.5)`로 반올림합니다. 분류 argmax를 적용하지 않습니다.
- ROI의 Pillow 12.3 언샤프(radius 1, 75%, threshold 0)·대비 1.4는 ONNX 그래프에 포함합니다. 브라우저와 Android는 기존 ROI/JPEG 입력을 유지하고 추가 전처리를 중복 적용하지 않습니다. 합성 RGB 픽셀에서 Pillow와 완전 일치를 검사합니다.
- 피부타입: 이마·좌우 볼의 softmax 확률을 각각 계산한 뒤 평균해 건성·중성·지성 중 하나를 선택합니다. 보정되지 않은 점수이며 복합성은 예측하지 않습니다.
- `skin-analysis-mobile-v2`는 기존 부위별 등급에 `skinType`(label, probabilities, roiCount=3)을 추가하고 모델 식별자 5개를 검증합니다. 이전 v1·서버 결과는 그대로 읽습니다.
- 보고서 상단은 모델 피부타입을 표시하며, 건성·지성은 기본 추천 관심사에 반영합니다. 건조·유분·민감 항목의 등급은 설문 답변으로 유지하고 피부타입을 임의의 수분·유분 등급으로 바꾸지 않습니다. 사용자의 수동 관심사 선택이 우선합니다.
- 기존 얼굴 영역 표시는 유지하고 피부타입 전용 가짜 검출 영역을 추가하지 않습니다. 정확도 개선이나 실제 기기 성능은 이 연결 검증만으로 주장하지 않습니다.
- 연결 검증: 원본 PyTorch·Pillow ↔ ONNX 출력, 실제 WASM 실행, Kotlin JVM 계산, 앱 저장·보고서·추천 흐름을 검사합니다. Android 전체 APK 빌드와 실제 갤럭시의 v3 촬영·추론 속도·결과는 별도 확인 대상입니다.

개발 APK 설치 후 Metro는 다음처럼 시작합니다.

```powershell
$env:EXPO_PUBLIC_ENABLE_SKIN_ANALYSIS='1'
npx expo start --dev-client
```

정식 시간 측정은 개발 빌드 대신 내부 배포용 release APK를 사용합니다.

```powershell
npx eas-cli@latest build --platform android --profile skin-benchmark
```

이 프로필에는 서버 자동 배포가 없고 모델은 APK에 포함됩니다.
Expo Go로 다른 화면을 확인할 때는 환경 변수를 해제하고 `npx expo start --go`로 실행합니다.
로컬 Android SDK가 있는 경우 `npm run skin:android`로 개발 빌드를 만들 수 있습니다.
루트 `android/`는 Expo prebuild의 생성물이며 직접 편집하지 않습니다.

## 처리·저장 계약

- CameraX와 번들 ML Kit가 전면 카메라에서 한 명의 얼굴·정면 방향·거리·중앙·이마
  여유 공간을 확인합니다. 조건이 1.5초간 유지되면 사진 한 장만 자동 촬영합니다.
  이마를 머리카락이 가렸는지까지 판별하지는 않습니다.
- 촬영 JPEG는 네이티브 메모리에서만 처리합니다. JavaScript로 촬영 ID·진행 상태와 임시 미리보기 사진·윤곽을 전달합니다. 사진·크롭·텐서는 서버에 보내지 않습니다. 작업 종료 후 참조를
  해제하며 촬영 사진을 갤러리나 앱 디스크에 기록하지 않습니다.
- 최종 ROI는 기존 OpenCV Haar 얼굴 상자 비율을 사용합니다. 촬영 가이드의 ML Kit
  얼굴 상자를 모델 ROI로 대신 사용하지 않습니다. 좌우는 회전 보정된 원본 사진 기준입니다.
- 모델을 하나씩 로드하고 해당 모델의 모든 부위를 분석한 뒤 해제합니다. 여드름은 전체
  이미지, 모공은 양 볼, 색소침착은 이마·양 볼, 주름은 이마·미간·양 눈가를 분석합니다.
  부분 실패를 0으로 채우지 않고 전체 흐름을 실패시켜 재촬영을 안내합니다.
- 앱 프로세스에서 최초 사용 시 Python 기준 전처리 텐서와 모바일 텐서를 비교하고,
  모델별 기준 출력도 비교합니다. 검증 실패 시 분석을 차단합니다. 검증 비용도 최초
  사용자 대기 시간에 포함됩니다.
- 최신 분석 수치 10개, 여드름 score·임계값, 모델 근거, 설문 응답과 등록일을 기기에
  저장합니다. 모든 설문 응답 및 저장이 성공한 뒤에만 등록 완료를 표시합니다.
  취소 시 이전 등록은 유지하며 ‘앱 데이터 모두 삭제’가 피부 정보와 측정 기록도 삭제합니다.

## 실기기 측정

회귀 검사는 `npm run check`로 실행합니다. 촬영 조건·Pillow 호환 리사이즈의 실제 Kotlin
코드는 Android SDK 없이 `npm run skin:test-native-math`로 검증할 수 있습니다
(JDK 및 Expo prebuild로 생성된 Gradle wrapper 필요). `npm run skin:test-assets`는
모델 자산 누락·변조·경로 이탈 차단을 검사합니다. 이 검사들은 Android 카메라/JNI의
전체 빌드나 실제 기기의 전처리·속도 검증을 대신하지 않습니다.

1. release APK 설치 후 비행기 모드에서 전체 등록을 완료해 오프라인 동작을 확인합니다.
2. 앱을 완전히 종료(force-stop)하고 다시 열어 측정하는 것을 3회 반복합니다.
   앱을 백그라운드로 보내는 것만으로는 새 프로세스가 아닐 수 있습니다.
3. 같은 앱 프로세스에서 10회 다시 촬영·분석합니다. 모델은 매회 다시 로드합니다.
4. 마이페이지의 ‘피부 분석 속도 측정’에서 확인하고 ‘측정 수치 공유’를 사용합니다.

요약은 가장 최근 측정과 기기·OS·빌드·런타임·모델 묶음이 같은 기록만 집계합니다.
최초 프로세스 측정과 반복 측정을 분리하며 최대 100건을 보관합니다.
총 시간은 촬영 시작부터 설문 화면 배치까지이며 얼굴 정렬과 설문 응답 시간은 제외합니다.
촬영·이미지 준비·검출·모델별 로드·전처리·추론 시간과 최대 **표본 PSS**를 기록합니다.
PSS는 처리 단계에서 읽은 메모리 값으로, 시스템 전체 추적에 의한 정확한 피크는 아닙니다.
최초 실행에는 자산 준비와 전처리·모델 출력 검증이 포함되며 반복 실행에는 해당
프로세스에서 이미 통과한 검증을 재실행하지 않습니다.

카메라 권한 거절, 여러 얼굴, 가이드 이탈, 화면 회전·미러링, 재촬영, 뒤로 가기,
백그라운드 이동, 저장 실패, 재등록 및 앱 재실행 후 복원을 실제 기기에서 확인합니다.
실기기에서 측정하기 전에는 속도·메모리 수치나 Android 전처리 일치 검증의 통과를
주장하지 않습니다. 이 기능은 기존 연구 모델의 실사 정확도나 의료적 유효성을 보증하지 않습니다.
